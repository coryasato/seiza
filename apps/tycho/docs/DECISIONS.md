# Decisions: Tycho

Why Tycho is built the way it is. Decisions that bind every app (toolchain, graphics backend, `shared/`, the measurement protocol) are in the root [`docs/DECISIONS.md`](../../../docs/DECISIONS.md).

One bullet per decision, under its area, oldest first: what was chosen, the numbers that chose it, and *[where they came from]* (a milestone, a code review, a results file in `perf/results/`). A decision that replaces another marks the old one *Superseded* rather than deleting it. Add new ones as they land; [`../PLAN.md`](../PLAN.md) keeps only what's still open.

## Scope

- **2026-09-25** · M7's overlay becomes a user-facing **observation panel**: live load waterfall, bytes read vs file size, and while scrolling rows/s, pages in flight, cache hits, memory, and a sparkline of both rAF interval and per-frame work time. It refreshes at ~4 Hz; the fling budget is checked with it open and closed. *[M7 planning]*
- **2026-09-25** · **Jump to row** is navigation, not analysis, so it's inside v1 scope (Tycho rule 4). It's the first text input. *[M7 planning]*
- **2026-09-25** · The React comparison, if built, is a **replay mode** (the same scripted run on each side in turn), not a live race in one tab, where both sides would share a main thread and GPU. Research first; see Long-term goals. *[planning]* *Superseded 2026-10-12 and 2026-10-14: the comparison moved to the observatory, which runs one contender at a time and replays them with a benchmark button (root `docs/DECISIONS.md`, "Comparison protocol").*
- **2026-10-23** · **Scope grows through `PLAN.md`, not a fixed v1 list.** v1 (M0–M9) is done; the old rule 4 (no SQL editor, charts, sort/filter, or GROUP BY) held it to a version, and every next feature would have needed the rule rewritten. Next: the table's `DataTable` features as each is ready (`components/tall-table/PLAN.md`), then a density plot of any two columns linked to the table ("Long-term goals"). Anything else enters `PLAN.md` as a goal before it's built. *[planning discussion]*
- **2026-11-17** · **Tycho is rebuilt as a public data workbench:** for a file too big for a spreadsheet, opened, understood, checked, and exported in part, with nothing uploaded. The old Tycho proved a canvas table scrolls tens of millions of rows and did nothing else; the measuring had moved to the observatory and the table had become a component. The old `PLAN.md` is replaced whole, its carried-over items and open questions not carried over. The first release is built for the quick checker, the ML engineer second, the investigator third (`docs/personas.md`). *[Tycho planning, 2026-11-17; `docs/research/tycho-workbench.md`]*
- **2026-11-17** · **A controller holds one view state, and every driver produces it.** The controller is the layer between DuckDB-Wasm and the tall table: it holds the source, columns, order, filters, sort, pins, and formats as one serializable state, compiles it to SQL and to calls on the table, and is built first and thin, each of the table's features adopted through it. A click, a typed command, a pasted reply, a browser agent, and a link all produce that state. Named "the controller" and "the view state"; "smart table" was dropped. *[Tycho planning, 2026-11-17; `docs/research/tycho-workbench.md`]*
- **2026-11-17** · **Tycho hosts no model, no API to one, and takes no visitor's API key.** Security for the visitor and for us comes first in a public app. So Tycho is never an LLM's client: it is the tool an outside LLM operates, by the clipboard (a copied context, a pasted reply) or by the visitor's own browser agent driving the same input. The LLM is one driver of the app, not the app. *[Tycho planning, 2026-11-17; `docs/research/tycho-workbench.md`]*
- **2026-11-17** · **The thread is DOM beside the canvas, and a log, not a chat.** A collapsible panel at the left with the input and its history: every action lands in it, clicks included, and each reply is Tycho's own (a row count, a small answer, an error). Text entry, selection, Ctrl+F, screen readers, and agents need the DOM; the table stays the canvas and the focus. Whether it earns its place, and its input's form, are the design session's. Its input takes commands and actions, never SQL: SQL gets an editor of its own, a later goal, after checked SQL expressions have been explored. *[Tycho planning, 2026-11-17; `docs/research/tycho-workbench.md`]* *Superseded in part 2026-11-20: the log sits at the right, as a tab, and its input is a command bar of its own (below).*
- **2026-11-17** · **Open from a URL is in, Parquet only,** read by range so part of a large remote file opens quickly; a remote CSV has no index and isn't offered. Also in, from the personas: filter by a cell, a row detail view, the view copied as SQL, JSONL, and more than one file (after the single-file app works). Charts are a goal with a planning session of their own, which reopens "Tycho builds no plot" (root `docs/DECISIONS.md`, "Repo structure", 2026-11-10). *[Tycho planning, 2026-11-17; `docs/research/tycho-workbench.md`]*
- **2026-11-17** · **The page's technology is measured, not assumed:** static and prerendered, plain TypeScript for the thread to start; a framework only if the page's DOM state grows enough to need one. *[Tycho planning, 2026-11-17; `docs/research/tycho-workbench.md`]*
- **2026-11-19** · **The row detail view is DOM, opened from the tall table's cell popover.** Two steps: the popover, drawn by the table, is the quick look at one cell; its button opens the row detail view beside the table for reading the whole row, long text and nested values included. The view is DOM, not canvas, because it holds the text people read closely: selecting part of it, finding in it, and a screen reader come free there (the reworded claim: the DOM where text lives). How it opens and whether it follows the selection is the design session's (PLAN, open question 17). *[planning discussion]*
- **2026-11-20** · **Only the table is canvas; everything else on the page is DOM.** The top bar, the views row, the toolbar, the side panels, the status bar, the command bar, the first screen, and every menu: a column's or a cell's menu is a DOM menu opened from the table's `clicks` events, so the keyboard and a screen reader reach it. The title bar and jump to row, canvas today, are rebuilt in the DOM. *[design session, 2026-11-20; [the design canvas](https://claude.ai/artifact/CR8skvUDrUsVxE4zXJtRmK)]* *Superseded in part 2026-11-21: the column menu's button reports through the table's own event, not `clicks` ("The header icon's raised look has a 1 px border", below).*
- **2026-11-20** · **The design covers the whole app,** goals past the first release included (open from a URL, offline, views), and is scaled back when a milestone is opened, not before it's drawn. *[design session, 2026-11-20; [the design canvas](https://claude.ai/artifact/CR8skvUDrUsVxE4zXJtRmK)]*
- **2026-11-20** · **The frame: columns at the left, the table in the middle, the log and the row detail view as tabs at the right.** Three frames were drawn; this one follows what most tools do (navigation left, history and detail right). The left panel lists the columns, each with its type, and opens one's profile in place, which needs nothing new from the table. Over the table: a row of views, then a toolbar that shows the view state as chips (filters, the sort, hidden columns) and the row count. The top bar holds the file's name and the command bar; the file's facts (rows, columns, size) sit in the status bar, since beside the command bar they ran under it, with the engine's state, a "local only" entry, and the selection. Both side panels collapse. *[design session, 2026-11-20; [the design canvas](https://claude.ai/artifact/CR8skvUDrUsVxE4zXJtRmK)]* *Superseded in part the same day: a view is a row of the left panel's list, not a tab over the table ("The views are a list in the left panel", below).*
- **2026-11-20** · **The input is a command bar at the top center, apart from the log.** A box in a thread reads as a chat and invites a sentence; a bar with completion says what it takes. Its states, as drawn: the list of commands; a command's parts across the top with the current one marked, and the columns that match below; a whole command, shown in plain words and as the action it becomes; a pasted action, its steps listed in plain words and run on Enter; a sentence, answered with "Tycho reads commands, not sentences" and Copy context. The log keeps every step, with where it came from (a click, typed, pasted) and a way back to it. The command names on the canvas are drafts until the catalog is written. *[design session, 2026-11-20; [the design canvas](https://claude.ai/artifact/CR8skvUDrUsVxE4zXJtRmK)]*
- **2026-11-20** · **A grouped result opens as a view tab, and keeps the filters it was made with.** A tab is a table of its own, with its own sort and scroll: the base rows stay as they were in theirs, and a later change to their filter doesn't recalculate the grouped tab (group again for a fresh one). "Show rows" on a group goes back to the base view with a filter on the group's key added. A breadcrumb was drawn beside it and dropped: it nests three levels, and going up one leaves the level below. Views as tabs are new scope, taken on with it. *[design session, 2026-11-20; [the design canvas](https://claude.ai/artifact/CR8skvUDrUsVxE4zXJtRmK)]* *Superseded in part the same day: a view is a row of the left panel's list, not a tab over the table ("The views are a list in the left panel", below).* *Superseded in part 2026-11-21: "Show rows" opens a view of its own and leaves the base view as it was ("'Show rows' on a group opens a view of its own", below).*
- **2026-11-20** · **Tycho has a theme of its own:** not the apex site's, and not gpui-kit's as it ships. Quiet graphite neutrals, one warm accent kept for the current state (an active filter, the sort, the selection), and a color per column type, each with a glyph so none is told by hue alone; dark and light both drawn. One token set feeds the DOM and the tokens Tycho hands the table, so the two can't drift. The table is drawn in the one face the apps ship (IBM Plex Sans Regular); the DOM adds its other weights and Plex Mono for commands. The values are the canvas's until the token file exists. *[design session, 2026-11-20; [the design canvas](https://claude.ai/artifact/CR8skvUDrUsVxE4zXJtRmK)]*
- **2026-11-20** · **The first screen is the command bar, open in a blank workbench.** The top bar, a ghost table across the page, and the status bar are there, both side panels closed; the command bar sits in the middle under "Drop a file, paste a URL, or pick one below", with three rows (choose a file, the sample, a Parquet file's URL). The whole page takes a drop. When a file opens, the bar moves to its place in the top bar (about 200 ms; no motion under reduced motion). All of it is DOM, so it can be in the prerendered page, before the wasm. A file Tycho can't open is named between the heading and the bar, which stays usable. Five other first screens were drawn and dropped; this one is two of them combined. *[design session, 2026-11-20; [the design canvas](https://claude.ai/artifact/CR8skvUDrUsVxE4zXJtRmK)]*
- **2026-11-20** · **A dragged file hazes the whole page:** a dark layer over everything, the command bar included, at 70% with a 4 px blur, and on it a file icon, "Drop to open", and "CSV or Parquet". No accent frame, no tint, and no plate under the message. A full-page tint in the accent was too loud, and a lighter haze (55%) left the message unreadable over the bar without a plate. The strength may move toward 50% with an 8 px blur once it's seen built. *[design session, 2026-11-20; [the design canvas](https://claude.ai/artifact/CR8skvUDrUsVxE4zXJtRmK)]*
- **2026-11-20** · **The toolbar shows one control a kind, in two steps, and never a chip a filter.** Filters, the sort, and hidden columns are each one control, always there and in that order: an outlined button with nothing applied ("Filter", "Sort", "Columns"), a labeled chip with something ("Filters · 5", one filter included), and an icon with a count where space is short (a phone, or find open). A chip a filter was drawn and dropped: its width is the data's (`place contains Alaska`), and cutting it makes it unreadable. A filter's column, operator, and value are read, removed, and added in the list its chip opens. An overflow chip ("+3 filters") was drawn and dropped: at a phone nearly everything ends up behind it. *[design session, 2026-11-20; [the design canvas](https://claude.ai/artifact/CR8skvUDrUsVxE4zXJtRmK)]*
- **2026-11-20** · **The row count sits beside the chips, and find has the toolbar's right side.** The count is what the filters result in, so it reads after them; at the right, next to find's input, it read as a count of matches. With find open at the desk the chips step down to icons; at a phone the first row doesn't change and find takes a second row of its own, its input from the left edge, so the filters are never covered. A row of its own for find at every width was drawn and dropped. *[design session, 2026-11-20; [the design canvas](https://claude.ai/artifact/CR8skvUDrUsVxE4zXJtRmK)]*
- **2026-11-20** · **"+" is every way to make a view, and the toolbar has no Group button.** The toolbar only shows the state of the view in front of the visitor. "+", in the Views list's header, opens: group this view by a column, duplicate this view, a new view of all rows. Grouping is also in a column's menu and the command bar. *[design session, 2026-11-20; [the design canvas](https://claude.ai/artifact/CR8skvUDrUsVxE4zXJtRmK)]*
- **2026-11-20** · **A view's name is automatic until it's renamed.** A grouped view is "by " and its column; a duplicate takes a number ("by magType 2"); "All rows" is fixed: never renamed or closed, so the file's rows are always one press away. A name is 40 characters at most, a duplicate's number and its space counted. Where a name doesn't fit it is cut with an ellipsis and the number, a piece of its own, never is. Renaming is a button on the view's row and happens in the row; nothing depends on a double-click, which a phone doesn't have. *[design session, 2026-11-20; [the design canvas](https://claude.ai/artifact/CR8skvUDrUsVxE4zXJtRmK)]*
- **2026-11-20** · **The views are a list in the left panel, above the columns, and there are no tabs.** The left is where navigation goes, a name gets the panel's width, and the columns under the list are the selected view's. Each row switches to its view; rename, duplicate, and close show on the current row and the hovered one. The current view's name follows the file's in the top bar: plain text while the panel is open, and with it closed, or at a phone, a button that opens the same list, so there is one list and one place to manage views. An info button in the list's header, in the panel only, says what a view is. Drawn and dropped on the way: a row of tabs over the table (uncapped; capped at three with a "2 more" button; a single selector), and a menu on the current tab beside the list's own buttons, which was two ways to do one thing. *[design session, 2026-11-20; [the design canvas](https://claude.ai/artifact/CR8skvUDrUsVxE4zXJtRmK)]*
- **2026-11-20** · **One Share menu holds every way out of a view:** copy link, copy as SQL, copy context, and export, each with a line saying what it does and its limit ("The file isn't in it", "No cell text"). It sits in the top bar, at the right, and acts on the view in front. A link holds a view's state, never the data: for a dropped file it asks for the file again. A plain menu without the lines was drawn and dropped. *[design session, 2026-11-20; [the design canvas](https://claude.ai/artifact/CR8skvUDrUsVxE4zXJtRmK)]* *Superseded in part 2026-11-21: export is two items, one a format ("Export is one press", below).*
- **2026-11-20** · **Views last for the session, and are kept on the device only if the visitor asks.** A list in the panel reads as kept, where tabs read as temporary, so the list comes with a way to honor it: one switch under the list, "Keep on this device", with an estimate of its size beside it, and "Forget". Opt-in because what's saved is the file's text (column names, filter values) and a work laptop or a leak may not want it written down, and because the personas ask for it that way. Kept: each view's definition, with widths and order only where they differ from the default. Never the rows, a profile's results, or the log. The file itself can't be kept: the first screen lists files with kept views and asks for each again. Proposed caps: the 10 files opened most recently, 20 views a file; at an estimated 1 to 2 KB a view, about 400 KB at the very worst against the browser's 5 MB or so for the origin, which Kirkwood shares. The list is read after first paint. *[design session, 2026-11-20; [the design canvas](https://claude.ai/artifact/CR8skvUDrUsVxE4zXJtRmK)]*
- **2026-11-20** · **A header's type icon is its column's menu button.** Every header starts with its column's type icon, at the left whatever the name's alignment, so the button is in one known place; under the pointer it is drawn raised, on a solid backdrop with a shadow, not outlined. It adds nothing to a narrow header, and it is always in sight, so it works where there is no hover. A right-click on the header opens the same menu, and so does the column's row in the left panel, the only way in for a keyboard or a screen reader. At a phone a tap anywhere on a header opens the menu, which holds every ability, and the sort arrow only shows the direction: a header's zones (the arrow's 20 px, the edge's 9 px) are too small for a finger, and a stray sort reads as a mistake. A "more" mark shown on hover was drawn and dropped. The icon as a press target, the tap, and a long press reported as a right-click are asked of the tall table (`PLAN.md`, "Waiting on"). *[design session, 2026-11-20; [the design canvas](https://claude.ai/artifact/CR8skvUDrUsVxE4zXJtRmK)]* *Superseded in part 2026-11-21: the raised look has a border ("The header icon's raised look has a 1 px border", below).*
- **2026-11-20** · **Everything that acts shows the pointer cursor.** *[design session, 2026-11-20; [the design canvas](https://claude.ai/artifact/CR8skvUDrUsVxE4zXJtRmK)]*
- **2026-11-20** · **A column's menu, a cell's menu, and the editors.** A column's menu: sort either way, filter this column, group by it, pin, hide, fit to its values, show its profile. A cell's menu: keep the rows with this value, leave them out, copy, open the row. The filter's editor reads "Keep rows where" a column, an operator in words ("is at least"), and a value, and its foot shows the command it makes, as the command bar does; the column's profile previews what the filter keeps (the bars it keeps in the accent, a text column's values as a checklist with counts, a timestamp's span with shortcuts), so nothing is queried as the visitor types. The sort's editor holds one column, as the table sorts by one; the list it grows into when the table sorts by several is drawn and marked for later. *[design session, 2026-11-20; [the design canvas](https://claude.ai/artifact/CR8skvUDrUsVxE4zXJtRmK)]*
- **2026-11-20** · **The hidden-columns chip opens the left panel's column list,** where each column's eye already is; with the panel closed it opens the same list as a dropdown. One place to show and hide, as with views. *[design session, 2026-11-20; [the design canvas](https://claude.ai/artifact/CR8skvUDrUsVxE4zXJtRmK)]*
- **2026-11-20** · **The column profile is drawn in three stages, in the panel first; the strip under the headers waits.** An exact profile of every column is too slow for a large file: on 1 GB and 42 million rows, 38 to 53 s on open and about 20 s after each filter, against 3 s from a 1% sample, 0.24 s for the range and nulls from the Parquet footer, and 2.5 s for one column in full ([`docs/research/tycho-workbench.md`](../../../docs/research/tycho-workbench.md), "The column profile's cost"). So: the footer's facts over placeholder bars at once, a sample's shape muted and marked as sampled, then every row for a column the visitor opens or a small file. The panel's profile is built first. The header strip is the same numbers drawn smaller, by the table from numbers Tycho gives it, and is asked of the tall table only once the panel's proves fast enough. If it doesn't, a session of its own tries to make the sample faster first (its starting points are in the research); only if that fails does the graphic leave the panel, its figures staying. The sort arrow stays at the header's right edge, where the table draws it. *[design session, 2026-11-20; [the design canvas](https://claude.ai/artifact/CR8skvUDrUsVxE4zXJtRmK)]*
- **2026-11-20** · **The cell popover's cue is a fade and a chevron, on a value that overflows only.** At rest an overflowing cell ends in its ellipsis, as now. Under the pointer and on the active cell the ellipsis gives way to the text washing out to the right, with a chevron at the cell's far right, past the fade, that opens the popover and turns up while it is open. A value that fits, and a number, gets no cue: Enter opens its popover. As the table builds the cue today it is on every cell once the popover has a button, and a value with no ellipsis steps aside for it under the pointer (about 18 px in a 28 px row), which is what this replaces. Drawn and dropped: the mark in the ellipsis's place, a raised chip over the cell's free end, the fade at rest on every overflowing cell, and the chevron always shown. Asked of the tall table (`PLAN.md`, "Waiting on"). *[design session, 2026-11-20; [the design canvas](https://claude.ai/artifact/CR8skvUDrUsVxE4zXJtRmK)]*
- **2026-11-20** · **The cell popover is a glimpse of overflowing text, and nothing else.** It opens only on text the cell cuts (or text with line breaks), by the chevron or by Enter, and holds the value and one row at its foot: "Open row" in the accent at the left, "Enter" muted at the right. No copy button and no filter actions: those are the cell's menu's, and one job has one place (the popover's text can still be selected, and a part of it copied). A rounded number or a timestamp gets no popover: its exact value is in the table's tooltip under a resting pointer, and in the row view. Enter on any cell with no popover opens the row view, so Enter is "show me more" everywhere and the row is two presses away at most. The cell's menu keeps "Open the row" for the pointer, with no key beside it: Space, drawn there before, is the table's page down. As the table is built, Enter opens a popover on every cell, a NULL included; the narrowing is a setting Tycho asks of it (`PLAN.md`, "Waiting on"). Drawn and dropped: a text link at the foot, a head with the column's name and a copy button, a foot with the value's length and a copy button, and popovers on a number, a timestamp, and a NULL. *[design session, 2026-11-20; [the design canvas](https://claude.ai/artifact/CR8skvUDrUsVxE4zXJtRmK)]*
- **2026-11-20** · **The row detail view always shows the active cell's row.** It is the Row tab's body: "Row 7 of 38,112", arrows to the row before and after, which move the table's selection, and a button that copies the row. Every column is a field, in the table's order, hidden ones included and marked, the active cell's field marked in the accent. There is no switch for following the selection: one state, not two. A field under the pointer or in focus shows a copy button and the cell's menu (keep, leave out, copy), which is how a keyboard reaches the filter actions. Long text is cut at eight lines with "Show all" and its length; with nothing selected the tab says so. Drawn for later, with JSONL: a nested value read as a tree, and a long list of numbers as its first few with its least and greatest. A switch that pinned the view to one row was in the first frame and dropped. *[design session, 2026-11-20; [the design canvas](https://claude.ai/artifact/CR8skvUDrUsVxE4zXJtRmK)]*
- **2026-11-21** · **Export is one press: a Share item a format, straight to saving.** "Export as CSV" and "Export as Parquet" replace the menu's one "Export…" item, so Share holds five; each one's line gives the rows and an estimate of the file's size. The file is the view as it stands: its rows in its sort's order, hidden columns left out, values as the file holds them and not as rounded on screen, named for the file and the view. A panel under Share with a format, a name, and Save was drawn and dropped, since it made every export two presses; so was a dialog with the file's first lines. *[design session, 2026-11-21; [the design canvas](https://claude.ai/artifact/CR8skvUDrUsVxE4zXJtRmK)]*
- **2026-11-21** · **Export's size plan is a cap, in every browser, and a view over it gets a panel that says why.** An over-the-cap format's item says so in its own line before the press, and opens a panel under Share in place of saving: the format, the name, what the file would hold, the refusal, and the ways around it (filter, hide columns, the other format when it fits, or the view copied as SQL). Drawn and dropped: writing in pieces to a picked file (Chrome and Edge only, the cap elsewhere), and a large export saved as several files. *[design session, 2026-11-21; [the design canvas](https://claude.ai/artifact/CR8skvUDrUsVxE4zXJtRmK)]*
- **2026-11-21** · **An export under way shows in the status bar and the log.** The status bar's left end names the file being written, with a bar, the rows written of the rows in all, and Stop. - **2026-11-21** · **Where the browser has a save-file picker, the one press opens the system's save dialog.** In Chrome and Edge "Export as CSV" opens the dialog with the automatic name filled in, so the file is named and placed there and written to that spot; it is also the browser's own prompt the security rules ask an export to end in. - **2026-11-21** · **At a phone the panels are one sheet over the lower part of the table.** The top bar's panels button opens it, with three tabs: Columns (the left panel's list and its profile, without the views, which stay in the top bar's list), Row, and Log. - **2026-09-23** · The bridge self-test ships in release behind `?selftest` (part of M2's +12.3 KiB), so it checks the build that's measured. *[M2]*
- **2026-10-08** · **A failed Parquet page read re-registers the file under a new SQL name** (`<name>-r<n>.parquet`) and the table reads from it (`TableEvent::ReadFailed`, `RowTable::read_from`). After a failed HTTP range read, every later read of those bytes under the old name fails ("TProtocolException"), online, after re-registering the same name, and with `enable_external_file_cache` off. ## Files and CSV

- **2026-09-27** · Drops and the file dialog are Rust (`crate/src/files.rs`, web-sys): a `window` listener, since gpui-pre-web 0.3.5 swallows `drop` on its canvas, and a hidden `<input type=file>` clicked from a GPUI click handler. No new bridge call. *[M5]*
- **2026-09-27** · A chosen file is sniffed (`PAR1` at both ends) before the engine sees it; a refused file leaves the current one open and shows why inline. *[M5]*
- **2026-09-27** · Each open registers under its own SQL name (`file-<n>.parquet`), never the file's (a glob to `read_parquet`); a new open drops the old one's task, cancels its queries, and closes its table. Registered handles stay (unregistering is a fourth bridge call; a handle holds no bytes). *[M5]*
- **2026-09-30** · **Chunked ingest, not raw-file queries**, for CSV. Raw `read_csv` pages re-parse from the top: a page at 90% of the 1 GB CSV took 5.1 s and `count(*)` 3.3 s. Chunked: first rows in ~0.2 s, the count grows, a page at 90% reads in ~4 ms. *[M6 `perf/results/2026-09-30-m6.md`]*
- **2026-09-30** · **One table per chunk** (`CREATE TABLE … AS`), not appends to one table. Appends stalled 200–600 ms every few chunks inside DuckDB and grew memory with the chunk count; per-chunk tables never passed ~255 ms. Pages spanning two chunks read both with `UNION ALL`. *[M6]*
- **2026-09-30** · Chunk tables live in `ATTACH ':memory:' AS tycho_csv (COMPRESS)`: 300 MiB of DuckDB memory for the 1 GB CSV, against 2.1 GiB uncompressed, for ~40% slower chunks. One schema per open, so `DROP SCHEMA … CASCADE` frees a replaced CSV. *[M6]*
- **2026-09-30** · `read_csv` with `auto_detect = false` and every option from one `sniff_csv` of the first chunk (1 MiB): sniffing each chunk cost ~20 ms of ~55. RFC 4180 quoting is forced (the sniffer sees no quotes in the head and picks none); a conversion error widens that column to VARCHAR and retries the chunk. *[M6]*
- **2026-09-30** · Chunks aim at 200 ms (1 MiB first, then 1–8 MiB, smoothed): the count updates between chunks, and a page read waits for the chunk in progress. Record boundaries are found in Rust (quote-aware), 1 MiB per read; the next chunk's end is found while DuckDB reads the current one. Chunks are `File` slices through `registerFile`: no new bridge call. *[M6]*
- **2026-09-30** · A replaced CSV's load task stops, cancels its query, and drops its schema only after that query answers (a table mid-creation can't be dropped under it); a CSV that's done or stopped has its schema dropped by the workbench on close. *[M6, code review]*
- **2026-09-30** · Chunk tables are paged by `rowid`, except when the file has a `rowid` column (it hides DuckDB's): then each table numbers its rows with `row_number() OVER ()`, which streams in order but cost ~2.6× natively, so only those files pay it. *[M6 code review]*
- **2026-09-30** · A quote opens a field only at the field's start, in the scanner as in DuckDB; RFC 4180's quote is forced unless the sniffer found an unquoted TSV. *[M6 code review]*
- **2026-10-08** · **Size limits:** Parquet up to 10 GB (flat memory to 9.6 GB measured; time grows with row groups), CSV up to 6 GB at the drop and 1.5 GiB of DuckDB memory during the load (`csv::MEMORY_BUDGET`, checked after every chunk with one `duckdb_memory()` query; a chunk of bytes that yields no rows also stops it). DuckDB-Wasm 1.32.0 stores empty tables without an error past ~2.1 GiB, below its 3.1 GiB `memory_limit`. Refusals happen before anything is read, and leave an open file open. *[M7 part D `perf/results/2026-10-08-m7-hardening.md`]*
- **2026-10-08** · The CSV scanner's window stays 1 MiB: at 256 and 64 KiB the throttled fling during a load was the same (interval p95 50 ms, work p95 ~50 ms, 4–5 long tasks of ~55 ms, which are frames) and the load slower (+9%, +57%). *[M7 part D]*

## Density plot

**Every decision in this section is superseded (2026-11-10, its last bullet): Tycho builds no plot.** The plot's own decisions (how it draws, its API) were in `components/kirkwood/docs/DECISIONS.md`, removed with the component. - **2026-11-10** · **Worth building, as a component Tycho adopts** (`components/kirkwood/`, its own `PLAN.md`). - **2026-11-10** · **A plot's two columns are read once, into a compressed in-memory DuckDB table** (`FLOAT`, the file's row order, so its `rowid` is the table's row index), and every bin, box count, and click is answered from it, never from the file. ## Hosting

- **2026-09-22** · Hosting: Cloudflare, one Worker + static assets + R2. *[initial spec]*
- **2026-09-23** · Both DuckDB wasm bundles (32.7 / 37.5 MiB raw) are over Cloudflare's 25 MiB asset limit and go to R2 in M8. `just tycho build` names them (`asset-sizes.ts --r2`); any other oversize file still fails. *[M2]*
- **2026-09-24** · M3 serves data through `wrangler dev` in local mode (Miniflare R2); the Cloudflare account is first used in M8. Worker `tycho`, bucket `tycho-data`, binding `TYCHO_DATA`. *[M3 planning]*
- **2026-09-24** · Dev and preview proxy `/data/*` to `wrangler dev`, so the page stays same-origin under COEP and keeps Vite's HMR and the M1 perf setup. The Worker's `/data` route falls through to static assets, so M8 adds config, not a rewrite. *[M3 planning]*
- **2026-09-24** · The Worker parses `Range` itself (single range; 416 for multi-range, past-the-end, or malformed) and answers a ranged `HEAD` with 206. *[M3]*
- **2026-09-24** · Missing DuckDB extensions are 404s (dev, preview; M8 Worker): autoload asks our origin for any extension a query needs, and an SPA fallback would hand it `index.html`. *[M3 code review]*
- **2026-09-24** · The Worker retries an R2 range rejected with 10039 clamped to the object's size (416 only when the start is past the end); unit-tested against a strict fake R2, since Miniflare clamps. *[M3 code review]*
- **2026-10-10** · **Production origin: `tycho.seiza.io`, a Workers custom domain**, `workers_dev = false`, `preview_urls = false`. The account's default subdomain names its owner; it's off and never committed. *[M8]*
- **2026-10-10** · **Production wasm encoding: br at quality 11, precompressed at deploy** and served by the Worker (`run_worker_first` for the page, `/assets/*`, `/duckdb-ext/*`; `encodeBody: 'manual'`), not Cloudflare's own: it sent zstd to Chromium (which offers it) at a low level, the app wasm 3.92 MB against 2.89 MB, and TTFP read 455.4 / 4837.9 ms (ref / throttled) against 304.8 / 3804.9 with the `.br`. A browser without br gets Cloudflare's zstd or gzip. Rejected: zstd at a high level (3.11 MB at level 19, still over br's 2.89). *[M8 `m8-prod-cold`, `m8-prod-cold-br`]*
- **2026-10-10** · **The page is served `no-cache, no-transform` through the Worker**: the zone's Web Analytics injected `static.cloudflareinsights.com/beacon.min.js` into the HTML, a request before first paint (repo rule 1) that every cold run failed on. `no-transform` stops it whatever the zone's settings; `check.ts` fails on an injected script. *[M8]*
- **2026-10-10** · **Data file names stay stable** (`asteroids.parquet`, `no-cache, no-transform` to browsers), and the Worker keeps `/data` range reads in Cloudflare's edge cache keyed by content: `DATA_VERSIONS` (each sample's SHA-256 prefix from MANIFEST.json, passed by the deploy after the upload) + method + `Range`. Hashed names would have meant threading the hash into the Rust build for nothing more: a browser barely reuses cached 206s, and the edge key already changes with the bytes. Each R2 read cost 55–125 ms (a static asset 20–35), and a page read is a chain of them. *[M8]*
- **2026-10-10** · **DuckDB's wasm bundles (33 and 38 MiB) live in R2 under `assets/<name>`**, their own path, served by the Worker when static assets have no match; their quality-11 `.br` (5 and 6 MiB) are static assets, so a browser with br never reaches R2 for them. `/data/assets/*` is a 404 (not data). *[M8]*
- **2026-10-12** · **Abuse guards at the WAF, not in the Worker.** Every app path runs the Worker, and only requests that reach it are billed, so a guard inside it (the rate-limiting binding, a request counter) still pays for each request it refuses. A WAF path allowlist blocks probes before the Worker (Workers Logs stay unsampled, holding only real traffic), and one per-IP rate-limiting rule covers every path, set well above the heaviest human burst, 93 requests in 10 s (random jumps on Gaia). *[cost review `perf/results/2026-10-12-waf-burst.md`]*
- **2026-10-12** · **A manual pause switch, not an automatic one:** `just tycho pause` sets the Worker secret `DATA_PAUSED`, and `/data/*` answers 503 (no R2 read) while the page and dropped files keep working. An automatic cap (a cron reading the analytics API and setting a flag) waits until an alert shows it's needed. Cloudflare's default billing notification is the alert. *[cost review]*
- **2026-10-12** · **The build files keep going through the Worker** for their quality-11 `.br`, though moving the page, JS, and font back to static assets would save ~5 Worker requests per visit: those files would cost ~25 KB more before first paint (page 11.4 → ~12.7 KB, app JS 21.4 → ~27, font 70.9 → ~88) and ~45 KB more before the first rows (engine and DuckDB worker JS). Kept open for when real traffic makes the requests matter; the engine and DuckDB worker JS can move first (they load after first paint). *[cost review]*
- **2026-11-21** · **The bucket stays, for DuckDB-Wasm's two wasm bundles alone; no dataset goes in R2.** The bundles are 33 and 38 MiB, over the static-asset limit, and the Worker serves them to a browser that doesn't take br. A sample Tycho serves is a static asset under that limit; a larger one is a Parquet file on someone else's host, opened by URL. Not taken: a gzip copy of the bundles as static assets, which would have let the bucket go. *[sample session, 2026-11-21; the owner's decision]*

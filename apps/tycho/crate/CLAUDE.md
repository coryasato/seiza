# Tycho's Rust crate (`crate/`)

The app itself: the workbench, the frame's state and the page's calls, the command bar's grammar and the log, the theme, the table's source, the engine's events, files, CSV, errors and limits. Claude Code loads this file when a file under `crate/` is read. Tycho's rules and the map of its folders are in `apps/tycho/CLAUDE.md`, the repo's in the root `CLAUDE.md`; both apply here. Paths are relative to `apps/tycho/`.

## Architecture

- **UI:** `shared/` (crate `seiza`) on the workspace's pinned `gpui-kit`.
- **Engine:** `engines/duckdb/` (`seiza-duckdb` in Rust, `@seiza/duckdb` in the host); its rules and DuckDB-Wasm gotchas are in `engines/duckdb/CLAUDE.md`, its API in its `README.md`. Tycho's side is `crate/src/engine.rs`: it starts the engine **locked down** from the post-paint callback (`engine::lockdown`: the CSV tables' `ATTACH` and the view's, then the lock; the engine's rule 9), names every file it registers inside the lockdown's directory (`engine::path`: `tycho/…`; a locked engine reads nothing else), turns its events into the panel's "Engine ready", "Parquet ready", and "Engine locked" steps and the `tycho:parquet-ready` and `tycho:engine-locked` marks, and runs `?selftest` once the lockdown settles. **Nothing reaches the engine before the lock:** `EngineStatus::Ready` means locked, and a file chosen before it (a drop, the picker, the sample's download) waits in `Workbench::held`, shown as opening, and opens when the status turns `Ready`. Never send the engine a statement it can't take locked (an `ATTACH` of a file, a `SET`, a `LOAD`) after the start: add it to `engine::lockdown`.
- **Table:** `components/tall-table/` (`seiza-tall-table`): its rules are in `components/tall-table/CLAUDE.md`, its scroll model, page cache, cells, and tooltip in `components/tall-table/src/CLAUDE.md`; its DuckDB source (the page SQL, `QueryResult` as a page, the Parquet summary) is `seiza-duckdb`'s `tall-table` feature. Tycho's side is `crate/src/table.rs`: the source (`Source::Parquet`, a `ParquetFile` with its rows and bytes; `Source::Csv`, the CSV's `Chunks`), a `RowSource` read through the engine's view (`seiza_duckdb::view::ViewRows`: a filter as an index of row numbers, a sort as a sorted copy, both in `tycho_view`, which the lockdown attaches; a Parquet file over `table::SORT_LIMIT` draws no arrow, and a CSV still loading is neither filtered nor sorted, `RowSource::busy`), wrapped in `Rows`, which keeps a weak reference to each page it hands the table so a row the table holds is read from its page (`Rows::loaded`; no copy, and nothing once the table drops it); the paging overrides from the URL, the panel's activity settings, the table's settings for the menus and the popover (`settle`: a finger's tap on a header one press, Ctrl+press a context press in a Mac browser, the popover on cut text, its fade and chevron, its "Focus row in panel" foot), each header's type badge (`type_icon`; `type_name` is the one place a column's type is named for a badge), the SVGs it draws (`icons`, embedded: the table loads a path at the call that sets it, so never a fetched asset), and the table's events turned into marks and probes (`publish`). The features Tycho turns on are `crate/Cargo.toml`'s, the table's and the bridge's alike; a new one is a decision (`docs/DECISIONS.md`, "Scope"). The `tycho:first-rows` and `tycho:viewport-filled` marks are set from `TallTableEvent::Filled`, which the table emits while the frame renders, so they land right after it's presented; set them nowhere else. Pages are 1024 rows (the component's default), read with a `file_row_number` filter; a row the table doesn't hold is read through the view too (`Rows::read`).
- **The frame:** the canvas holds the table alone; the top bar, the first screen, the command bar, the log, and the status bar are the page's (`web/CLAUDE.md`). `crate/src/frame.rs` is the seam: the workbench describes what the frame shows as one `FrameView` (the engine, the file and its facts, what's opening, its one line, the panel, the log, the bar's last answer, the table's active cell, the columns), published to the page from its render each time it changes (`Workbench::publish_frame`); a press in the table the page answers goes as an event, the sink's `press` (`frame::Press`, from `Workbench::table_pressed`), never as state (a popover opened on a cell outside the selection selects that cell, `Workbench::select_popover_cell`; its button, and the cell menu's "Focus row in panel" through `open_row` (`Workbench::open_row_at`), select their cell and send `open` only after the frame carrying the selection is published (`open_after_frame`), since the page's Row tab drops a focus ask for a row it isn't on: `docs/DECISIONS.md`, "Scope", 2026-11-25); a range of columns leaves no active cell; and the page's calls come in as `#[wasm_bindgen]` functions (`open_file`, `open_sample`, `retry_engine`, `set_theme`, `toggle_perf`, `command`, `back_to`, `row`, `row_text`, `select`, `open_row`, `fit`, `copy`), each run on GPUI's next turn with the window and the app, the window redrawn after, but `copy`, run at once (`send_now`) so the clipboard's write opens in the press's task. The page's menus act through `command` (a click's line, a refusal said in the frame's line, `About::Click`), `fit` (the table's `fit_column`), and `copy` (the table's `copy`); the frame's `columns` (every column in the view's order, each with its name as a command writes it, `typed`) is the column list's. **Never run one inside the workbench's update** unless it's the workbench's own (`on_workbench`): a call that sets a global the workbench observes (the engine's status, the panel's) would update it from within, and panic. Calls before the workbench exists wait (`PENDING`). `row` answers with a promise, `crate/src/row.rs`'s values of one row from the page the table holds or one row's query (`Workbench::row_values`), each cut at `row::MOST_CHARS`; `row_text` reads the same row uncut for the Row tab's copies (`row::copy_text`: a value as it is, or the row as a line of names and one of values, quoted as the table's copy quotes). `select` is the Row tab's Previous and Next row: one cell selected and scrolled into view through the table's `select_in_view` (`Workbench::select_cell`), focus left on the page. `complete` is the one call that answers at once: it reads the copy of the open file's view the workbench leaves in `frame.rs` (`set_catalog`, from its render, compared in place since the table renders every frame of a scroll), never the workbench. What the frame says is written here, in Rust (`Workbench::message`, `frame::facts`); the page only shows it.
- **Theme:** `crate/src/theme.rs` writes the token file (`web/src/tokens.css`, read by `build.rs` into `$OUT_DIR/tokens.rs`) onto the gpui-kit colors the table and the panel read (`map`), after `Theme::change` for the mode (`apply`). The page owns the mode: `start` takes the first, `set_theme` every change, and `shared/` doesn't follow the system for Tycho (`frame::first_theme`). A new token goes in the file's both blocks or the build fails.
- **Files from the device:** the page takes a drop or the file dialog's choice (`web/src/frame/core.ts`; GPUI doesn't deliver browser drops, `.claude/rules/gpui-web.md`) and hands the `File` to `frame::open_file`. `files::sniff` checks `PAR1` at both ends before anything reaches the engine. Every open registers under its own SQL name (`tycho/file-<n>.parquet`), never the file's: `read_parquet` would glob a name like `x[1].parquet`. A new open replaces the current one: its task is dropped, its queries cancelled, and its table closed (`TallTableState::close`).
- **CSV:** `crate/src/csv.rs`. A CSV isn't queried where it lies (it has no index). It's cut into chunks at record boundaries (Rust scans quote-aware, in 1 MiB reads that yield between frames), each chunk a `File` slice registered through `registerFile`, and each copied into **its own table**, `CREATE TABLE tycho_csv.f<n>.c<k> AS SELECT * FROM read_csv(…, auto_detect = false, …)`, in an attached compressed in-memory database (`ATTACH ':memory:' AS tycho_csv (COMPRESS)`, attached once by the lockdown, before the lock). The dialect and types come from `sniff_csv` on the first chunk (1 MiB), with RFC 4180 quoting forced (except for a TSV the sniffer found unquoted); the scanner, like DuckDB, opens a quoted field only at a field's start, so `12" pizza` is literal. A later chunk whose value doesn't fit a type widens that column to VARCHAR and goes again (the page SQL casts the earlier chunks). Chunks aim at 200 ms (`Sizer`, 1–8 MiB); the next chunk's end is scanned while DuckDB reads the current one. The table (`table::Source::Csv`, `csv::Chunks`) grows after every chunk. Rows are paged by `rowid`, except in a file with its own `rowid` column (which hides DuckDB's): its tables add `row_number() OVER () - 1 AS __tycho_row` (`csv::row_column`). Replacing a CSV that's still loading stops its task (`csv::Stop`: no further query is sent, the running one is cancelled), and the task drops its schema once that query answers; replacing one that's done or stopped drops the schema in `Workbench::close_current`. Every chunk stays registered with DuckDB for the session (unregistering is a fourth bridge call; a registration holds no bytes). Don't append chunks to one table or turn compression off without re-reading `docs/DECISIONS.md`, "Files and CSV".
- **The controller:** `crate/src/view.rs`. It holds the view's filters (`crate/src/filter.rs`: each typed against its column, written into SQL only by `filter::literal`) and its sort; `Workbench::sync_rows` gives them to the shown table after any change (a filter's index built off the table, then the source and `replace_rows` in one update with the sort; a sort alone through `set_sort`), and the table's `Sorted` comes back into the view as its widths do. The open file's view (`Load::Open`'s `view`) is a `Controller`, held by the table's column indices; `ViewState` is its named, serializable form (`docs/DECISIONS.md`, "Table and paging"). Every table is made from its calls (`table::new` takes `TableCalls`), and the shown table's `ColumnWidthsChanged`, `ColumnsMoved`, and `Pinned` go into it (`Workbench::watch_table`; on `Pinned` it reads the table's count, since the event carries the run in effect). **After any pin Tycho makes, read the table's count into the view** (`Controller::set_pinned`, as `pin_for_bench` does): `Pinned` comes only when the run in effect changes, so a count too wide to draw sends nothing. **Anything that calls `set_columns` gives the view back after it** (`TableCalls::apply`): `set_columns` resets the order. A CSV's widened column does (`Controller::retype`). **`take` reads the table's order and count as they are when the event is heard, never the event's payload** (events come after the update, so a `set_order` then `set_pinned` reports a stale count): a command changes the controller first, then the table (`TableCalls::arrange`), so its own events come back as no change, and a change that comes back is the table's own, a drag, which the log keeps (`Workbench::table_changed`). `arrange` calls `set_columns` only when widths or formats differ (`Controller::same_columns`): it resets the table's per-column state. `globalThis.__tychoView` publishes the view read-only while measuring, and `?bench`'s `__tychoPin` pins through the table (`frame.rs`).
- **The command bar and the log:** `crate/src/command/` reads a typed line or an agent's JSON to the same steps (`parse`), checks them against a copy of the controller, all or none (`plan`), and completes the part being typed (`complete`, its offsets UTF-16, the page's; with the command's parts for the bar's row, each column's kind for its badge, and a whole command's JSON, `Plan::json`); its verbs are `filter`, `sort`, `find`, `pin`, `unpin`, `hide`, `show`, `jump`, `clear`, and `undo` (`hide` and `show` take columns between commas, `command::groups`; `filter`'s line is cut by `split_filter`, which looks for the operator in the column's words alone, and its value is read as the column's type in `plan`, `filter::typed_value`, never in `parse`), every other verb of the grammar answered with its goal (`LATER`). A new verb goes in `VERBS`, `parse_line`, `json_step`, `plan`, and `complete`'s `part_at` and `slots`, with its words and tests, and leaves `LATER`; a completion item says whether a part follows it (`Item::space`), which is all the page reads to put a space after it. A step that changes the filters is logged at once with `Reply::Counting`, and the workbench settles its entries when the index answers (`Filtering::entries`, each with how it asked, `Asked`; `Log::settle`). One that can't be had fails through `Workbench::fail_entries`: an `Own` entry is a refusal (`Log::failed`, which moves the current entry and each `from` past it), a `Later` one keeps its step over what's in effect (`Log::rebase`), and the controller and the table follow the log back (`give_back`, `restore`'s half without focus). An index stopped before it was built keeps its entries in `uncounted` for one built again for the same filters. A filter or a sort the source refuses inside `run` gives the whole action back. `crate/src/log.rs` is the open file's history: each entry its command lines, words, reply, origin, time, and the view after it (none for a refusal or an answer, which never become current); `undo` (to the entry the current one was taken from, not the one before it in the list) and the way back (`back_to`) restore an entry's state through the controller, make it current only once that worked, and add no entry; a drag is an entry in words, a run of one column's resizes one entry, a table-made pin `pin x`, a table-made hide `hide x`. The workbench runs it all (`Workbench::command`, `run`, `undo`, `restore`) and answers in the bar (`say`), each answer carrying the number `frame::command` gave its command (`Answer::ask`; 0 for none), since the bar shows only its own command's answer and one can arrive after the next command is sent (`docs/DECISIONS.md`, "Scope", 2026-11-24); `run` reads the table's run in effect after applying a plan and refuses a `pin` it can't draw, giving the view back (`Plan::undrawn_pin`), once the table has been laid out (`Workbench::laid_out`, from its scrollbar's first report with a height: before it the run reads 0); a way back refused is said in the frame's line (`Notice`), not the bar; a CSV's growth counts its rows in every entry's reply (`Log::set_rows`); a refused action's lines are capped as a typed line's are (`shorten`); a file's opening starts the log again, and `close_current` clears it.
- **Jump to row:** the command bar's `jump`; `jump.rs` reads the row (full-width digits and thousands separators included, tested natively), and the table's `jump_to` brings it into view and selects it.
- **Keys and the clipboard:** the workbench's root has a key context of its own (`Workbench`), so a key the table goes on with reaches its bindings: Enter on a cell the popover doesn't open on is `OpenRow`, sent to the page as a press (`workbench::init` binds it). Cmd/Ctrl+C is the table's `copy`; each `TallTableEvent::Copy` goes to the bridge's `Clipboard` (`Workbench::copied`), and a copy that can't run is said in the frame's line (`Notice`, `About::Copy`). The workbench restores lost focus to itself (`cx.on_focus_lost`), and a command that runs puts focus on the table.
- **Errors and limits:** the engine failing to load or its worker stopping shows in the frame with Retry (`frame::retry_engine`); a stopped worker closes the open file, and the app hears of it at its next call. A Parquet page read that fails to read the file (`EngineError::is_read_failure`, `TallTableEvent::ReadFailed`) makes the workbench register the file again under a new SQL name (`tycho/<name>-r<n>.parquet`, at most every 5 s, doubling to a minute) and point the table at it (`table::read_from`, then `TallTableState::retry_failed`). Files over `limits.rs`'s sizes are refused before anything is read, and a CSV load stops at `csv::MEMORY_BUDGET` (1.5 GiB of DuckDB memory, checked after every chunk; above 1 GiB, a chunk of bytes that becomes no rows stops it too). The observation panel keeps clear of the table's scrollbars (`seiza::perf::set_clearance`).
- **The sample:** `dataset::sample` (its URL from the host, through `start`) is downloaded whole on the first screen's press (`files::download`) and opened as a `File`, like a dropped one; a file opened meanwhile replaces the download, and one refused leaves it running; every open reports under `FILE_MARKS`. Its row's words are the page's (`web/src/frame/bar.tsx`, `openRows`).
- **Arrow:** results cross the bridge as Arrow IPC stream bytes, read by the engine's reader (`engines/duckdb/crate/src/arrow.rs`). New column types go there, with a test (`engines/duckdb/CLAUDE.md`).

## DuckDB-Wasm gotchas

They're the engine's: `engines/duckdb/CLAUDE.md`, "DuckDB-Wasm 1.32.0 gotchas". Check them before debugging the table, a CSV load, or a failed read.

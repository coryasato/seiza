# Tycho's Rust crate (`crate/`)

The app itself: the title bar, the workbench, the table's source, the engine's events, files, CSV, jump to row, errors and limits. Claude Code loads this file when a file under `crate/` is read. Tycho's rules and the map of its folders are in `apps/tycho/CLAUDE.md`, the repo's in the root `CLAUDE.md`; both apply here. Paths are relative to `apps/tycho/`.

## Architecture

- **UI:** `shared/` (crate `seiza`) on the workspace's pinned `gpui-kit`.
- **Engine:** `engines/duckdb/` (`seiza-duckdb` in Rust, `@seiza/duckdb` in the host); its rules, architecture, and DuckDB-Wasm gotchas are in `engines/duckdb/CLAUDE.md`. Tycho's side is `crate/src/engine.rs`: it starts the engine from the post-paint callback, turns its events into the panel's "Engine ready" and "Parquet ready" steps and the `tycho:parquet-ready` mark, and runs `?selftest` once the Parquet prefetch settles.
- **Table:** `components/tall-table/` (`seiza-tall-table`): its rules are in `components/tall-table/CLAUDE.md`, its scroll model, page cache, cells, and tooltip in `components/tall-table/src/CLAUDE.md`; its DuckDB source (the page SQL, `QueryResult` as a page, the Parquet summary) is `seiza-duckdb`'s `tall-table` feature. Tycho's side is `crate/src/table.rs`: the source (`Source::Parquet`, a `ParquetFile`; `Source::Csv`, the CSV's `Chunks`), the paging overrides from the URL, the panel's activity settings, and the table's events turned into marks and probes (`publish`). The `tycho:first-rows` and `tycho:viewport-filled` marks are set from `TallTableEvent::Filled`, which the table emits while the frame renders, so they land right after it's presented; set them nowhere else. Pages are 1024 rows (the component's default), read with a `file_row_number` filter; the samples' row-group sizes, and why, are in `docs/data.md`.
- **Files from the device:** `crate/src/files.rs`: drops and the file dialog go around GPUI (`.claude/rules/gpui-web.md`, "GPUI doesn't deliver browser file drops"). `files::sniff` checks `PAR1` at both ends before anything reaches the engine. Every open registers under its own SQL name (`file-<n>.parquet`), never the file's: `read_parquet` would glob a name like `x[1].parquet`. A new open replaces the current one: its task is dropped, its queries cancelled, and its table closed (`TallTableState::close`).
- **CSV:** `crate/src/csv.rs`. A CSV isn't queried where it lies (it has no index). It's cut into chunks at record boundaries (Rust scans quote-aware, in 1 MiB reads that yield between frames), each chunk a `File` slice registered through `registerFile`, and each copied into **its own table**, `CREATE TABLE tycho_csv.f<n>.c<k> AS SELECT * FROM read_csv(…, auto_detect = false, …)`, in an attached compressed in-memory database (`ATTACH ':memory:' AS tycho_csv (COMPRESS)`). The dialect and types come from `sniff_csv` on the first chunk (1 MiB), with RFC 4180 quoting forced (except for a TSV the sniffer found unquoted); the scanner, like DuckDB, opens a quoted field only at a field's start, so `12" pizza` is literal. A later chunk whose value doesn't fit a type widens that column to VARCHAR and goes again (the page SQL casts the earlier chunks). Chunks aim at 200 ms (`Sizer`, 1–8 MiB); the next chunk's end is scanned while DuckDB reads the current one. The table (`table::Source::Csv`, `csv::Chunks`) grows after every chunk. Rows are paged by `rowid`, except in a file with its own `rowid` column (which hides DuckDB's): its tables add `row_number() OVER () - 1 AS __tycho_row` (`csv::row_column`). Replacing a CSV that's still loading stops its task (`csv::Stop`: no further query is sent, the running one is cancelled), and the task drops its schema once that query answers; replacing one that's done or stopped drops the schema in `Workbench::close_current`. Every chunk stays registered with DuckDB for the session (unregistering is a fourth bridge call; a registration holds no bytes). Don't append chunks to one table or turn compression off without re-reading `docs/DECISIONS.md`, "Files and CSV".
- **Jump to row:** the header strip's input (`workbench.rs`; parsing, full-width digits and thousands separators included, in `jump.rs`, tested natively; what it does, item by item, is `perf/jump.ts`'s header). It's gpui-base's unstyled single-line `Input`, styled here, with the right-click menu built in `edit_menu` (why not gpui-kit's: `.claude/rules/gpui-web.md`). The workbench restores lost focus to itself (`cx.on_focus_lost`), so its Cmd/Ctrl+G binding survives the table going away.
- **Errors and limits:** the engine failing to load or its worker stopping shows in the empty state with Retry (`engine::retry`); a stopped worker closes the open file, and the app hears of it at its next call. A Parquet page read that fails to read the file (`EngineError::is_read_failure`, `TallTableEvent::ReadFailed`) makes the workbench register the file again under a new SQL name (`<name>-r<n>.parquet`, at most every 5 s, doubling to a minute) and point the table at it (`table::read_from`, then `TallTableState::retry_failed`). Files over `limits.rs`'s sizes are refused before anything is read, and a CSV load stops at `csv::MEMORY_BUDGET` (1.5 GiB of DuckDB memory, checked after every chunk; above 1 GiB, a chunk of bytes that becomes no rows stops it too). The observation panel keeps clear of the table's scrollbars (`seiza::perf::set_clearance`).
- **Title bar:** `crate/src/shell.rs` (`Shell`, around the workbench): the title, the theme toggle (Sun/Moon button and Cmd/Ctrl+Shift+L; a press calls `seiza::stop_following_system_appearance`, in memory until a reload), and the observation panel's button (`seiza::perf::toggle`). Its icons go to `seiza::Bootstrap::assets` (`Icons`), and the jump input's Mac editing keys come from `Bootstrap::mac_input_bindings()`. Change the bar and the placeholder's `titleBar` must change with it.
- **Empty state:** `render_empty` (`workbench.rs`). Change a label or a button in `render_empty` and the placeholder must change with it: `just tycho placeholder` fails until it matches (box edges per button, text per line, surfaces, at DPR 2 and 1).
- **Arrow:** results cross the bridge as Arrow IPC stream bytes, read by the engine's reader (`engines/duckdb/crate/src/arrow.rs`). New column types go there, with a test (`engines/duckdb/CLAUDE.md`).

## DuckDB-Wasm gotchas

They're the engine's: `engines/duckdb/CLAUDE.md`, "DuckDB-Wasm 1.32.0 gotchas". Check them before debugging the table, a CSV load, or a failed read.

## Commands

`just tycho wasm`, `dev`, and `lint` build and check it (the top file's Commands); its checks run from `perf/` (`perf/CLAUDE.md`).

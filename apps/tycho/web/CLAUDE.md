# Tycho's JS host (`web/`)

The Vite host the wasm boots in, and the page's frame around the table. Claude Code loads this file when a file under `web/` is read. Tycho's rules and the map of its folders are in `apps/tycho/CLAUDE.md`, the repo's in the root `CLAUDE.md`; both apply here. Paths are relative to `apps/tycho/`.

## Architecture

- **JS host:** `index.html` (the head script that sets `data-theme` before the page paints, the prerendered `#root`, and `#table-slot`), `src/main.ts` (binds the frame, creates the engine's bridge, imports the sample as a hashed asset, boots the wasm, and loads React after the first frame), and `vite.config.ts` (Tailwind, the frame's prerender, `virtual:tycho-sample` from `data/MANIFEST.json`, the engine's `duckdb()` plugin, the frame's stylesheet named `assets/frame-*.css`, and the check that refuses a build or dev server without `data/gcat.parquet`, or with a file whose SHA-256 isn't the manifest's). What goes in JS at all: the root `CLAUDE.md`, "Stack and pins": the frame draws what the app publishes and calls the app; the logic is the crate's (`crate/CLAUDE.md`, "The frame").
- **The frame** (`src/frame/`): React with shadcn's components on Base UI and Tailwind (`docs/DECISIONS.md`, "Scope", 2026-11-23), as the design canvas draws it, scaled back to what Tycho has (`view.tsx`): the top bar and the file's menu, the command bar (`bar.tsx`), the first screen, the toolbar and its editors (`toolbar.tsx`), the left panel's column list (`columns.tsx`), the table's menus (`menus.tsx`), the right panel's log (`log.tsx`) and row view (`rowview.tsx`), the status bar, the haze, and at a phone what the design puts in their place. Three rules hold it together:
  - **Nothing of React before the first frame.** `prerender.tsx` renders the frame to HTML at build time and in dev; `hydrate.tsx` loads after `gpui:first-frame`. Until then `core.ts` runs the page: every control says what it does with `data-action` (one listener runs it), the first screen's box (its arrows, Enter, and a press; `hydrate.tsx` hands it to Base UI with `handOver`), the page's keys, drops and the haze (`data-dragging`), the file dialog, and the theme. Give a new control a `data-action`, not an `onClick`, if it's on the page before React. React's chunk must stay out of the first-paint set (smoke fails a request before the first frame). The prerender imports the frame's modules, `core.ts` included, where there's no `document`: nothing may touch the page as a module loads.
  - **The app's state, one store.** `state.ts` holds what the app publishes (`frameSink`, the `Frame` the crate calls); `view.tsx` reads it with `useSyncExternalStore`, the prerendered state (`INITIAL`) while hydrating, so the two renders match. A press in the table the page answers (a menu, the Row tab) comes as an event, not state: `frameSink.press`, heard through `subscribePress`; a row's values come from `App.row`. What CSS alone shows rides on the root's attributes (`data-file`, `data-panel`, `data-log`, `data-columns`).
  - **The canvas is the table's.** GPUI adds its canvas to `<body>`; `core.ts`'s `slotCanvas` moves every one into `#table-slot` as it's added (pointer and viewport are read relative to the canvas). `#root` is `display: contents`, so the frame's parts and the slot share the body's grid. The first screen sits over the canvas and lets it show (the perf panel draws there; its ghost of a table steps aside for it).
- **The command bar** (`bar.tsx`): one box on Base UI's Autocomplete (inline, unfiltered), in two places. With no file it's the first screen's box: its rows alone, O and S choosing them while its input is empty, a typed line answered there. With one open it's a box in the top bar (a button at a phone) that opens the bar over the page (`core.ts`'s `openBar`, `closeBar`): the crate's completion as the list (`App.complete`, at once, for the text and caret), the command's parts, and what Enter would do (`Completion.preview`), or the last answer. Its rows run by `data-action`, as on the first screen: Base UI presses an item with a DOM click. Base UI names the items' ids, so nothing presses one by id. When a file opens, the top bar's box moves from where the first screen's was (`state.ts` keeps its rect, `takeBarFrom`). `App.command` returns its command's number, and the box shows and acts on (closes on `done`) only the answer carrying it (`Answer.ask`): an earlier command's answer can arrive after the next is sent.
- **The toolbar** (`toolbar.tsx`): a row of the main column under the top bar, between the panels (the grid's `tools` area; Phone 5's line under it), while a file is open, drawn from the frame's `tools` (the view's filters, each with the command that adds it and the one that removes it alone; the sort; the rows in view) and `columns`. One control a kind, outlined or a chip; at a phone the icons with counts. What's open is its own store (`openFilterEditor` for a column's menu): at a wide page a Base UI Popover on each control's trigger, which keeps one shape whatever its state (a remounted trigger loses an open popover's anchor), the filter's control holding both the list and the editor; at a phone a Drawer sheet, but the hidden chip's, which turns the panels' sheet to Columns. Everything acts through `act`: the filter editor's operators and their words are `App.complete`'s after the column, its command `App.filter_line`'s (the crate quotes each value: never quote a value here), and whether Apply runs is the bar's preview of that command (`Completion.preview`); the sort editor applies as it's pressed. An action that ends a popup or a sheet closes it through itself (the `Close` context), so its closing plays (a popover keeps drawing what it held meanwhile; a sheet clears the store once it has) and gives the table focus (`finalFocus`); Escape gives focus back where it was, the editor a column's menu opened to where that menu was opened (`openFilterEditor`'s `back`). While a filter's index is built the count says so (`tools.counting`). Its controls run by `onClick`: the toolbar is only drawn with a file, after React.
- **Find** (`find.tsx`): the toolbar's Find button, and the bar it opens at the toolbar's right, the chips drawn as their icons meanwhile (`Chip`'s `compact`), or at a phone on a row of its own under the toolbar. Its open state is `core.ts`'s (`openFind`, `closeFind`), opened by Cmd/Ctrl+F (Cmd on a Mac, Ctrl elsewhere: `findKey`, taken on the way down once the toolbar is drawn and nothing opens, and let through from find's own input, so the second press is the browser's), the button, or the bar's `find` (the frame's `find.opens` changing). Opened over the command bar, it closes the bar and takes its way back; over a menu, a popover, or a sheet, each closes itself as find opens (`subscribeFind`), its `finalFocus` giving way to find's. The app holds the rest (`crate/CLAUDE.md`, "Find"): the input's text goes to `App.find` as typed, Enter, Shift+Enter, and the buttons to `App.find_step`, and the bar shows the frame's `find.text` in a `role=status`. The buttons don't take focus, so Enter goes on stepping; Escape and Close end it, focus on the table once a step has landed, else back where it opened (the Find button looked for again once it's drawn). The tag under the input says the second press is the browser's until a character is typed, and a live region says it too.
- **The log** (`log.tsx`): the right panel (Log and Row tabs, Log first, the tab kept: `core.ts`'s `setPanelTab`) and its Log tab, drawn from the frame's `log` (the entries are the app's; the way back calls `App.back_to`, `core.ts`'s `backTo`). Its open state is `core.ts`'s (`setLogOpen`, the top bar's `data-action=log`, the root's `data-log`), collapsed at first and kept across files. At a wide page it's a column of the body's grid, so the table's slot narrows; at a phone it's a sheet over the table, Base UI's Drawer, not modal, its height snap points (`docs/DECISIONS.md`, "Scope", 2026-11-24). Its chrome isn't selectable, and Cmd/Ctrl+A in a tab selects its `[data-select-all]` alone (the log's entries, the row's fields).
- **The menus** (`menus.tsx`): a column's and a cell's, drawn from the frame's `columns` (so a column pinned or hidden since its press shows as it is now), holding only what runs: a column's sort either way (its type's words, the bar's completion's), "Filter this column" (the toolbar's editor on it, which takes focus: `Item.focuses`), Pin, Hide, and Fit; a cell's, and a Row tab field's, keep and leave out its value (`keepValue`: the value read whole through `App.row`, or `App.row_text` past its cut, then `App.filter_line`). The table's presses open them (`subscribePress`: the header icon's under its bounds, a context press at the pointer, a canvas's coordinates moved into the page by the canvas's offset; a `tap` on a header only at a phone after a finger's press), and so does a row of the column list (`openColumnMenu`, anchored to the row). A wide page's is Base UI's Menu with no trigger, a phone's a Drawer sheet over a scrim, its rows 44 px. An action is a click's command (`core.ts`'s `act`, the column's `typed` name: never quote a name here) or the table's call (`fitColumn`, `copySelection`); `App.copy` is never queued, since the clipboard's write must open in the press's task. Each menu holds its own open state and is dropped once its closing has played (`onOpenChangeComplete`), keyed by a count of menus opened, and every menu closes when another file opens (its log's first entry changes). Acting gives the table focus through the popup's `finalFocus` (focusing it from the item's handler leaves focus on `<body>` once the menu closes), but after an item that places focus itself (`Item.focuses`: "Focus row in panel" gives the table focus from its handler, and the row's field takes it once drawn, which can be after the menu's closing has played), whose `finalFocus` is `false`: a focus chosen at the closing's start is applied at its end, over the field's; Escape or a press outside gives it back where it was. A panel's own keys (Escape, select-all) skip a key from outside its DOM: React passes a portal's events (a menu's, the show-and-hide list's) up to it.
- **The row view** (`rowview.tsx`): the panel's Row tab and the phone's sheet's, following the frame's `active` cell (none for a range of columns, which picks no row): its row read through `App.row` when the row, the view (`columns`: order, types, hidden flags), or the file changes, and the active field kept in sight only when the row or the active column changes, scrolling the fields alone (`keepInSight`, never `scrollIntoView`, which scrolls the page around them). The table's presses that open it (`double`, `enter`, `open`) are heard in `menus.tsx` and open it through `core.ts`'s `openRow`, which turns the shown one to Row, the panel at a wide page or the sheet at a phone, the other keeping its tab; each but the double press (`enter`, `open`, and the cell menu's "Focus row in panel", which the app answers with an `open` press after it selects the cell: `App.open_row`) asks for focus at its field (`docs/DECISIONS.md`, "Scope", 2026-11-25), taken once that row is drawn (`takeRowFocus`, a store the tab subscribes to, since the row may be drawn already). Previous row and Next row are `App.select`, `aria-disabled` at the ends, never `disabled` (a disabled button drops its focus to the page); its copies (`copyRowText`) open the clipboard's write in the press's task and hand it `App.row_text`'s whole text, or write the value the tab holds whole at once where a browser has no ClipboardItem; a field's menu is `menus.tsx`'s (`openFieldMenu`), focus back on its button, closed when the tab moves to another row (`closeFieldMenuOff`), its Copy (`core.ts`'s `copyField`) said on the field's own Copy button.
- **The column list** (`columns.tsx`): the left panel at a wide page (`core.ts`'s `setColumnsOpen`, the top bar's `data-action=columns`, a column of the grid at the table's left, closed at first and kept across files), and at a phone the panels' sheet's Columns tab (`log.tsx`, the sheet's tab `core.ts`'s `setSheetTab`, Columns first). Its rows open their column's menu; its head's button opens the show-and-hide list (Base UI's Popover; `ShowHideList`, which the toolbar's Columns control opens too), whose eyes and Show all are click commands too.
- **Keys and focus:** the page's keys (Cmd/Ctrl+K, Cmd/Ctrl+Shift+L, Cmd/Ctrl+Shift+P) are taken on the way down, before the canvas, which may mark a key handled before it bubbles (Firefox). Cmd/Ctrl+K focuses the first screen's input, or opens the bar; Escape puts focus back where it was (in the log, on the table, the panel left open), a command that ran or a way back taken puts it on the table (`docs/DECISIONS.md`, "Scope", 2026-11-24, the bar's keys). GPUI takes focus for its own hidden input (gpui-pre-web's `ImeMirror`, `body > textarea`) as its window opens, so the first screen's input takes it back after the first frame, and a file opened from it hands focus to that input, which is where the table's keys arrive.
- **Theme and type:** `src/tokens.css` is the one token file, dark and light, in oklch; `crate/build.rs` reads it too, so the canvas's colors follow it (`docs/DECISIONS.md`, "Scope", 2026-11-23). `src/frame.css` maps it into Tailwind. The page follows the system until the theme button or its key, then holds until a reload (in memory). The DOM draws in Plex Sans: Regular registered from the bootstrap's bytes (`main.ts`, the canvas's face, one download), Medium and SemiBold (`src/fonts/`, the same release, 3.005) loaded after the first frame, never in the first-paint set; until they load the browser synthesizes them. Plex Mono Regular, the bar's and the key hints' face, loads after the first frame with them; the system's monospace until then.

## Files

```
web/              # Vite host: index.html, vite.config.ts; public/duckdb-ext/ is downloaded (gitignored)
  src/main.ts     # the entry: frame bound, bridge, wasm boot, React after the first frame
  src/tokens.css  # the token file (the page's and, through crate/build.rs, the table's)
  src/fonts/      # Plex Sans Medium and SemiBold (woff2, @ibm/plex-sans 1.1.0), Plex Mono Regular (@ibm/plex-mono 1.1.0), and their OFL
  src/frame.css   # Tailwind, the tokens' mapping, the page's grid
  src/frame/      # state.ts (the app's state), core.ts (the page before React, the page's keys, the bar's, the log's, and the left panel's open state, the menus' calls), view.tsx (the frame), bar.tsx (the command bar), toolbar.tsx (the toolbar, the filters' list, and the filter and sort editors), find.tsx (find's bar and the toolbar's Find), log.tsx (the right panel, its Log tab, and the phone's sheet), rowview.tsx (the Row tab), columns.tsx (the column list), menus.tsx (the column's, the cell's, and a field's menus; the presses that open the Row tab), icons.tsx (with the type badge), prerender.tsx, hydrate.tsx
```

## Commands

```
just tycho extensions   # download the DuckDB extensions the engine pins (engines/duckdb/web/duckdb-extensions.json) into web/public/duckdb-ext/; dev and build run it
```

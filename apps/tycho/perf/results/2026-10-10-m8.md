# M8: deploy to Cloudflare (2026-10-10, files dated UTC)

Production: **https://tycho.seiza.io**, one Worker (custom domain) with static assets and R2. Measured from Apple M1, macOS 25.6, machine `local`, Chromium headless=new, 1440×900 at DPR 2, median of 10, over the owner's home connection (~25 ms to Cloudflare's SJC data center, ~100 Mbit/s). Load average 1.4–6.2 during the runs (recorded per part in each file).

Budgets apply to the local build only (decided in M8; root CLAUDE.md, measurement protocol). Production numbers are recorded beside the local ones and never fail a run.

Raw: `2026-10-10-m8-prod-cold.json` (Cloudflare's own compression), `2026-10-10-m8-prod-cold-br.json` (quality-11 br), `2026-10-10-m8-prod-no-edge-cache.json` (the full suite, before the edge cache), `2026-10-10-m8-prod.json` (the full suite: cold, jump, and csv against production; panel local; table updated with the edge cache), `2026-10-11-m8-prod-table.json` (the table part again, under the recorded-not-enforced rule; the date rolled over in UTC).

## What changed

- **Worker** (`worker/src/index.ts`): `/data/*` from R2 by range (as in M3), now through Cloudflare's edge cache, keyed by each sample's content SHA (`DATA_VERSIONS`). The page, `/assets/*`, and `/duckdb-ext/*` run the Worker first and go out as the deploy's quality-11 `.br`. DuckDB's two wasm bundles (over the 25 MiB asset limit) are in R2 under `assets/`. The page is `no-cache, no-transform`.
- **Deploy** (`just tycho deploy`, `worker/scripts/deploy.ts`): R2 uploads by SHA-256 over the S3 API, `.br` copies, `.assetsignore`, `wrangler deploy` with `DATA_VERSIONS`, then `check.ts` against production.
- **`_headers`** from `shared-web`'s Vite config: COOP/COEP/CORP on every asset, `immutable` on `assets/`.
- **Perf scripts:** `--url` on table, jump, and csv (`serveApp`), passed by the suite to every part but panel; `perf.ts` splits TTFP at wasm ready and, with `--vs-local`, measures the local build interleaved.

Everything production adds is before wasm ready: a probe of the waterfall (ad hoc, 8 runs) put the connection at 27 ms, the HTML at +28, the wasm's first byte 81 ms after its request (one round trip plus the edge), and its transfer at 65 ms; all zero for local preview. From wasm ready to the first frame, production and local match.

Cloudflare's own compression sent the app wasm as zstd to Chromium (which offers zstd), at a low level: 3.92 MB against 2.89 MB at br quality 11 (3.85 MB as Cloudflare's br, 4.05 as gzip). DuckDB's eh bundle: 7.14 MB zstd against 5.19 MB br-11. The Worker's path costs ~5 ms (`Server-Timing: cfWorker;dur=5`); `/` through the Worker and `/index.html.br` straight from static assets answered within noise of each other (49–75 ms on a fresh connection).

A first page in production is ~8 sequential round trips: the app's `bytes=0-0` size probe, DuckDB's sizing HEAD, two footer reads, and four readahead steps (16 KB → 1 MB; Gaia adds 4 MB, 5.6 MB in all). A range read from R2 took 55–125 ms against 20–35 ms for a static asset on a warm connection; from the edge cache, a hit took 40–75 ms after the connection against ~210 for a miss. Throttled numbers match local: Fast 4G's emulated latency and bandwidth dominate both. Not optimized further: production goals get their own session.

## Checks

- **Custom domain:** `tycho.seiza.io` (Workers custom domain), `workers_dev = false`, `preview_urls = false`. a fixed-string `git grep` for the default subdomain's suffix finds only PLAN.md's M8 note and Hosting section; every results file records only `https://tycho.seiza.io/` (or local).
- **`just tycho perf` against production:** cold, jump, csv pass (`m8-prod`), table passes (`m8-prod-table`), panel passes on the local build (170/170 values within 5%, reference and throttled).
- **`crossOriginIsolated === true`:** in Chromium, Firefox, and WebKit (`just tycho smoke https://tycho.seiza.io/`: 0 console errors, 0 blank frames).
- **Ranges:** `check.ts --url https://tycho.seiza.io` passes: HEAD `Content-Length` + `Accept-Ranges: bytes`, ranged HEAD 206, GET 206 with the right `Content-Range` for closed, open, suffix, and clamped ranges, 416s, 404s, the whole file's SHA-256, a repeated range served from the edge cache with the same bytes. Both samples load and scroll in production (table part: last row matches `count(*)`, the fling reaches the end, both samples).
- **Compression:** every wasm, JS, font, and the page go out as br, byte-for-byte the deploy's quality-11 `.br` (`check.ts` counts the wire bytes). Without the Worker's copies, Cloudflare negotiated zstd.
- **No request before first paint:** every cold run; the zone's Web Analytics beacon (injected into the HTML until the page went out `no-transform`) failed all 20 runs of the first production measurement.

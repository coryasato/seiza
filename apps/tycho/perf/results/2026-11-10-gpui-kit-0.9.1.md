# Dependency upgrade: gpui-kit 0.9.0 → 0.9.1 (2026-11-10)

**Machine:** local (Apple M1, Darwin 25.6.0), Chromium 153.0.8010.12. **Machine load:** 2.7 at `check`, 4–6 through the A/Bs, with the user's browsers open; TTFP is compared interleaved against a 0.9.0 build, not against the baseline.

**What changed:** `gpui-kit =0.9.1`, `Cargo.lock` re-seeded from 0.9.1's published lock: gpui-kit/gpui-component/gpui-base/gpui-kit-assets 0.9.1, **gpui-pre-* 0.3.11 → 0.3.12** (gpui-fast, unused, 0.1.13 → 0.1.14), rustls 0.23.46 and rustls-webpki 0.103.16 (upstream's CVE fix; native-only, not in any wasm); wasm-bindgen still 0.2.127. `arrow`'s crates (60.1.0 → 60.0.0) and `atoi` (3.1.1 → 3.1.0) floated on `cargo fetch` again and were pinned back. No code changes. Every crate passes clippy (wasm32 and native, each recipe's feature sets); `just tall-table test` (1,364 tests over its feature builds) and `seiza`'s, the engine's, Tycho's, and the GPUI contender's native tests pass. JS dependencies unchanged.

**What 0.9.1 changes that reaches the web build:** gpui-pre-web 0.3.12's source is identical to 0.3.11's (only its version and zed snapshot rev), but gpui-pre 0.3.12's core changes the input path. **Every mouse and scroll event now resets the cursor:** `Window::dispatch_mouse_event` calls `reset_cursor_style` after the listeners on every event (0.3.11 called it only when the hit test changed), and on the web that is gpui-pre-web's `set_cursor_style`, which writes `document.body.style.cursor` each time with no check for an unchanged value: a call into JS for every wheel event in a fling and every move in a drag. Its cost to frame work and to input → response is **not measured** here (below). gpui-pre 0.3.12 also keeps a cached view's or deferred element's entity subscriptions when its prepaint is reused (the perf panel is a cached view; their paint now runs inside the accessed-entities scope), and re-measures `list` items when its padding changes. The rest of the release is desktop and component work (DataTable, GridLayout, Markdown, Slider, gpui-shell) that Tycho doesn't build or that the optimizer strips; the tall table's view of the DataTable changes is in `components/tall-table/perf/results/2026-11-10-gpui-kit-0.9.1.md`.

**The "before" build:** the same tree with the bump stashed, built in place (`just tall-table build`, `just tycho build`, `just observatory gpui-build`, then `gpui-parts`), so its gpui-kit 0.9.0 dependencies came from `target/`'s cache; then the bump restored and the same builds again.

**Files:**
- `2026-11-10-gpui-kit-0.9.1-ab.json`: `just tycho placeholder --ab <0.9.0 build's web/dist>`, 10 interleaved runs per build, reference and throttled; also the placeholder checks on 0.9.1.
- `2026-11-10-gpui-kit-0.9.1-ab-reference.json`: the reference A/B again (`--reference-only`).
- The GPUI contender's wasm by crate, both builds: `apps/observatory/perf/results/2026-11-10-gpui-kit-0.9.0-parts.json` and `…-0.9.1-parts.json`.

The throttled A/B met its spread gate (0.9.0 2.3%, 0.9.1 2.8%): level. The reference A/B didn't meet its 6% gate in two runs, each failed by one side's outlier: 0.9.0 15.4% / 0.9.1 5.4% (medians 199.9 vs 198.9), then 0.9.0 5.9% / 0.9.1 7.1% (medians 199.1 vs 200.3; the table's row). Read it as reference TTFP unchanged, not proven to 3%, as with 0.9.0.

`just tycho check`'s steps after `lint` (the home-path check and `perf.ts --check`; `lint` fails on an unrelated TypeScript error, below): 206.0 ms vs the 214.8 ms limit, 2930.1 KiB vs 3283.0 KiB, no home path in the wasm. PASS.

Where the bytes went, in the GPUI contender (`gpui-parts`, brotli scaled to the file): framework code +3.0 KiB (raw −17.6), static data +0.3, runtime −0.6, the data layer −0.1; the component and the host flat. The other builds: the GPUI contender 2771.1 → 2773.5 KiB (+2.4), the tall table's bare host 2749.4 → 2753.6 KiB (+4.2); their notes are `apps/observatory/perf/results/2026-11-10-gpui-kit-0.9.1.md` and `components/tall-table/perf/results/2026-11-10-gpui-kit-0.9.1.md`.

## Functional checks

- First-frame probe: the mark followed the presenting GPU task in every `check` run on 0.9.1 (WebGPU).
- Placeholder vs first frame (light/dark, DPR 2 and 1: 0.0000% of surfaces differ), the slow-font controls, and the theme toggle: PASS.
- Still true on 0.9.1 (source checked): gpui-base's Input binds its Mac shortcuts only under `cfg(target_os = "macos")` (`cmd-a` among them), so `shared/`'s bootstrap still binds them; gpui-pre-web still `preventDefault`s and drops `dragover`/`drop` and still renders the first real size from its `ResizeObserver` with `force_render`; `skeleton.rs`, gpui-kit-assets (the Sun/Moon icons), and the default theme's colors are unchanged. The title bar now rounds its corners by the theme's new `window.radius`, 0 by default, so it draws as before.
- **Not the bump:** `just tycho lint` fails in its TypeScript step: `shared-web/perf/protocol.ts(67,11): error TS2304: Cannot find name 'ResizeObserverEntry'` (`tsc -p shared-web/perf`, TypeScript 7.0.2). Neither that file nor its `tsconfig.json` changed in this bump; left for its own fix.
- Not run: the full suite, `table` (so the fling's frame work under the cursor reset per event is unmeasured), `jump` (so the paste and context-menu checks are 0.9.0's: gpui-component 0.9.1 sizes the menu's items in rems, and `jump.ts`'s `MENU_PASTE_DY` is unchecked on it), `engine`, `smoke`. Manual pass in real Firefox and Safari not done. `table` and `jump` are left to Tycho's next table milestone (its `PLAN.md`).

## The static placeholder shell: decided yes, built later

`just tycho placeholder` (`perf/placeholder.ts`): HEAD's release build against a copy whose `index.html` adds a prototype placeholder (an HTML/CSS copy of the empty shell in system fonts, saying "Loading the app…", removed by a `PerformanceObserver` once `gpui:first-frame` is set). Same wasm and JS. Interleaved, run by run, alternating order, 10 runs each per profile.

| | HEAD: TTFP | Placeholder: TTFP | Placeholder: its paint |
|---|---|---|---|
| Reference | 193.7 ms | 193.3 ms | **66.5 ms** |
| Throttled | 3696.9 ms | 3668.5 ms | **234.5 ms** |

The placeholder's paint is the Element Timing render time of its heading: when its text was painted. Not the browser's first-contentful-paint, which the protocol rules out (on HEAD's page it's the canvas). In every run the placeholder painted before the first frame and was gone after it; the script fails otherwise, and fails if the injection into `index.html` didn't happen. The first run of this A/B used FCP and read the same (56.5 / 237.4 ms; code review).

On Fast 4G a visitor sees the shell **3.46 s sooner**, and TTFP doesn't move (−28 ms throttled, −0.4 ms reference; noise). The placeholder paints ~63 ms after the HTML arrives (171 ms), long before the 2.8 MiB of wasm. This A/B ran on the post-review build (2805.0 KiB).

**Decision: build it, in its own piece of work** (M7 part G, see PLAN). What building it needs, beyond the prototype:
- **Fonts.** The UI font is preloaded `as=fetch` for GPUI, and a CSS `@font-face` can't use that preload, so Plex would download twice and compete with the wasm on a slow link. The prototype uses system fonts, so the text would shift at the swap. Decide between that, or one font download both can use.
- **A pixel match.** An HTML copy of the shell drifts from the GPUI one unless something checks it: a screenshot of the placeholder against the first frame, in light and dark.
- **The swap.** No blank frame between them; the prototype keeps the placeholder above the canvas until the mark, so a late removal shows the placeholder a frame longer, never nothing.
- **Owning it in the README.** A DOM layer in a "GPU beats DOM" demo: say what it is, that it's inert, and that TTFP still means GPUI's first frame.

## One copy of the mark and clock helpers

It replaces `frames.rs`'s `mark` and `now`, Tycho's `engine::bridge` `now`, `mark_start_time`, and its inline `performance.mark`, and the workbench's `mark_at`. Readers take the **last** entry: part D had already moved `mark_start_time` to the last entry, so the three copies agreed by the time they were merged. Nothing measured changed; the wasm is +1.8 KiB brotli, and +0.6 KiB after the review merged `mark` and `mark_at` into one `performance.mark` call that reads `startTime` off the returned entry.

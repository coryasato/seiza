# Dependency upgrade: gpui-kit 0.8.0 → 0.9.0 (2026-11-02)

**Machine:** local (Apple M1, Darwin 25.6.0). **Machine load:** 25 at `check` (right after the release builds), 3–4.5 through the A/Bs and the suites, with the user's browsers open; TTFP is compared interleaved against a 0.8.0 build, not against the baseline.

**What changed:** `gpui-kit =0.9.0`, `Cargo.lock` re-seeded from 0.9.0's published lock: gpui-kit/gpui-component/gpui-base/gpui-kit-assets 0.9.0, **gpui-pre-* and gpui-pre-web 0.3.9 → 0.3.11** (the default backend; gpui-fast, unused, 0.1.10 → 0.1.13), wgpu 29.0.4/30.0.1 → 30.0.1 alone, taffy 0.13/0.14 → 0.15, icu 2.3 → 2.4; wasm-bindgen still 0.2.127. `arrow`'s crates (60.0.0 → 60.1.0) and `atoi` (3.1.0 → 3.1.1), the workspace dependencies outside gpui-kit's lock that floated on `cargo fetch`, were pinned back. One code change, in the tall table: gpui-pre 0.3.11 renames `ScrollWheelEvent` → `ScrollEvent` (a new `source: ScrollSource` field, `Pointer` for a wheel) and the element's `on_scroll_wheel` → `on_scroll`; the old names are deprecated aliases, which clippy's `-D warnings` refuses. Every crate builds and passes clippy (wasm32 and native, all features); `just tall-table test` and the engine's, `seiza`'s, and Tycho's native tests pass. JS dependencies unchanged.

**The nightly:** stays `nightly-2026-09-20`. `wasm_thread` 0.3.3 (gpui-pre-web's `multithreaded`) still needs `#![feature(stdarch_wasm_atomic_wait)]`. `nightly-2026-11-01` fails to build gpui-pre 0.3.11 (`E0391: cycle detected when computing when scheduler::executor::TaskState needs async drop`), a rustc regression filed and fixed upstream (rust-lang/rust#165263); it also reports `trim-paths` stable in 1.101, so the next nightly bump drops `cargo-features = ["trim-paths"]`.

**Files:**
- `2026-11-02-gpui-kit-0.9.0-ab.json`: `just tycho placeholder --ab` against a HEAD (0.8.0) build from a worktree with its own `target/`, 10 interleaved runs per build, reference and throttled; also the placeholder checks on 0.9.0.
- `2026-11-02-gpui-kit-0.9.0-ab-reference.json`: the reference A/B again (`--reference-only`).
- `2026-11-02-gpui-kit-0.9.0-table.json`: `just tycho table --reference-only`, asteroids, n=10.
- `2026-11-02-gpui-kit-0.9.0-jump.json`: `just tycho jump --reference-only`, asteroids + Gaia, n=10, with the input's edge checks.
- The GPUI contender's wasm by crate, both builds: `apps/observatory/perf/results/2026-11-02-gpui-kit-0.8.0-parts.json` and `…-0.9.0-parts.json`.

| App wasm (after wasm-opt) | 10195.1 KiB | 10415.6 KiB (+220.5) |
| App wasm (brotli 11) | 2855.6 KiB | **2924.8 KiB (+69.2 KiB, +2.4%)** |
| Reference TTFP, interleaved A/B (n=10) | 197.0 ms | 197.9 ms (+0.5%) |
| Throttled TTFP, interleaved A/B (n=10) | 3739.6 ms | **3819.7 ms (+80.1 ms, +2.1%)** |

The throttled A/B met its spread gate (0.8.0 1.6%, 0.9.0 1.8%): the cost is real, and about what the bytes predict (69 KiB more to download at Fast 4G's ~9 Mbit/s is ~60 ms, and 220 KiB more code to compile at 4× CPU). The reference A/B didn't meet its 6% gate in two runs: 0.8.0 13.3% / 0.9.0 23.2% (medians 197.1 vs 204.3; load 3.1), then 0.8.0 11.9% / 0.9.0 5.4% (medians 197.0 vs 197.9; load 3.0–3.6, the table's row), each failed by one outlier. Read it as reference TTFP unchanged, not proven to 3%.

`just tycho check`: 203.0 ms vs the 214.8 ms limit (load 25 at its start), 2924.0 KiB vs 3283.0 KiB, no home path in the wasm. PASS.

Where the bytes went, in the GPUI contender (the same framework as Tycho's; `gpui-parts`, brotli scaled to the file): framework code +46.8 KiB, static data +12.5, the module's other sections +0.9, the runtime +0.3; the component −0.4, the data layer +0.2, the host −0.1. Within the framework's code, raw: gpui itself +63 KiB, wgpu-core and wgpu +40 (wgpu 30), taffy +17 (0.15), gpui-base +6.5, gpui-component −14. Nothing to switch off: no feature of 0.9.0's is optional at the pin. The other builds: the GPUI contender 2710.1 → 2770.4 KiB (+60.3), the tall table's bare host 2689.6 → 2749.7 KiB (+60.1); their notes are `apps/observatory/perf/results/2026-11-02-gpui-kit-0.9.0.md` and `components/tall-table/perf/results/2026-11-02-gpui-kit-0.9.0.md`.

## Functional checks

- First-frame probe: the mark followed the presenting GPU task in every `check` run on 0.9.0 (WebGPU). gpui-pre-web 0.3.11 changes the scroll event's name, the platform's OS detection (now `PlatformInfo`, which tells iOS and iPadOS apart), and the Fetch client's executor; its window and `ResizeObserver` path are unchanged.
- Table (`table --reference-only`), against 0.8.0's (not interleaved): first rows 203.7 → 209.9 ms, jump to 90% 81.3 → 82.5 ms, fling p95 16.7 ms both, max 25 → 16.7 ms, 0 frames over 50 ms both, fling work p50 5.9 → 4.7 / p95 7.7 → 6.5 ms, steady work p50 12.3 → 12.1 / p95 15.7 → 15.6 ms, last row matches. PASS. The fling's lower work is worth an interleaved look before anyone credits it to 0.9.0.
- Jump to row, both samples: all jumps and refusals pass; IME, Ctrl/Cmd+V, context-menu Paste with `clipboard-read` lands, without it nothing is pasted (unchanged, as the root CLAUDE.md says); the Mac keys pass. PASS.
- Placeholder vs first frame (light/dark, DPR 2 and 1: 0.0000% of surfaces differ), the slow-font controls, and the theme toggle: PASS.
- Still true on 0.9.0 (source checked): Input binds its Mac shortcuts only under `cfg(target_os = "macos")` (one binding now reads the platform at run time: the secondary Enter, `cmd-enter` on a Mac browser, which Tycho's field doesn't use), so `shared/`'s bootstrap still binds them; gpui-pre-web still `preventDefault`s and drops `dragover`/`drop`; `skeleton.rs`, the title bar, and gpui-kit-assets (the Sun/Moon icons) are unchanged. The default theme changes only its diff colors (`created`, `deleted`, `modified`, which nothing here draws), so `placeholder.ts` needed no change and the observatory's generated `theme.css` changed only its version line.
- 0.9.0's breaking changes don't reach this repo's code beyond the scroll rename: nothing builds a theme struct by literal (`#[non_exhaustive]` now), uses `DisplayMap`, or sleeps on the wall clock under `Animation`; `Window::text_system()`'s `Rc` is read through auto-deref.
- Not run: the full suite (`sample`, `cells`, `errors`, `panel`, `drop`, `csv`), `engine`, `smoke`, the throttled table and jump. Manual pass in real Firefox and Safari not done.

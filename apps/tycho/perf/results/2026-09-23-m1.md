**Machine:** local (Apple M1, macOS 26.6.2). **Toolchain:** nightly-2026-09-20, gpui-kit 0.6.4 (gpui-pre 0.3.5), wasm-bindgen 0.2.121, wasm-opt 133, Vite 8.3.0, Playwright 1.63.0, Chromium 153.0.8010.12 (headless=new).

**Protocol:** `just tycho perf`. A new Chromium per run (cold cache), 1440×900 at DPR 2, median of 10. Reference is unthrottled; throttled adds CPU 4× and DevTools "Fast 4G" (9 Mbps down × 0.9, 165 ms latency). Served by `vite preview` from `web/dist`, brotli quality 11, as production will be. ## Checks

- **Overlay matches the mark:** on every run in every file above, the overlay's drawn TTFP (read from `globalThis.__seizaPerfOverlay`) is the mark rounded to 1 ms, so within 0.5 ms. The overlay reads the mark's own `startTime`.
- **Mark honesty (first-draw probe):** `perf.ts` hooks WebGL2 draw calls and WebGPU `queue.submit`. For each task that does GPU work, it records the last GPU call and the end of that task's microtask checkpoint. Every run passes: the mark lands inside one of those windows (typical window: 0.1–1.3 ms), after the first GPU work. With WebGPU the mark trails the first submit by 12 ms (reference) or 50 ms (throttled). That's the same callback: GPUI first presents an empty frame at 0×0, then resizes and draws the real frame.
- **Budget check, negative controls:** with a fake baseline of 150 ms / 2200 KiB, `perf.ts --check` fails on both ("reference TTFP 174.8 ms is over 165.0 ms", "wasm brotli 2619.5 KiB is over 2530.0 KiB; add a row to perf/budget-notes.md"). With a note row accepting 2620 KiB, it passes. `just tycho check` on the final tree: 175.3 ms vs a 195.0 ms limit, 2618.8 KiB vs a 3012.4 KiB limit. PASS.
- **Overlay UI:** `?perf` shows it at load. Cmd+Shift+P and Ctrl+Shift+P toggle it with no click first; the input mirror has focus. Checked in light and dark themes. Hidden, it clears `__seizaPerfOverlay`.
- **Smoke (`just tycho smoke`, release preview, Auto backend):** PASS in Chromium (305 ms), Firefox (567 ms), and WebKit (336 ms), with no console errors, blank frames, or size mismatches.

## What changed in how we measure

1. **DPR 2 in headless Chromium, unblocked.** An init script deletes `ResizeObserverEntry.prototype.devicePixelContentBoxSize`. gpui-pre-web then takes its Safari path (`contentRect × devicePixelRatio`) and gets a 2880×1800 backing store with sharp 2× text. `perf.ts` asserts the backing size on every run.
2. **The first-frame mark was wrong on WebGPU, and right on WebGL2 only by luck.** M0 marked in a rAF requested from the first render. The first real draw isn't where M0 thought (see LESSONS). The mark is now a microtask queued by the first render with a non-zero viewport, and it's checked against GPU calls on every run.
3. **Preview serves brotli.** `vite preview` served the 9.5 MB wasm uncompressed, which would have made the throttled run measure the wrong download. A preview middleware in `shared-web/` serves quality-11 brotli from a cache that `asset-sizes.ts` fills during the build.

## After code review (same day)

- **Preview server:** it hashed and re-read the 9.5 MB wasm on every request before serving the cached brotli, which added server time that production won't have. Compressed bodies are now prepared at server start and kept in memory (wasm time to first byte: 0.7 ms). **The baseline above was recorded before this fix, so it's slightly conservative.** Re-record it on a quiet machine with `just tycho perf --label m1-baseline --write-baseline`.
- **Preloads are an explicit list** (`seizaViteConfig({ preload: [...] })`), not every `.wasm` and `.ttf`, so M2's DuckDB wasm can't be preloaded before first paint by accident. A listed name missing from the bundle fails the build.
- **Budget check:** `baseline.json` now records the CPU and OS. `--check` skips the TTFP budget, with a warning, when the machine label, CPU or OS differ. Budget notes only count if dated on or after the baseline. Negative controls: a different label skipped TTFP; a note dated before the baseline was ignored (FAIL); a note dated after it was accepted (PASS).
- `perf.ts` fails a run whose wasm arrives without `Content-Encoding: br`. Result files record the OS. The overlay reads back the mark it just set (the last entry). `seiza::perf::set_metric` no longer panics before the overlay is installed.

## What changed

- Tycho's table moved out, unchanged in behavior: `crate/src/table/` became `seiza-table` (`components/table/`): `TableState<D: TableDelegate>` (the entity), `Table<D>` (the element: focus, keys, border), and the delegate (`load_page`, `cancel`) whose pages answer in the component's own `CellValue`s. Columns come in as `ColumnKind`s, not DuckDB type names.
- Its `seiza` calls left: paging comes in as `Paging` (Tycho reads the URL overrides), the panel's window, clock, and visibility as `ActivityOptions`, the probes as `probe_frames` and `probe_cells`. The first-rows and viewport-filled marks are Tycho's now, set from `TableEvent::Filled`, which the table emits while the frame renders; the probes and the scrollbar targets are events too.
- The Parquet source (the page SQL, `QueryResult` as a page, the file summary) became `seiza-duckdb`'s `table` feature; the SQL helpers and `ColumnInfo` moved to its base `sql` module. Tycho's `crate/src/table.rs` holds the source (Parquet or the CSV's chunks) and turns the events into marks and probes.
- App wasm (brotli): **2840.2 KiB**, the same as after part B. Against the pre-M9 build (2838.0, part A's suite): +2.2 KiB, +0.08%. (The first build was 2841.1 KiB; the two code reviews' fixes took 0.9 KiB off.)

## Experiments and controls

- **Code review:** the A/B's out-of-repo path kept three segments, enough to name a home directory (now only the directory's name); a replaced table's late probe could overwrite the shown one's (the workbench now publishes only the shown table's); outside the browser every page read had request id 0 (now a counter); widening k CSV columns rebuilt the columns k times (now once); `quote_identifier` moved to `seiza_duckdb::sql` beside `string_literal`; `format_count` stays private in the component, and Tycho keeps its own. Declined: dropping one of the two scrollbar dedups (the component's keeps events off most frames, `targets::publish`'s covers every target). After the fixes, `check`, `csv` (fixture, formats, supersede), `drop` (supersede), and `cells` were run again and pass.
- **Second code review:** the mark check above (it was only a scratch script); `placeholder --ab` no longer re-summarizes (and throws with `--runs 0`); `close()` cancels without collecting; `open_parquet` sends no metadata query when no keys are asked for. Declined: one `QueryRows::new` signature for both targets (natively there's no engine; the README says so), and an IQR-based spread for the A/B gate (the user kept max − min). After the fixes, `check`, `sample`, and `table --browsers-only` were run again and pass.

- **Where the moved marks land.** Now a committed check: `table --browsers` records every GPU task (`shared-web/perf/`'s `presentingTaskRecorder`) and requires the first-rows mark, and the viewport-filled marks after the jump and after End, to land after the presenting task's last GPU call and before the next task starts (`presentedMark`), with a negative control (a timer's time after the mark must fail). It passes in Chromium, Firefox, and WebKit: 0.16–1.36 ms after the last GPU call, every control caught (`2026-10-13-m9-c-table-browsers.json`). The first look, a scratch script against the pre-M9 build: every GPU task's last GPU call, the end of a microtask queued at its first GPU call, and the start of the next task (a `MessageChannel` message posted at its first GPU call) were recorded; then a sample click, its `tycho:first-rows` and `tycho:viewport-filled`, and End's `tycho:viewport-filled`. 5 runs each, interleaved with the pre-M9 build:
  - pre-M9: 15/15 marks inside the first-GPU-call microtask's window (the test `perf.ts` applies to `gpui:first-frame`), 15/15 before the next task.
  - this build: 0/15 inside that window, **15/15 before the next task**, 0.005–0.045 ms after the window. The table's own call queued the mark during render, before the frame's first GPU call; Tycho's subscriber runs in the effects GPUI flushes after the present, so its microtask comes after the probe's. Both land in the presenting task's microtask checkpoint, before the browser can render anything else, which is what "right after the frame is presented" requires (`components/table/docs/DECISIONS.md`, "Component API").
  - The pre-M9 build publishes `__tychoTargets` (renamed in part A); the script aliased it to `__seizaTargets` to click it.

## Arrow IPC decoder: hand-rolled vs arrow-rs

Same API, same app, release profile + `wasm-opt -Oz` (measured before the review's checked-math change, which added 0.9 KiB to the hand-rolled build):

| Decoder | App wasm raw | App wasm brotli | vs hand-rolled |
|---|---:|---:|---:|
| **Hand-rolled** (`arrow.rs`: flatbuffer walk + ranges into one shared buffer) | 9566.1 KiB | **2630.9 KiB** | — |
| arrow-rs 60 (`arrow-ipc` + `arrow-array` + `arrow-schema`, `default-features = false`) | 10260.1 KiB | 2758.2 KiB | **+127.3 KiB (+4.8%)** |

arrow-rs pulls in `chrono`, `half`, `flatbuffers`, `arrow-data`/`buffer`/`select`, and more, even with default features off. The hand-rolled reader is part of M2's +12.3 KiB total. It reads null, bool, ints, float32/64, decimal128, utf8/binary (and large), date32/64, time32/64, and timestamps. Anything else (list, struct, dictionary, views, …) decodes as an unsupported column showing its type name, and doesn't hide the other columns. The Arrow reader has 9 unit tests against streams written by arrow-rs (a dev-dependency only), including truncation and a bit flip at every byte. The self-test checks it against DuckDB's real output: a row of 17 columns of every shown type decodes to the expected text in all three engines.

## After code review (same day)

The review found eight problems; all are fixed, and every number above was re-measured after the fixes. Cancel during the result-fetch phase was ignored; a worker dying after load would hang its queries; `registerFile(url)` accepted a 404 (and an SPA fallback's `index.html`) and could report a compressed size; the Arrow reader's offset math could wrap on wasm32; decimal 0 with a negative scale showed `000`; DuckDB autoloaded Parquet from extensions.duckdb.org (now off, M3 self-hosts it); the traced perf run counted toward the median; failed requests were invisible to the waterfall check. The M7 note in `PLAN.md` records one left open by choice: a failed engine load is cached until reload.

Verified in the browser: a Parquet function now fails with "exists in the parquet extension" and no external request; `registerFile` rejects a missing URL and reports a present file's true size (9795644 bytes). Not verified: a worker that dies mid-query after load. A memory-exhausting query was optimized into a count and didn't kill the worker. The guard uses the same `error` event the negative controls exercise.

## What changed in how we measure

1. `perf.ts` waits for the engine on every run and checks the waterfall: no request outside the first-paint set (document, entry JS, app wasm, UI font) may start before the first-frame mark. Main-thread requests come from Resource Timing (the marks' clock); the worker's own requests (DuckDB's wasm) come from Playwright's network events. `--trace` saves a Playwright trace (see 4). Traces need `snapshots: true`, or they record no network.
2. **Bug fixed:** `perf.ts` took the first `.wasm` in `dist/assets` as the app's. With DuckDB in the build, that was DuckDB's 5 MB wasm, which would have broken the size budget. It now picks `tycho_bg-*.wasm`.
3. `just tycho engine` (new) runs the Rust self-test (`?selftest`) and the negative controls.
4. After code review: `--trace` records in an extra run that isn't counted (tracing with snapshots slows the page), and the request log includes failed requests (a failed request is now a run problem). `2026-09-23-m2.json` was re-recorded after these changes.
5. `perf.ts` filters `blob:` URLs (the wrapper worker's script), like `data:`.

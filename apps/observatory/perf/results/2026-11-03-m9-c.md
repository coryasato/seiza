## What changed

- **The build:** the TanStack contender builds per level, as the GPUI contender does: `--mode wide` into `web/dist-wide/` at `/observatory/contenders/tall-table/tanstack/wide/`, staged beside the base (`stage.ts` checks its `duckdb/` is the GPUI build's six files). `contenders/level.ts` holds the level helpers both Vite configs use, `__LEVEL__` and `__RANGES__` among them. The GPUI side's config moved onto it, and its rebuilt `dist/` and `dist-wide/` are byte-identical to before.
- **The view at the level:** the table's `Sizes` (`density.ts`, `layout.ts`), the pin's geometry (`pin.ts`), paint (`paint.ts`: Oklab, the ramp's `color-mix`, `FramePaint`), the scene at a stop (`scene.ts`), and the wide view (`wide.ts`, `wide.css`). `main.ts` picks the scenario and stop (`pickScenario`). `theme.css` gains `--chart-1`, the heat ramp's far stop (`#93c5fd` in both themes).
- **The base:** none of the level's code in its bundle (its output holds no `color-mix`, `data-column`, `on-fill`, or wide CSS), but the scenario pick and the layout's `Sizes` stand-in, both shared. The tooltip finds its cell through a `TooltipCells` the wide view passes in; the base passes none and keeps its own lookup.

## The review's fixes

`/code-review high` found ten. Eight are fixed here, one didn't reproduce, and one waits for market watch (a shared level and recipe helper, worth writing once there's a second level).
- **Element Timing on sideways-revealed cells:** fixed. A column that a sideways scroll brings into a drawn row is a new element. Before the fix, one 700 px scroll reported 432 cell paints for rows loaded long ago. Now only the cells created with a row's page carry `elementtiming`: 0 paints after the same scroll, and 230 for ten rows down (the control). `wide.ts` checks it, and with the old rule it fails.
- **The columns' virtualizer hearing vertical scrolls:** fixed. It is now told only of sideways moves. It did flip `isScrolling` on vertical scrolls, but it cost less than the review thought. Counting React's commits per 5 px vertical scroll (a stub devtools hook), the first scroll went 4 → 3 and later ones stayed at 2. The row virtualizer's own start and end commits dominate.
- **The probe going stale on a small sideways scroll:** didn't reproduce, so no code change. The columns' virtualizer's view is the probe's (right of the run's edge), so the cells on screen change only when its range does, and that change renders. `wide.ts` now checks the probe mid-scroll (two moves inside 150 ms, past Latitude's width). It passed with and without a scroll listener added to republish, so the listener was taken out again.
- **A wide scenario the build can't set** (no heat range) fails the load and the replay, as an unknown stop does. Before, it drew the base's table.
- **`wide.ts --side`** starts only the builds it reads (GPUI's wide one always), inside its `try`.
- **The parity's wide block:** servers in a `try`/`finally`, and the rest of a browser's run skipped, as one failure, when the run isn't drawn.
- **The page's dev and preview servers** serve each level's builds under their contenders' bases, as the deploy stages them. Preview answered 200 for both `wide/` bases with the level's assets.
- **One naming rule for `dist-<level>`:** the harness's `distDir` and the page's config read `levelOutDir`.
- **`pinnedStyle`:** its unused parameter and wrong comment are gone.

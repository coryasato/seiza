# M12 part B1: the countries file, the admin table on both sides, and the TanStack contender's ARIA roles and every row (2026-11-09)

Measured on Apple M1, Darwin 25.6.0 arm64, machine `local`: native DuckDB (`@duckdb/node-api` 1.4.5-r.1, `data/`'s lockfile) for the file; the TanStack contender's bundles by its build manifest, brotli 11 (`tanstack-sizes`); Playwright's Chromium, headless, for the cell fixture and the probe. Nothing here is timed: no protocol run.

Raw: `2026-11-09-m12-b1-tanstack-sizes.json`, `-wide.json`, `-market.json`, `-tail.json` (each TanStack level's bytes after the change).

## What changed

- **The data:** `prep.ts --only countries` builds `countries.parquet` from `data/countries.ts`'s rows and `prep-countries.sql`, its three sources pinned (CLDR's tarballs in `prep.ts`, the Wikidata result in `MANIFEST.json`), and writes its `MANIFEST.json` entry: 250 rows, 8,392 bytes, one row group, SHA-256 `a4fa4aa0f38dd6a59132f7667bf31f90525ec57a19c3721c4b0bc10f0f64710f`, byte-identical across two builds; its credit, terms, licenses, and CLDR's notice verbatim.
- **The scenario:** `ADMIN_TABLE` in `contenders/scenarios.ts`, base level, one stop (`all`), in `ALL_SCENARIOS`; both contenders' `pickScenario` load it with `?scenario=admin-table`. Its results are labelled `admin-table` (`resultLabel`).
- **The TanStack contender, every level:** ARIA table semantics (`src/aria.ts`); on the base level, every row of a table of at most one page rendered.
- **The fixtures:** `cells.json` gains `scenarios.admin-table`, its five text columns and 220 cells, and both runners read a text section; `sql.json` gains the file's section.
- **No wasm changed:** nothing in the GPUI contender, `shared/`, or the component's code. Tycho is untouched.

## The admin table on both sides

**The cell fixture** (`cell-fixture`, the GPUI base build, `?scenario=admin-table`): native DuckDB read the 250 rows; 44 picked (each column's longest and shortest text, the first row of each of 33 sets of non-ASCII blocks, every tenth row); the contender drew all 220 cells, every one DuckDB's text to the byte, exact and shown, at DPR 2, with the columns' layout the same at DPR 1: five text columns of 200 px, budget 21. The component's native test (`cell_text`, `cell_controls_fail`) and the TanStack contender's (`the admin-table scenario's cells`, its control) pass; the control, each text's UTF-8 read as Latin-1, fails both, as it must. `view.test.ts` lays out the file's five `VARCHAR` columns and gets the GPUI contender's x, widths, and budgets; its control, a float's width, differs. `sql.json`'s section passes the engine's native test (`sql_fixture`, its controls) and the TanStack contender's.

for level in base wide market tail; do just observatory tanstack-build $level; done
just observatory tanstack-sizes --check            # and --level wide|market|tail
cargo test -p seiza-tall-table cell_ && cargo test -p seiza-duckdb --features tall-table sql_fixture
npm test --workspace @seiza/observatory-tall-table-tanstack

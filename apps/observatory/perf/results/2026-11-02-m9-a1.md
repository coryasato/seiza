Measured on Apple M1, Darwin 25.6.0 arm64, machine `local`, Chromium 153 headless=new, cold (a fresh context per run), median of 10, reference only (no throttling: this sizes the candidates, it isn't a protocol run; the numbers that publish come from part D). Load average 2.7 → 4.0 (the machine in use).

Raw: `2026-11-02-m9-a1-wide-read.json` (the three GHCN candidates), `2026-11-02-m9-a1-wide-read-derived.json` (the asteroid file read through 365 derived columns), `2026-11-02-m9-a1-wide-read-asteroids.json` (the asteroid file's own 11 columns, today's page), all from `spike/wide-read.ts`: DuckDB-Wasm in Tycho's release build (`?bench`), the files streamed by range from a local origin that counts each request and its bytes, the table's page SQL. The decode timings are from a scratch build of `seiza-duckdb`'s Arrow reader alone (native, `opt-level = "z"`) and from `apache-arrow` in Node, on the 4096 page a first pass wrote; indicative only, not wasm.

## What changed

Nothing built: the data's candidates measured, to pick the wide sheet's file and its page SQL.

## The source

NOAA's GHCN-Daily, the 2025 year file (`csv.gz/by_year/2025.csv.gz` in NOAA's Open Data Dissemination bucket, `noaa-ghcn-pds`; byte-identical to NCEI's own copy, SHA-256 `7d1ad5c3…c179`, 166,428,453 B), version 3.35-upd-2026103117, and `ghcnd-stations.txt` (`437ee87f…0dc3`) and `ghcnd-countries.txt`. Fetched 2026-11-02.

- **Terms:** CC0 1.0, for NOAA data disseminated through NODD (the AWS Open Data Registry's entry for `noaa-ghcn`); NOAA asks for attribution, no implied endorsement, and that modified data not be called original or unaltered. NCEI's own record (ISO metadata, `gov.noaa.ncdc:C00861`) asks for its citation: Menne et al. 2012, GHCN-Daily Version 3, doi:10.7289/V5D21VHZ, with the version and access date, and the overview article, doi:10.1175/JTECH-D-11-00103.1.
- **The year file changes:** NOAA appends late reports, so the 2025 file's bytes move until the year settles. The pin is the SHA-256 fetched; a rebuild from a later download differs.
- **Coverage:** 13,706 stations report TMAX in 2025 (TMIN 13,750; TAVG 7,036; PRCP 41,692), the research's ~40 k being every element's. With a quality-clean TMAX on at least 300 days: 10,632 (the file's set); on 330: 10,126; on 360: 7,304. Of the file's 10,632: 6,842 in the US (64%), then Canada 952 and Australia 522; by latitude, 55 north of 70°, 4,332 in 40–50°N, 148 between 0 and 20°N, and 601 south of the equator, Antarctica's 31 at the end. Values: −75.5 °C (Antarctica) to 51.1 °C.

## The candidates

The GHCN file: the 10,632 stations, one row each sorted by latitude (north first), `Station`, `Place` (the state and country for the US and Canada, else the country), `Latitude`, then a column per day (`Jan 1` … `Dec 31`), the high in °C, NULL where the day has no clean value. 368 columns. Written by DuckDB 1.4.5 with ZSTD, its `ROW_GROUP_SIZE` 1024 (DuckDB writes no group under 2,048 rows: 1024 and 2048 gave the same file, 6 groups).

The medians are the reading. Most runs fall within 10% of theirs, but the slowest single run of a page reaches +25–58% in places (the `SMALLINT` file's 4096 page and its repeat, the derived file's 1410048 page), and registration, ~2.4 ms, up to 3× in one run: the machine was in use.

- **Requests:** a page sends 4 ranged GETs (16 KiB, 64 KiB, 256 KiB, 1 MiB: DuckDB-Wasm's read-ahead doubling over the group's span), not one per column chunk; the first page adds 5 (the HEAD and the footer's reads). Reading the whole file is ~29 requests (9, then 4 for each of the 5 other groups), fewer than a base-level session sends in its busiest 10 s (`perf/results/2026-10-21-m6-burst.json`, 125).
- **Arrow:** 3.1 MB a page as `DOUBLE`, as estimated (1,024 × 365 × 8 bytes, and validity). The 64 MiB cache holds ~21 pages and the file is 11, so a session caches it whole and never evicts.
- **The engine dominates a page:** ~115–125 ms a page over the network and ~102 ms with none, against the asteroids' 11 columns' ~11–17 and ~9, on the same engine. Most of the cost is the width: 365 columns computed from the asteroid file's 3 floats cost ~63 ms with no network, cheaper than GHCN's stored columns (~40% less) but ~7× the asteroids' own page. One 2,048-row group a page decodes twice the rows the page needs; the one-group file decodes less a page (53 ms) but fetches the whole file (5.6 MB) for the first page.
- **Each side's decode is ~1 ms:** `seiza-duckdb`'s reader 0.60 ms a page natively (a copy of the bytes included; 0.36 for `SMALLINT`), `apache-arrow`'s `tableFromIPC` and the columns 1.39 ms (its vectors are views). Reading a screen's 2,400 values: 0.11 ms in JS, 0.83 ms in Rust with each formatted by `{:?}`. Against the engine's ~115 ms, the decode is noise: time to data on this file reads DuckDB, the same on both sides.

## The pick

GHCN, the days as `DOUBLE`, DuckDB's 2,048-row groups. The page SQL is the table's unchanged (`SELECT * EXCLUDE (file_row_number) …`, a `sql.json` case for the new file name): `DOUBLE` costs 6% more bytes than `SMALLINT` and keeps the cells the fixtures' float kind with no cast in the SQL, while `SMALLINT` would draw tenths as integers ("-123") or need a page query of the host's own. The 2,048-row groups over one: the first page waits for 1.6 MB, not 5.6 (on Fast 4G, seconds), for ~55–65 ms more engine time on each later page. The derived columns: cheaper in the engine, but no bytes saved over today's file and a heat map of noise, against data a visitor reads at a glance (`docs/DECISIONS.md`, "Scenarios", 2026-10-30).

## Experiments and controls

- **The probe's server:** a first pass read the whole file for every ranged request; streaming only the range (this run) cut the asteroid file's first page from ~98 to 68 ms and the derived one's from ~200 to 171, the GHCN file's by ~4%. The first pass's numbers aren't recorded.

## Reproducing it

The candidate files were built in a scratch directory from the downloads above; part B's `prep` builds the picked one. Then:

```sh
just tycho build
node apps/observatory/spike/wide-read.ts --dir <dir> --runs 10 --label m9-a1-wide-read ghcn-2025-tmax-double.parquet ghcn-2025-tmax-int16.parquet ghcn-2025-tmax-double-one-group.parquet
node apps/observatory/spike/wide-read.ts --dir <dir> --runs 10 --rows 1567523 --derived --label m9-a1-wide-read-derived asteroids.parquet
node apps/observatory/spike/wide-read.ts --dir <dir> --runs 10 --rows 1567523 --label m9-a1-wide-read-asteroids asteroids.parquet
```

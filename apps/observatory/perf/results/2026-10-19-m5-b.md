# M5 part B: the readouts (2026-10-19)

The comparison's numbers on the page: the cold medians from M4's runs, and this tab's live readings of the shown contender. Measured on Apple M1, Darwin 25.6.0 arm64, machine `local`, Playwright's Chromium headless=new, 1440×900 at DPR 2. Load average 3.3–5.0 throughout (the user's browsers open), so first-paint numbers here carry that noise; the A/B below is interleaved for that reason.

Raw: `raw/2026-10-19-m5-b/` (gitignored): `numbers-light-reference.png`, `numbers-dark-throttled.png`, `numbers-phone.png`, after a GPUI scroll, a flip, and a TanStack scroll.

## What changed

- **The page's numbers** (`web/src/numbers.ts`, `readouts.ts`, `live.ts`, `web/cold.ts`): the Reference | Throttled switch, four headline cards (first usable, time to data, the fling's late main-thread frames, page memory), each with GPUI and TanStack's cold medians and a "This tab, live" row, and the input-to-response chart (key, track press, wheel; → new position and → rows real), cold. The section is a chunk of its own, rendered after first paint.
- **The cold numbers come from `perf/results/` at build time**, through `shared-web/scripts/results.ts`: `report.ts`'s resolver, moved out unchanged (`report --check` still reads every app's docs as current). Tycho: no change to any bundle.
- **The metrics module** gains `liveReadings`, `lateFrames`, `refreshPeriod`, and `memoryOf`. `underLoad` now counts late frames through `lateFrames` (same threshold, 1.5 × 16.7 ms) and `metric-cost.ts` splits memory through `memoryOf` (the same rule as before), so both compute one way with the page. No contender changed.
- **Which cards:** the design canvas's mock-up had "wheel → rows real" and "per-frame work p95" cards; neither can be read in a tab (both are the trace's), so they became time to data and page memory. The wheel stays in the chart. Reasons and rejected sources: `docs/DECISIONS.md`, "Page".

## Experiments and controls

- **Prerendering the numbers cost first paint.** Interleaved, 12 cold runs each (one per variant per round, order alternating), first paint at `/observatory/tall-table/`, load ~4:

  | Variant | HTML | First paint, median (p25–p75) |
  |---|---|---|
  | The slot empty (control, as HEAD) | 13.3 KB | 62.8 ms (56.3–68.9) |
  | The numbers prerendered | 30.3 KB | 81.8 ms (75.6–90.0) |
  | Prerendered, `content-visibility: auto` | 30.4 KB | 70.5 ms (56.6–77.9) |

  So the numbers render after first paint instead (root rule 1); `page --check` then read 78.6 ms. With them prerendered the check had read 88.6 and 89.9 ms, over the 85 ms limit.
- **The headless shell can't read the page's memory or time the GPUI side.** A first scratch run used Playwright's default `chromium-headless-shell`: `measureUserAgentSpecificMemory` threw `SecurityError` on every page, isolated or not, and GPUI's open → filled took ~1050 ms in its frame (TanStack's 238 ms). With `channel: 'chromium'` (headless=new, as every metric script runs) memory worked and GPUI's open → filled was 213 ms. The page's own code wasn't the cause.
- **The metrics module was briefly requested before first paint:** the live store's subscription loaded it during hydration. `page --check`'s per-run check caught it (10 of 10 runs); the subscription now waits for `afterFirstPaint`.
- **The phone's Escape check failed once** and passed on the next two runs, with nothing in the sidebar changed: focus can move into the frame as it loads, and the page's listener then never hears the key. Not chased this part.

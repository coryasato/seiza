# M10 part A2: market watch on both sides, the stops, and the measure (2026-11-04)

Measured on Apple M1, Darwin 25.6.0 arm64, machine `local`, Chromium 153 headless=new, 1440×900 at DPR 2, cold (a fresh browser per run), median of 3, reference and throttled (CPU 4×, Fast 4G): a spike that sizes the scenario, not a protocol run (the numbers that publish come from part D, on the improved component). Load average 2.8–3.5 over the corrected runs (9.5 → 2.9 over the first GPUI matrix).

**Read the corrected files only for TanStack** (see "After the code reviews"): `2026-11-04-m10-a2-market-flash.json` (both profiles, 100 to 50k), `-flash-{none,bg,css,waapi}.json` (the flash's three ways and none, at 5k), `-market-hold-frame.json` (Shown in's control), `-market-gpui-workload-bg.json` (TanStack at the bare host's flash workload). **GPUI's** are `-market.json` (1k to 50k), `-market-low.json` (100, 500), and `-market-noflash.json`; its side ran the bare host, untouched by the fixes. `-market-hold.json` is "keeps up"'s control. Superseded, TanStack's flash never running or drawn another way: TanStack's rows in `-market.json`, `-market-low.json`, `-market-noflash.json`, and all of `-market-review.json`, `-market-hold-review.json`, `-market-gpui-workload.json`. All from `spike/market-run.ts`.

## The sides

- **TanStack** (`spike/market.html`, `src/market.ts`): A1's feed worker into an idiomatic store (a new row object per tick, a new array per batch), React and TanStack Virtual over the 50 instruments, the canvas's 12 columns (fixed decimals, a sign, `%`, grouping by `Intl.NumberFormat`), rendering once a frame (a rAF after a batch), rows memoized by their object. Last, Bid, and Ask flash when their value changes from the one drawn, 30% fading linearly over 400 ms; Change and Change % by sign, a zero in the foreground. ~78 flash animations run at once at 1k (checked: `document.getAnimations()`).
- **GPUI:** the tall table's bare host built `live,custom-cells`, `?shape=narrow&live=<rate>&flash`: its own seeded feed over the visible rows (an update changes a row's every float), answered from memory, every float column flashing for 1 s, 11 columns. Its flash can't be set from the URL, so TanStack was also run at GPUI's workload (every numeric column, 1 s; below). The store's fold it leaves out costs ~2 ms a second at 50k (A1).
- **Read the same way:** each frame that showed new values (TanStack's commits that drew a newer batch; GPUI's `tall-table:refreshed`), and a batch's start (the worker's post; the host's feed tick) to the presentation of the first frame that showed it (the trace's `AnimationFrame::Presentation` for the frame holding the commit or mark: Shown in). The throttle's control, a fixed busy loop on each page before the window: 116–122 ms reference, 478–492 ms throttled (4.0–4.1×) on both sides, so these pages' throttled times are real (A1's idle page wasn't).

- **The fast device: both keep up at every rate,** no late frames. Their main thread is close: TanStack 259–462 ms a second, growing with the rate; GPUI 343–382, flat.
- **The slow device: TanStack keeps up to 1k and falls behind from 5k; GPUI doesn't keep up at any rate.** GPUI's main thread is saturated (994 ms a second) and 11–21% of its frames are late; its "100%" is the bare host's feed starving on the same thread (its batches fall from ~35 to ~12 a second), so the coalescing hides in the feed (the contenders' feed is a worker's, where it would show).
- **The flash is the cost on both sides, paid differently.** Throttled at 5k with no flash, both kept up (TanStack 98.3%, 0% late; GPUI 0% late, 660 ms a second). With it, GPUI redraws every visible cell every frame while any flash fades (~17–22 ms a frame throttled, whatever the rate or how many cells flash); the DOM runs an animation per flashing cell, so its cost grows with them. **At GPUI's workload** (every numeric column flashing for 1 s), TanStack fell far behind throttled: keeps up 51.1% at 1k and 30.7% at 5k, 97–100% of frames late (reference: 100%, busy 470 and 442 ms a second); GPUI under that workload had 11–21% late. So with as many flashing cells, GPUI is the stronger on the slow device; with the scenario's three columns, the DOM is, up to 1k.
- **The rate matters up to ~5k, not past it:** at 1k ~17 ticks a frame change ~14 of the 50 rows, at 5k ~83 change nearly all of them. TanStack's work grows from 100 to 5k (throttled busy 293 → 535 → 697 → 996 ms a second) and keeps growing a little past it at the reference (386 → 435 → 462) as its collections do (32 → 39 → 48 in 10 s); GPUI's is flat (its flash redraws every frame at any rate).
- **Collections:** TanStack 8–48 in 10 s, each ≤ 3.3 ms at the reference and ≤ 6.5 ms throttled; GPUI 2–4 (its JS glue's). Mechanism B is visible as counts; whether one lands in a late frame is part D's reading.

## The two controls

- **"Keeps up"'s control** (`-market-hold.json`, TanStack committing every other frame, its batches coalesced): 100% → 55.2% at 5k and 55.4% at 20k. The measure sees a side falling behind the feed.
- **Shown in's control fails on the DOM side** (`-market-hold-frame.json`, TanStack committing every frame's batches a frame later): Shown in 75.2 → 75.6 ms p50, where a frame later should read ~16.7 ms more; keeps up 100% both, as it should. And TanStack's Shown in reads 44–75 ms at the reference, run to run, above its throttled 40–42 ms at the lower rates, and 32 ms with no flash. With ~80 CSS animations running, the trace's presentation for the frame holding a commit doesn't follow the commit; the reading isn't Shown in. GPUI's (~24 ms reference) wasn't controlled. **Shown in needs another method before part D** (Element Timing on the changed text, which the DOM side's other marks already use, or the compositor's frame for the commit's paint), with this control passing on both sides.

## Experiments and controls

- **The measure against the display's frames alone** (the first try): TanStack 85.6%, GPUI 58.8% at 5k, both showing every batch: it read each feed's cadence, not the UI. Replaced by the batches' share.
- **A per-cell custom property in one keyframes pair** (`var(--flash-color)` set by a class, a review's tidying of the four pairs): at 5k busy 448 ms a second at the reference, keeps up 57.7% throttled (86% late), against 388 and 77.8% (56%) with the color in each pair's keyframes. The four pairs stay.
- **The busy loop** is each page's throttle control (above).

## After the code reviews

The first matrix's TanStack never flashed: in the default `bg` way no overlay is rendered, and the effect returned early when the overlay was missing, so every `bg` row read as no flash (busy 275 ms a second and 98.7% keeping up throttled at 5k, the no-flash numbers). Found when a review's fixes changed the numbers; every TanStack row was measured again with the flash running (`document.getAnimations()` checked). Also fixed: `?hold=1` committed every other frame (that run is now "keeps up"'s control, and a frame-late commit is Shown in's), the virtualizer's own renders counted as shown frames, a window with no batch divided by zero, the spike drew the superseded colors, GPUI's mark names went unchecked against the host's, and `--flash` changed TanStack alone without saying so (it now refuses GPUI).

## Reproducing it

```sh
just tall-table build live,custom-cells
node apps/observatory/spike/market-run.ts --sides gpui --label m10-a2-market            # GPUI, 1k–50k
node apps/observatory/spike/market-run.ts --sides gpui --rates 100,500 --label m10-a2-market-low
node apps/observatory/spike/market-run.ts --sides tanstack --rates 100,500,1000,5000,20000,50000 --label m10-a2-market-flash
node apps/observatory/spike/market-run.ts --no-build --sides tanstack --rates 5000 --mode bg|css|waapi --label m10-a2-flash-<mode>
node apps/observatory/spike/market-run.ts --no-build --sides tanstack --rates 5000 --flash 0 --label m10-a2-flash-none
node apps/observatory/spike/market-run.ts --no-build --sides tanstack --rates 5000 --profiles reference --hold --label m10-a2-market-hold-frame
node apps/observatory/spike/market-run.ts --no-build --sides tanstack --rates 1000,5000 --flash 1000 --flash-all --label m10-a2-market-gpui-workload-bg
```

# Dependency upgrade: gpui-kit 0.9.0 → 0.9.1 (2026-11-10)

Measured on Apple M1, Darwin 25.6.0, machine `local`, by `just observatory lint` and `gpui-parts`. What changed and why: `apps/tycho/perf/results/2026-11-10-gpui-kit-0.9.1.md` (the lock, gpui-pre 0.3.12, the source checks, the A/Bs).

- The GPUI contender's wasm (base level): **2771.1 → 2773.5 KiB brotli (+2.4 KiB, +0.1%)**, raw 9907.2 → 9875.3 KiB, against a 0.9.0 build of the same tree with the bump stashed. By part (`gpui-parts`, both builds: `2026-11-10-gpui-kit-0.9.0-parts.json`, `2026-11-10-gpui-kit-0.9.1-parts.json`): framework code +3.0 KiB (raw −17.6), static data +0.3, runtime −0.6, the data layer −0.1; the component and the host flat. No code changes. The TanStack contender and the page don't build gpui-kit.
- `theme.css` (the TanStack contender's, generated from gpui-kit's resolved default theme): only its version line changed; 0.9.1's theme adds `window.radius` (0 by default), which it doesn't take.
- `just observatory lint`: PASS (every level's clippy, wasm32 and native).
- The published comparisons stay labelled with gpui-kit 0.9.0, the version they were measured with (each results file's `versions`), and no scenario is re-measured for this bump. The contender's code is unchanged, but its input path isn't: gpui-pre 0.3.12 resets the cursor on every mouse and scroll event, a write to `document.body.style.cursor` each time on the web (`apps/tycho/perf/results/2026-11-10-gpui-kit-0.9.1.md`), so GPUI's fling, scroll, and response numbers may differ on 0.9.1. Whether to re-measure or keep the label is an open question in `PLAN.md`.
- Not run: `check` (the contender's TTFP and wasm budgets on 0.9.1: M12's part E runs it before its deploy, `PLAN.md`), the cold suites, `page --check`.

## Reproducing it

```sh
just observatory theme-css && just observatory lint
just observatory gpui-build
node apps/observatory/perf/gpui-parts.ts --label gpui-kit-0.9.1-parts   # and with the bump stashed, as -0.9.0-parts
```

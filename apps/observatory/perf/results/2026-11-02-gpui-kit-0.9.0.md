# Dependency upgrade: gpui-kit 0.8.0 → 0.9.0 (2026-11-02)

Measured on Apple M1, Darwin 25.6.0, machine `local`, by `just observatory check` (no JSON written: its parts run without `--label`) and `gpui-parts`. Load average ~3–4 through it, with the user's browsers open. What changed and why: `apps/tycho/perf/results/2026-11-02-gpui-kit-0.9.0.md` (the lock, gpui-pre 0.3.11, the scroll rename, the source checks, the nightly).

## What changed

- The GPUI contender's wasm: **2710.1 → 2770.4 KiB brotli (+60.3 KiB, +2.2%)**, against a 0.8.0 build from a worktree. By part (`gpui-parts`, both builds: `2026-11-02-gpui-kit-0.8.0-parts.json`, `2026-11-02-gpui-kit-0.9.0-parts.json`): framework code +46.8 KiB (raw: gpui +63, wgpu 30 +40, taffy 0.15 +17, gpui-base +6.5, gpui-component −14), static data +12.5, other sections +0.9, runtime +0.3; the component, the data layer, and the host flat. No code changes in the host; the table's are the scroll rename. The TanStack contender and the page don't build gpui-kit.
- `theme.css` (the TanStack contender's, generated from gpui-kit's resolved default theme): only its version line changed; 0.9.0's theme changes only the diff colors, which it doesn't take.

Everything else in `check` passed: `sizes --check` (the panel-leak and home-path checks), the placeholder against the first frame (light/dark, DPR 2 and 1), `reach`, `engine-files --controls`, `tanstack-view --gpui` (the GPUI contender's column widths unchanged), `tanstack-contract`, `tanstack-parity` (in Chromium, Firefox, WebKit, the GPUI contender's keys the same), `page --check`, and the fixtures (paging, SQL, the TanStack run, `cell-fixture --check`: 254 cells, budgets unchanged).

Not run: the per-use metrics (`metric …`), `readout-cost`, the throttled cold run. The published comparison's numbers are still the earlier pins'; Tycho's interleaved throttled A/B puts 0.9.0's first frame ~80 ms later on Fast 4G (+2.1%), which the GPUI side's first-pixel footnote will show at its next cold run.

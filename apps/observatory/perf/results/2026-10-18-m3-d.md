# M3 part D: the TanStack contender's contract and first screen (2026-10-18)

What this part added: the contract, the prerendered first screen (with first usable confirmed by a probe), the JS budgets, and where plain TanStack stops. Apple M1, Darwin 25.6.0 arm64, machine `local`, Node 26.0.0; Playwright 1.63.0's Chromium (headless=new), 1440×900 at DPR 2; Firefox and WebKit (headless) for plain TanStack and the view's and parity's checks. Load average 2.4–2.9 (the user's machine in use). Nothing here is a timing comparison between the sides; those are M4's.

Raw:
- `2026-10-18-m3-d-contract.json` (`just observatory tanstack-contract --label m3-d-contract`): the marks, the probe and its control, the cells' paints after each filled mark, state, targets, replay, relay.
- `2026-10-18-m3-d-tanstack-sizes.json` (`just observatory tanstack-sizes --label m3-d-tanstack-sizes --write-baseline`): the JS by chunk, brotli.
- `2026-10-18-m3-d-plain.json` (`just observatory spike --only plain --label m3-d`): plain TanStack in Chromium, Firefox, and WebKit.

## What changed

- **`src/contract.ts`** (new): `TableContract` marks `contender:filled` after each of the table's commits, and after each move into rows already drawn, whenever the visible rows become all real. With `?measure` it writes `__contender.state` and the targets in the next animation frame. It also drives the replay's `jump` and `fling`; `replay` reopens through `main.ts`.
- **`src/main.ts`**: `hydrateRoot` over the prerendered first screen. `contender:first-pixels` is the status line's Element Timing paint, with FCP where there's no Element Timing; `usable` is the hydration commit, and `open` is set as the file starts opening. The engine starts once both the paint entry and the commit have happened (`docs/DECISIONS.md`). `publishContender('tanstack', …)`.
- **`src/view.ts`**: `FIRST_SCREEN`; `App` calls `hydrated` in its first commit; with `?measure`, `ProbeKey` takes the first key for the probe (`contender:input`). Placeholder cells are keyed apart from loaded ones, and with `?measure` loaded cells get `elementtiming="row:<row>"`. Nothing reads `location` at import (the build renders the view in Node).
- **`src/scroll.ts`**: `step` (the replay's 1:1 scroll, source `replay`) and `scrollbar` (the track and the estimated thumb, for the targets).
- **`vite.config.ts`**: the `prerender` plugin. **`contenders/contract.ts`**: `MARKS.input`.
- **`perf/tanstack-contract.ts`** and **`perf/tanstack-sizes.ts`** (new, both in `check`); `perf/budgets.json`'s two TanStack JS budgets and `perf/baseline.json`'s `tanstackJsBrotliKiB`. `cold.ts --write-baseline` now keeps the baseline's other entries. The spike gains `--only plain`.
- **Sizes (brotli, `tanstack-sizes`'s method on both builds):** first-paint JS 70.5 → 72.1 KiB (the contract, hydration, the probe); HTML 0.3 KiB with the first screen; the data layer (1.8 + 1.0 + Arrow 31.9 = 34.7 KiB), the engine chunk (7.5), and CSS (1.0) unchanged. The GPUI contender is unchanged, and no other app builds the TanStack contender.

## Review fixes

A code review of this part, before commit, found these; all fixed, and the checks above rerun on the fixed build:

- **The probe key re-rendered the whole table on every key** under `?measure`, which would have inflated measured key latency. It's now `ProbeKey`, a component of its own that takes only the first key (first-paint JS 71.9 → 72.0 KiB).
- **A replaced table's reads and timers kept running.** Its paging is now closed as the next open starts, and again when the table unmounts.
- **A failed Parquet extension load stayed cached**, so every later open failed. A failed start is now retried.
- **The replay's `open()` could race the first open.** Opens now run one after another, after the hydration commit.
- **The first-pixels observer outlived a first screen that never painted** (a hidden page). It's disconnected once the table opens.
- **The contract's scroll subscription had narrower deps than the model it subscribes to.** They now match.
- **The dev server prerendered from the view as of its start.** It now loads the view through `ssrLoadModule` on each request.
- **The TanStack baseline carries its own date and machine.**

A second review, after those fixes, found these; all fixed, with the checks above rerun on that build:

- **The replay's `open()` could resolve on an earlier open's table.** It now waits for the table of the open it started (each `TableContract` knows its open's number).
- **The hydration check took the parsed node at `DOMContentLoaded`, after the module had run.** It now takes it at `readyState` 'interactive', before any module script.
- **A reopen closed the old table's paging while the table was still on screen.** The "Opening…" screen now commits synchronously (`flushSync`) before the close, and `close` is idempotent.
- **`report.ts` dated a baseline entry by the file's top-level date.** It now uses the nearest `date` on the entry's path. This is a shared-web change; every app's report is unchanged.
- **Every status line carried `elementtiming="first-screen"`,** a reopen's too. Only `FIRST_SCREEN` carries it now.
- **First pixels took Element Timing's `renderTime` even when 0.** It falls back to `startTime`, as shared-web's placeholder does.
- **A rendered move scanned the visible rows twice.** A move checks once now (`moveStarted`, `moveEnded`).
- **`tanstack-sizes` parsed imports from the minified chunks.** It reads Vite's build manifest (`build.manifest`, `dist/.vite/manifest.json`) instead.
- **The engine's retry handler** is attached once, where the engine starts. **The scrollbar's strip** is one helper, shared by the press test and the targets.

First-paint JS after both rounds: 72.1 KiB. One parity run failed once, after this round, on Firefox's loading-row tooltip: it showed row 3087's name over row 50250. Three Firefox reruns passed, and none of these changes touch the tooltip, so it's recorded as a flake to watch.

Not changed: the probe confirms the commit, not a presented frame. The trace reading of first usable is M4's metrics module.

## What surprised us

- **Hydration can commit before the HTML's first paint.** In 3 of the 6 runs whose marks were logged, React's commit came 1.6–7.2 ms before `first-paint`; in the other three it came 6.1–10.8 ms after. So "first usable before first pixels" happens on the DOM side, and the engine's start has to wait for both.
- **Element Timing reports a cell only at its first paint, and buffers 150 entries.** A placeholder turned real in place is never reported, so the cells are now keyed by state. A screen of cells is ~330 entries, so a reader observes from an init script and waits for late entries: they arrive in an observer's task after the paint, and one run read them too early.
- **The replay's fling read as a thumb drag.** A 261,254 px step per frame, with no wheel behind it, is the model's definition of the thumb. The fix was an input source of its own, `replay`.
- **Firefox's plain TanStack isn't stuck at the top; it crawls.** Its spacer lays out at 0 px, but the absolutely positioned rows still overflow the scroller, so each End reaches the edge of the rows last drawn.

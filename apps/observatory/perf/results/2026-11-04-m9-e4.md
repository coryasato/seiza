# M9 part E4: shipped (2026-11-04)

Measured on Apple M1, Darwin 25.6.0 arm64, machine `local`, Chromium 153 headless=new, 1440×900 at DPR 2, unthrottled, one run per use (a peak, not a timing: `perf/burst.ts`). No new measurement of either contender: the README shows part D's numbers (`2026-11-03-m9-d.md`) through `report`.

Raw: `2026-11-04-m9-e4-burst.json` (the requests one visitor sends in the busiest 10 s, five uses, counted at the server), `2026-11-04-m9-e4-burst-fix.json` (`wide` and `both` again, after the review's fixes).

## What changed

- **The README** has a section per scenario. Big file's numbers are unchanged. The wide sheet's are two generated tables: at each stop, the frames that drew new cells and the work per frame (p95) in the scroll down, sideways, and the fast fling, both devices; and, at the default stop, usable, first pixels, data, the five responses, reach, CPU, page bytes, and memory. Its prose (where each side wins, even, neither on a slow device) is checked against those tables. Its "Data credits" names NOAA's GHCN-Daily with its version, CC0 1.0, the cut, no endorsement, and NOAA's citation.
- **`report` takes named README sections:** a metric's `show: ["readme:<name>"]` renders between `<!-- report:readme:<name>:start/end -->`, each with its own sources line (`shared-web/scripts/report.ts`). Tycho's README is unchanged (`report --check` passes for both apps). All 73 of the wide sheet's metrics are shown; their reference labels end in ", reference", as Big file's do.
- **`burst` covers the wide sheet:** `wide` (its route, each side flung and jumped at the stop it opens at, then the dial through the other three with a fling at each: each side at every stop), `both` (Big file's GPUI flung, the sidebar's link to the wide sheet, its GPUI flung: both files inside one window), and `wide-reloads` (five reloads of its route), beside `visit` and `reloads`.

## After the code review

`/code-review medium` found eight issues. All are fixed:
- **`wide` didn't put TanStack at every stop.** A flip keeps the stop, so TanStack opened at ~940, where GPUI's dial ended, and its loop clicked ~940 again last. That click changes nothing, so no frame was made and the wait for its fill could only time out or catch a late mark. The dial now goes through every stop other than the one shown. Re-run (`-fix`): the same 66 in its busiest 10 s and 172 in all; the table above has the re-run's rows.
- **`both` clicked the first link whose name held "Wide sheet".** It now clicks the sidebar's sub-item for the route. The first scoping by the scenario-link attribute alone matched the description's link too and failed strict mode. Re-run: 59 in its busiest 10 s, against the first run's 54.
- **The README's work claim** held for the scroll down and the fast fling, not sideways: on a fast device past the first stop, TanStack's sideways p95 is lower (at ~710, 12.8 / 11.6 ms). The README now shows the sideways and fling work rows too, and says so.
- **`report`** writes each file once for all its sections (a stale README was named once per section in `--check`'s error), and a section is typed as a metric's `show` value, with no cast.
- **LESSONS and DECISIONS** no longer copy this note's numbers.

The peak is unchanged: `wide-reloads`' 141, untouched by the fixes.

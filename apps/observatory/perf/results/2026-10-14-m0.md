# M0: Groundwork: the app, its data file, and static hosting (2026-10-14)

Measured on Apple M1, Darwin 25.6.0 arm64, machine `local`, Chromium 153 headless, against production (seiza.io and tycho.seiza.io, Cloudflare's SJC location). Data reads: median of 10 runs per side, a cold browser context per run, sides alternating; the edge cache warm (the cold first read is measured on its own, below). No page and no contender yet, so no TTFP or bundle budget applies.

Raw: [`2026-10-14-m0-b-data-read.json`](2026-10-14-m0-b-data-read.json) (`just observatory data-read`). Part A's engine runs are Tycho's: [`../../../tycho/perf/results/2026-10-14-observatory-m0-a-engine-review.json`](../../../tycho/perf/results/2026-10-14-observatory-m0-a-engine-review.json). The production checks (`just observatory worker-check`) print rather than write; their output is quoted here.

## What changed

- `@seiza/duckdb` takes `extensionDir`. Tycho's app wasm byte-identical; its engine chunk +206 B raw, +187 B brotli, after first paint.
- The observatory's data file: `data/asteroids.parquet`, 22,812,292 B (21.76 MiB), 1,567,523 rows, 52 row groups of 30,720, 11 columns (spkid BIGINT; full_name, class VARCHAR; neo, pha BOOLEAN; H, diameter, albedo, a, e DOUBLE; first_obs DATE), SHA-256 `805f18fa…` in `data/MANIFEST.json`. Rebuilt twice: identical bytes. Every kept value checked against the source, row for row.
- Production: Worker `observatory` on the apex `seiza.io` (a custom domain), static assets plus a script that runs first for `/observatory/data/*` only.

## Static assets and ranges

Served as a plain static asset (no script), the file failed the range checks:

| Request | Answer |
|---|---|
| `HEAD`, `Range: bytes=0-` | 200, no `Content-Range` |
| `GET`, `Range: bytes=0-0` | 200, all 22,812,292 B |
| 8 closed ranges | 200, all 22,812,292 B each |
| Not recompressed (offered gzip, br, zstd) | yes: no `Content-Encoding`, raw bytes, SHA-256 matches |
| COOP / COEP / CORP, `no-transform` | present |

`cf-cache-status` was MISS on every request, ranged or not, and stayed MISS with `Cache-Control: public, max-age=3600`, with `Content-Type: application/vnd.apache.parquet`, with plain GETs before the ranged ones, and for a copy named `.bin` (an extension Cloudflare caches by default). Static assets don't pass through the zone's cache, which is where Cloudflare answers ranges.

With the Worker (each request answered by `caches.default.match` from the whole file, put once per location; `worker/src/index.ts`), `just observatory worker-check`:

```
HEAD: 200, Content-Length 22812292, Accept-Ranges bytes, Content-Type application/vnd.apache.parquet, Cache-Control no-cache, no-transform
HEAD bytes=0-: 206, Content-Range bytes 0-22812291/22812292
GET bytes=0-0: 206, Content-Range bytes 0-0/22812292, 1 B on the wire
closed ranges: 8 checked
GET: 200, 22812292 B on the wire, sha256 805f18fafcd1…
PASS
```

The first request at a location under a new key (a deploy with a throwaway `DATA_SHA256`, n = 1, SJC): **2.27 s** to the first byte of a `bytes=0-0` answer, the whole file read from static assets and put in the cache. The next three: 58–79 ms.

## The first page, next to Tycho's R2 path

DuckDB-Wasm (Tycho's release build, routed in by Playwright under each data file's own origin) through `registerFile`, then the table's page SQL. Both files share the rows; Tycho's has 18 columns, this one 11. The first page's digest over the shared columns matched on all 20 runs, and `count(*)` was 1,567,523 on both.

| Median of 10 | Observatory (static asset + Worker + edge cache) | Tycho (Worker + R2 + its edge cache) |
|---|---|---|
| `registerFile` (HEAD + probe) | 63.6 ms | 79.3 ms |
| First page (rows 0–1023) | 390.4 ms, 1,453,320 B read | 474.9 ms, 1,483,463 B read |
| Page at 90% | 115.5 ms, 344,064 B read | 195.3 ms, 1,392,640 B read |

The 90% page reads a quarter of the bytes here (its row group holds 11 columns, not 18); the first page reads about the same on both, DuckDB-Wasm's first readahead.

## Experiments and controls

- The five static-asset variants above, each failing the same way.
- Local `wrangler dev` (4.148.0) with the static asset: also no ranges, and it gzips the Parquet. Not a stand-in for production here.

## Reproducing it

```sh
just tycho data && just observatory data

just tycho build && just observatory data-read --label m0-b-data-read
```

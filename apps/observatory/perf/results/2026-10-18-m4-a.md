# M4 part A: one metrics module and the scripts (2026-10-18)

What this part added: the metrics module, the GPUI contender's probe key, and one script per metric that runs on either bare contender page. Measured on Apple M1, Darwin 25.6.0 arm64, machine `local`, Playwright 1.63.0's Chromium headless=new, 1440×900 at DPR 2, reference and throttled. Load average 3.1 → 2.1 (the user's machine in use). **Each script ran once per contender and profile, to show it works: these are not the comparison's numbers.** Part B runs them cold, median of 10.

Raw:
- `2026-10-18-m4-a-smoke-<metric>.json` (`just observatory metric <metric> --runs 1 --label m4-a-smoke-<metric>`), for `usable`, `data`, `response`, `fling`, `reach`, `cost`: one run per contender and profile.
- `2026-10-18-m4-a-before-sizes.json`, `2026-10-18-m4-a-sizes.json` (`just observatory sizes --label …`): the GPUI contender's wasm without and with the probe key.

## What changed

- **`metrics/metrics.ts`** (new): every metric, computed from the marks, `__contender.state` as each frame starts, the DOM's cell paints, and Chromium's trace. It holds no Playwright, Node, or DOM code at import. Contents: `firstUsable` and `probePresented`/`probeLatency`, `timeToData` and `rowsPainted`, `readInputs` (input to visible response, its guard, → rows real), `frameWork` (per-frame work and main-thread CPU), `underLoad` (the fling), `reach`, and the protocol's constants (`PROBE_KEY`, `PROBE_MS`, `FLING_FRAMES` and `flingStep`, `LATE_FRAME_MS`, the trace categories). The trace reading is ported from `spike/latency.ts`.
- **The fling profile** moved from `contenders/contract.ts` to the module; both contenders' replay `fling` takes `flingStep` from it. Behavior is unchanged.
- **The GPUI contender's probe key** (`contract.rs`, `host.rs`): with `?measure`, `intercept_keystrokes` takes the first key the window gets and notifies the host, whose next render sets `contender:input` with `mark_after_current_task`. Keys count only once `gpui:first-frame` is set, as the DOM side listens only from its hydration commit. Wasm: 9703.5 → 9705.2 KiB raw (+1.7), brotli 2697.3 → 2695.7 KiB (within brotli's noise). Only the observatory builds this crate, so Tycho is unaffected.
- **`perf/contender.ts`** and **`perf/metric-{usable,data,response,fling,reach,cost}.ts`** (new), with `just observatory metric <name>`. **`perf/reach.ts`** checks the probe key: after usable, its control, and none without `?measure`. **`perf/tanstack-contract.ts`** presses the shared `PROBE_KEY`.

## Review fixes

A code review of this part, before commit, found these. All are fixed, and usable, response, fling, cost, and `reach` were rerun on the fixed build:

- **An input's trace window ran to the next input's mark,** so it held the next track press's setup (a wheel there and back), and a retried press marked its start twice, shifting every later reading onto the wrong input's view. Each input is now its own window (`input:<n>` … `input:<n>:end`, marked once it settled, before the next setup), and the last start of each counts.
- **The settle waited for any `contender:filled` since before the setup,** so a press could be followed by the next input while its rows were still loading, and those rows would count as already real on the DOM side. An input now settles once the view has moved from where it was at the mark and every visible row is real.
- **Cost's "use" CPU started at the open,** taking in the memory measurement (a forced GC) and the probe key. It now starts at the fling's first wheel event.
- **The probe frame's fallback stopped at the first frame after the mark** even when that frame presented nothing. It now takes the next frame that does.
- **The fling's unawaited wheels** could reject unhandled while the loop waited, killing the run without its cleanup; each now settles at once. **GPUI's first steps** waited on `wheel`'s device-scale read, so it's read before the fling. **The step count** divided by the first event's delta, wrong if that one was coalesced; it now uses the known per-step delta in the page's units. The loop, copied into cost, is one helper (`readyFling`, `fling`, `stepsReceived`).
- **GPUI's probe listened from the host's creation,** before its first frame, where the DOM side listens from usable. It now counts keys only once `gpui:first-frame` is set. `reach`'s control holds back the whole wasm, so it can't reach that gap; the gate is the bootstrap's own first-frame mark.
- **Dead code:** the module's unused mark helpers, an unused export, and `reach.ts`'s copy of the key recorder are gone.

## Experiments and controls

- **Paints read without an upper bound** made TanStack's "→ rows real" ~10.6 s in the first smoke run. Inputs alternate (Page Down, then Page Up), so a later input's new cells for the same rows counted toward an earlier one. Fixed: an input's paints are bounded by the next input's mark. The rerun is in the table.
- **The probe's frame fallback.** "The next presentation after the mark" put TanStack's frame 0.6 ms after its commit: a frame already under way, drawn without it. Fixed: a mark outside any frame is drawn by the first frame that begins after it.
- **A presented-frame check on GPUI's `contender:input`** (`presentedMark`) failed in one full check: no GPU call in the mark's task. The probe changes nothing on screen, and GPUI made no GPU calls for an unchanged scene. Dropped; `metric-usable` reads the frame from the trace instead, guarded by `EventLatency`.
- **The probe key Shift vs `x`** on GPUI: 18.8 vs 6.2 ms to the mark (one trial each). GPUI hears a modifier alone only on its release.
- **The awaited fling** took ~9 s on GPUI and ~6 s on TanStack for the same 180 events, so it now goes out on a schedule. The DOM side got 178–179 wheel events (coalesced) for the whole distance, so input is counted by summed delta.
- **`PipelineReporter`** called 116 of 188 frames in a GPUI fling `STATE_NO_UPDATE_DESIRED`, so late frames come from the main thread's frames instead.

## Reproducing it

```sh
just observatory gpui-build && just observatory tanstack-build
just observatory metric usable --runs 1 --label m4-a-smoke-usable   # likewise data, response, fling, reach, cost
just observatory sizes --label m4-a-sizes
```

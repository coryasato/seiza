## What surprised us

- **The engine's worker doesn't appear in the page's resource timing,** so the hidden checks time the engine's JS chunk (`assets/engine-*.js`), which the open imports first.
- **A page that only claims to be hidden still paints,** and its paint can land before the engine chunk's request, so "hidden" alone doesn't separate the visibility path from the paint path. The check also takes away the frames and the paint entries, as a real background tab has none.
- **Firefox warns about DuckDB-Wasm's `eh` bundle** (the deprecated `try` instruction). It's the engine's; the check ignores that one warning.
- **GPUI draws a short page's missing cells as `NULL`** (`render_body`'s `unwrap_or(CellValue::Null)`); the DOM side now draws them empty. No row of a static file is ever missing, so nothing measured differs; whether the component should change too is open.

## Experiments and controls

- **Hidden frame:** its 0 paint entries are the control that the zero-viewport path, not a paint, started the engine; before the review's change it started at the 1,000 ms timeout (1,046 ms).
- **Wheel and keys after the review's changes** (Chromium, once): 200 wheel events of 120 px from the top put row 800 at the top (24,000 px, 1:1), then 5 ↓ row 805, filled.

## After the code review

A review (medium) found, and this fixes:
- **A scrollbar press whose release never arrives** (Firefox past the window, or outside a frame) left every later scroll the thumb's (the stretch, ~3× per wheel step). A wheel, a key, or a touch now ends it, and `mouseup` counts as a release too.
- **A re-open would have kept the virtualizer on the old model:** the table is keyed by the open, so each open gets a new model and virtualizer.
- **TanStack's `isScrolling` never went false:** the model now tells its listeners when the scroller rests (150 ms).
- **The paintless timeout could start the engine before a slow first paint** (throttled runs): replaced by the zero-viewport test, so no page waits on a clock.
- **Every scroll event re-rendered every visible row** (~40 rows × 11 cells of `shownText`): rows are memoized by their page and index, so only rows whose page or place changed render.
- `openTable` was dead (the open runs from `main.ts`, with its status lines): removed. The native DuckDB loader, copied in three perf scripts, is `perf/harness.ts`'s `nativeDuckDB`; `tanstack-view` uses the harness's `ENGINE_CHUNK`; `tanstack-view` and `engine-files` fail at once on a failed row instead of waiting out 60 s.

Kept: the short page drawn empty where GPUI draws `NULL` (`PLAN.md`, open questions). `engine-files` no longer checks the row count; `tanstack-view` does. The first-paint JS after the fixes: 68.8 KiB brotli.

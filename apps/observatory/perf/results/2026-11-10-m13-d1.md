# M13 part D1: the metrics at the wall level (2026-11-10)

Measured on Apple M1, Darwin 25.6.0 arm64, machine `local`, Chromium headless=new (Firefox and WebKit for `tanstack-parity`). **Smoke runs only:** one run per side and profile, to show each script runs at the level and reads what it should. The numbers below aren't the protocol's (median of 10), and part D2 measures them on reviewed code. The raw files are dated 2026-11-11, the scripts' UTC date.

Raw: `2026-11-11-m13-d1-smoke-feed-monitoring-wall-{4,6,8}.json`, `…-smoke-usable-monitoring-wall-6.json`, `…-smoke-data-monitoring-wall-6.json`, `…-smoke-memory-monitoring-wall-6.json` (all before the scrollbar room below); `…-smoke-data-room-monitoring-wall-6.json` (TanStack after it); `…-smoke-market-market-watch-1k.json` (market watch's feed, still read as before).

## What changed

- **The pairing across the tables** (`metrics/metrics.ts`):
  - `FeedBatch` and `RefreshedFrame` take the wall's shape: a generation a table and a mask, and the drawn generations copied at each mark.
  - `batchVisible`: a tick on screen is market watch's flag, or the wall's mask not 0.
  - `drawnReaches`: a frame reaches a batch when every table in its mask has drawn the generation the batch names there.
  - `feedFrames` keeps one cursor, the first mark at or after a batch's send, and scans on from it. On the wall a later batch's tables can differ from an earlier one's, so its frame can come first and the old shared cursor no longer holds.
  - Market watch's pairing is unchanged: over 2,000 random market-shaped feeds (a throwaway check) it paired every batch as the old one-pass code did. A wall case where table 1 draws batch 0 a frame late paired batch 0 at the later mark and batch 1 at the earlier one.
- **`metric feed`** runs at the wall level. Its recorder copies `__contenderRefreshed` at each mark on the wall (the array changes in place), the same copy on both sides.
- **`metric usable`** runs at the wall level, unchanged otherwise.
- **`metric data`** runs at the wall level: GPUI's `filled` across the tables, TanStack's moment the latest paint among every table's visible rows (`row:<50t + r>`), and `state.tables` checked against the stop's.
- **`metric memory`** runs at the wall level: 10,000 ticks a table (`?ticks=60000` at 6), every table's last re-read drawn (`fedTicks` takes each table's highest generation), then the flash's fade, with the open's reading once every table has filled. Download by kind comes from the same run.
- **The scrollbar room, found by the data smoke:** GPUI showed 16 rows a table and TanStack 17. The tall table keeps 16 px under its rows for a horizontal scrollbar; the DOM's scroller kept none. Each TanStack wall table's scroller is now 16 px short of its frame, less its own horizontal bar's height after the review (below), decided with the user ([`docs/DECISIONS.md`](../../docs/DECISIONS.md), "TanStack contender"). `perf/wall-grid.ts`'s `gridDiffers` now compares the rows each table shows, and `perf/wall.ts` and `tanstack-parity` keep the cells at each grid to compare them, with a control (one more row shown).

## After the code review

- **The room under a classic scrollbar.** A fixed 16 px left the room whole under a classic horizontal bar. When the columns overflow, the bar sits inside the scroller, and TanStack showed a row fewer than GPUI. `keepBarRoom` (`wall.ts`) now keeps 16 px less the bar's height, measured at each resize. Headless browsers draw no bar with height, so `perf/wall.ts` forces a classic 15 px bar in its own Chromium, with scrollbars shown, at 8 tables at 1200×900. The room drops to 1 px and every table shows 16 rows, as without the bar; the control (the room kept whole) shows a row fewer in all 8. The first run of this check had no bar at all, because the script's Chromium hides scrollbars, and its guard failed it.
- **One rule for which batches count.** `batchVisible` takes a wall batch with any table in its mask, and `drawnReaches` takes a table at generation 0 as drawn. `perf/wall.ts` now pairs with the same two functions, from the first mark at or after the send, where it had searched from the log's start.
- **One recorder and one wait.** `refreshedRecorder` and `fedTicks` live in `contender.ts`; `metric feed` and `perf/wall.ts` both use them. `fedTicks` keeps a running tally on the page (`__fedTally`), so each poll reads only the new batches.
- **The pairing's scan stops at the window's end.**
- **`metric data` checks `state.tables` on both sides.**
- The other TanStack levels' builds are byte-identical with and without this part's TanStack changes (64 files: base, wide, market, tail). The wall's first-paint JS is 77.2 KiB (limit 84.6). `perf/wall.ts` passes on both sides, and so does `tanstack-contract` (at 6 tables: 79 batches in order, each table's generation drawn).

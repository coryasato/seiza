Measured on Apple M1, Darwin 25.6.0 arm64, machine `local`, Chromium headless=new. The cold runs at 1440×900 and DPR 2, median of 10, reference and throttled (root CLAUDE.md, "Measurement protocol"); `tail` at DPR 1 (2560×1700 for the cells, so every column draws). The baseline is the second cold run after `density` (reference 163.4–187.2 ms); the first read a median of 183.5 with a max of 228.5 at load ~4 and was rerun, and the build before `density` read the same 171.8 ms median.

Of that, the table's features alone in its bare host: `follow` +7.5 (with its `live`, +4.4 alone), `custom-cells` +4.2, `format` +3.8, `density` +3.9 KiB brotli (`components/tall-table/perf/results/2026-11-05-m12-c-size.json`); the rest is the host's (the loop's SQL, the time's text, the scene, the clock's glue).
- The other levels' wasm: +12 bytes raw each (10,142,558 → 10,142,570 B after wasm-opt for the base, 10,160,705 → 10,160,717 the wide, 10,202,356 → 10,202,368 the market), brotli 2,769.7, 2,776.6, 2,790.7 KiB. The base built from this tree with the four touched Rust files put back as they were is byte-identical to before (`4260cede…`), so what moves them is those files' source positions (panic locations), as in M10 B3. A first build with `web-sys` and `wasm-bindgen-futures` as plain dependencies changed every level throughout (most functions renumbered) and the market +36 B; optional, that went (`docs/DECISIONS.md`, "GPUI contender").
- Every bundle's entry carries live tail's entry in the one scenario list and the `contender:tail` mark's name: the TanStack levels' first-paint JS 73.5, 77.5, 75.7 KiB brotli, each under its budget; their other chunks unchanged but for the entry's hashed name they import. The tail build's entry is 23.7 KiB brotli, and its clock's worker a chunk of its own (1.2 KiB), loaded once the file is registered.

## Experiments and controls

- The widths: laid out by kind (time 184, request 200, status 69, bytes 101 px), every request line was cut at 200 px. The design canvas draws 196, 470, 72, 90, which the level now sets through `density` (decided with the user); `tail` checks them, the kinds' widths its control.

- The first run read `__contenderFollowing` unset: the table follows before the contract subscribes, so the first `Following(true)` went unheard; the contract now sets the global from the table's state as it starts watching.
- `wide`, `market`, `reach` (GPUI), and `engine-files --controls` pass with the tail build among the levels (the engine's files byte-identical in it too).

## After the code review

Nine findings. Fixed: the clock's log (`__contender.batches`) never emptied, so a replay's new clock appended to the old run's counts; a pause asked before the worker existed was dropped; the open checked the file's columns but not that its rows are the replay's laps; an infinite chroma passed `Tail::new`; a milestone named in `perf/tail.ts`; `main.ts`'s and the contract's `contender:failed` row not naming the tail level. Not taken: formatting each page's times once at its landing rather than each time a cell is drawn (at 100k rows/s a grown tail page is re-read about every frame, 1,024 rows each, against ~25 visible time cells a frame, so it would format ~40× more); sharing a worker module between `feed.rs` and `clock.rs` (it would change the market level's code; left for a part that touches both). The smoke and the native tests ran again after the fixes; the wasm's brotli moved 2,790.2 → 2,790.3 KiB, inside its ±0.5 between builds, so the baseline above stands.

# M6: The deploy (2026-10-21)

Measured on Apple M1, Darwin 25.6.0 arm64, machine `local`, Chromium headless=new, 1440×900 at DPR 2, median of 10, reference and throttled (root CLAUDE.md, "Measurement protocol"), against production (`https://seiza.io`, Worker version `1a310159`). Production numbers are recorded, never against a budget.

Raw: `2026-10-21-page-production.json` (the page's hosting checks and cold first paint), `2026-10-21-gpui-cold-production.json` (the GPUI contender's cold load), `2026-10-21-m6-burst.json` (request bursts, local).

## What changed

- The Worker runs first for every request and serves every build file as the deploy's quality-11 `.br` (`worker/scripts/stage.ts`); DuckDB's two wasm bundles (33.4 and 38.4 MiB, over the 25 MiB asset limit) are left out of the upload and go out only as `.br` (5.1, 5.7 MiB) or `.gz` (7.5, 8.5 MiB). No R2. No app's wasm changed: Tycho's Worker now imports its `Accept-Encoding` check from `shared-web/src/encoding.ts` (not redeployed; its tests pass).
- 48 files uploaded; the 24 build files go out as 14.7 MiB of brotli.

## Experiments and controls

- Through the real Worker under `wrangler dev` before deploying: every check but the brotli bytes passed. `wrangler dev`'s proxy re-encodes responses as gzip, so local runs can't check the encoding.
- `page --url`'s "theme while loading" test hung in production at its `goto`: over a real network the frame is created before the page's `load` event, which then waits on the frame the test holds. It now waits for `domcontentloaded`.
- After a code review, redeployed (version `ee41333a`, no asset changed) and checked again: PASS. The engine's hash check now accepts only DuckDB-Wasm's own file names with a hash added. As a control, `duckdb-bindings.js`, `duckdb-coi-pthread.wasm`, and `duckdb-eh.wasm` are rejected and both real bundles accepted. The deploy's check now polls the routes' HTML (`--wait`) instead of rerunning the whole ~35 MiB check up to 12 times.

## Reproducing it

```sh
just observatory deploy --behind-waf
node apps/observatory/perf/page.ts --url https://seiza.io
node apps/observatory/perf/cold.ts --url https://seiza.io
just observatory burst --label m6-burst
```

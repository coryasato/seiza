# The contenders (`contenders/`)

What both contenders share. Each contender's own file is beside its code: `tall-table/gpui/CLAUDE.md`, `tall-table/tanstack/CLAUDE.md`. Claude Code loads this file when a file under `contenders/` is read. The observatory's rules and the map of its folders are in `apps/observatory/CLAUDE.md`, the repo's in the root `CLAUDE.md`; both apply here. Paths are relative to `apps/observatory/`.

## Shared by the contenders

**Shared by the contenders:** `contenders/level.ts` (Node only: `gpuiCargoFeatures`, the GPUI crate's Cargo features at a level, which `built.ts --cargo` prints for the recipes; a side's build level from Vite's mode (`levelOf(side, mode)`: a level the side doesn't build yet, in `LEVEL_FEATURES` but not its `BUILT`, fails the build), its `dist-<level>` directory, and `levelConstants`, the `__LEVEL__` constant both Vite configs define), `contenders/scenarios.ts` (the one list of scenarios: each one's level, data file, stops, and default stop; the wide sheet's heat, its stops per theme in Oklch, each inside sRGB, and its domain, which both contenders and the page's drawings draw; market watch's seed, its rise and fall per theme in Oklch, and its flash (duration, mix, columns); live tail's rates, its error color per theme (market watch's fall), and its columns' widths; the monitoring wall's stops (its tables), its seed, its rate a table, its desks' names, market watch's signs and flash (shared), and its grid (the gap, the title row, the row height and text size, the four columns' widths, the width under which it's one column, that column's rows a table, and its tables' width); the levels' features (`LEVEL_FEATURES`); every scenario (`ALL_SCENARIOS`, which `pickScenario` and the scripts that measure a scenario read), the page's (`SCENARIOS`, which a scenario joins once both sides build it and the page draws it: the routes and cold numbers read it), and the levels each side builds (`BUILT`, which the recipes, `sizes`, `cold --level`, `tanstack-sizes`, `placeholder`, the page's servers, and `stage.ts` read; `contenders/built.ts` prints a side's for the justfile); `pickScenario`, a frame's `?scenario=` and `?stop=` on a level, an unknown id an error; the page and the perf scripts read it too), `contenders/market/` (market watch's feed, and the monitoring wall's, one module for both sides: `feed.ts`, pure, market watch's instruments' one home (`INSTRUMENTS`, their decimals), the batch's layout (`HEADER`, `TICK`, `AT`), the seeded generator (`Feed`, over any instruments' prices, market watch's 50 by default), and the rate's counting (`Rate`), and what a store does with a tick; `worker.ts`, the worker each contender frame starts (`FeedStart`: rate, seed, limit, and on the wall the stop's instruments' prices), a batch about every 16 ms as one transferred `ArrayBuffer`, its send time stamped at the post; `fixtures/feed.json` and `feed.bin` (the ticks' bytes), the feed fixture, written by `fixtures/write.ts` with a reference fold of its own (its header the format; `--check` regenerates it, and the wall's), run by each side's store with the same controls), `contenders/wall/` (the monitoring wall's instruments: `instruments.ts`, the 400's one home, 8 desks of 50 in the feed's order (`WALL_INSTRUMENTS`: desk, symbol, reference price), and `names.ts`, the desks' names (`DESKS`), a file of their own so `scenarios.ts` never imports the 400, both pinned as text; `desks.ts`, a stop's first N desks as the feed and the stores take them (`wallInstruments`, `DESK_ROWS`); `fixtures/feed.json` and `feed.bin`, the wall's feed fixture over all 400 (and each stop's feed bytes by SHA-256), written by market watch's `write.ts` and run by each side's store with market watch's controls), `contenders/fonts/` (the admin table's script faces: `faces.ts`, pure, the 13 Noto faces pinned (notofonts' release site at one commit, each face's version, bytes, and SHA-256), each kept and served under a name with its version and hash (`faceFile`), and `SCRIPT_FONTS`, `/observatory/fonts/`; `OFL.txt`, their copyright lines and license, committed; `files.ts`, Node only, `faces/` (gitignored) and `facesProblem` (a face missing or off its pin, or any file no pin names: all of `faces/` is served); `fetch.ts`, `just observatory script-fonts`, which fills `faces/` by the pins, checks each face's version and copyright line, and removes anything else; served in the GPUI base build's dev and preview by `engine.ts` (`contenderBuild`'s `scriptFonts`), staged by the deploy; their path is `paths.ts`'s `SCRIPT_FONTS`), `contenders/paths.ts` (every path above, a level's base under its contender's; the page and the perf scripts read it too), `contenders/follow.ts` (live tail's follow toggle: `FollowMessage`, `FollowingMessage`, `followToggle`; a module of its own so the TanStack entry, which imports `contract.ts`, doesn't carry it), `contenders/tools.ts` (the wide sheet's copy line, a module of its own for the same reason: `COPY_MARKS`, `ToolsMessage`, `ContenderTools`, `toolsReporter`, which with `?readout` in a frame publishes `__contenderTools` (focusing the frame before a copy) and posts the frame's reports, a change of the copy's state at once and the rest at most every 100 ms), `contenders/contract.ts` (`__contender`, the contract's mark names (`MARKS`), `READOUT_PARAM` and `SHOWN_RING` (the readout's ring), the marks' relay to a parent page, `markAt`, `nextMark`, the page's theme: `THEME_SCRIPT`, `pageTheme`, `followPageTheme`, `ThemeMessage`; the replay's fling profile is the metrics module's), `contenders/data.ts` (a Vite plugin serving `data/` by range at `/observatory/data/` in dev and preview, whatever the base, with the Worker's headers), and `contenders/engine.ts` (`contenderBuild`, in both Vite configs: DuckDB-Wasm's bundles emitted under `duckdb/`, content-hashed, and referenced at `/observatory/duckdb/`, so both contenders load the same files from there; the engine and the font served at their paths in dev and preview (`shared-web`'s `serveDirs` and `serveFonts`; the engine's missing extensions 404 there, so the contenders don't add `@seiza/duckdb`'s `duckdb()`, which guards only `<base>duckdb/`); `THEME_SCRIPT` inline at the head of the `<head>`; the build fails if Arrow or DuckDB-Wasm's JS is in a chunk the entry loads statically).

## Files

```
  contenders/       # scenarios.ts, paths.ts, contract.ts, data.ts, engine.ts, level.ts, built.ts (shared by the contenders; scenarios.ts, paths.ts, and contract.ts by the page too); fonts/ (faces.ts, files.ts, fetch.ts, OFL.txt: the admin table's script faces; faces/ fetched, gitignored); market/ (feed.ts, worker.ts: market watch's feed, and the wall's; fixtures/: feed.json, feed.bin, and the writer of both scenarios' fixtures); wall/ (instruments.ts, names.ts, desks.ts: the monitoring wall's instruments; fixtures/: its feed.json and feed.bin); tail/ (data.ts: live tail's file and the replay's constants; clock.ts, worker.ts: its clock; fixtures/: clock.json and its test); tools.ts (the wide sheet's copy line); tall-table/gpui/ (crate/: package tall-table-gpui, src/fonts.rs the fonts toggle (its feature `fonts`, the base build's), src/wide.rs the wide sheet's tools, src/scene.rs the scenario (scene/market.rs market watch's, scene/tail.rs live tail's, scene/wall.rs the monitoring wall's), src/wall.rs the wall's host, src/market.rs the feed's store, src/feed.rs its worker, src/tail.rs the replay's SQL and time text, src/clock.rs its clock; web/: its Vite host (src/base.ts the base level's host and src/fonts.ts its faces' fetch, src/level.ts, src/market.ts, src/tail.ts, and src/wall.ts the market, tail, and wall levels' hosts), pkg[-<level>]/ and dist[-<level>]/ built, public/duckdb/ downloaded); tall-table/tanstack/web/ (src/: the view, scene.ts and wide.ts the wide level's, market.ts market watch's, tail.ts live tail's, theme.css generated; src/data/: the data layer; test/: the fixtures in TS and the view's tests; dist[-<level>]/ built; public/duckdb/ downloaded)
```

## Commands

```
just observatory script-fonts  # the admin table's 13 Noto faces into contenders/fonts/faces/ by their pins (faces.ts), with OFL.txt, anything else removed (the base's gpui-dev and gpui-preview, admin, check, and deploy run it)
just observatory fixtures      # the tall table's fixtures (components/tall-table/fixtures/): their native tests and controls (the base, the wide level's features, and `copy`'s), the TanStack contender's TS run of them, and cell-fixture --check (run gpui-build and gpui-build wide first); the feed fixtures, market watch's and the monitoring wall's: write.ts --check, then each side's store against each, with its controls; live tail's clock fixture, then each side's loop SQL and time text, and the tail scene's numbers; the wall scene's numbers and each desk's rows of the store
```

# Decisions: kirkwood

Why the density plot is built the way it is. Decisions that bind every app are in the root [`docs/DECISIONS.md`](../../../docs/DECISIONS.md); what Tycho decided about its plot's data (where the points live, the first read) is in Tycho's [`docs/DECISIONS.md`](../../../apps/tycho/docs/DECISIONS.md), "Density plot".

One bullet per decision, under its area, oldest first: what was chosen, the numbers that chose it, and *[where they came from]* (a milestone here, a milestone of the app that drove it, a code review, a results file). A decision that replaces another marks the old one *Superseded* rather than deleting it.

## Drawing

- **2026-11-10** · **The grid is one image: `Window::paint_image` on a `RenderImage` the plot makes from the counts.** The pinned GPUI has no custom-shader API on the web (`paint_surface` is macOS and iOS only). A held image cost a frame 0.1–0.2 ms over an empty view at any grid size from 256² to 2048², and cropped and scaled differently every frame the same; a quad per non-empty bin cost 5.2 ms a frame at 64², 29.5 at 128², and 173.7 at 256². The image path added +2.3 KiB after wasm-opt (+1.3 brotli, inside build noise): the atlas, the sprite pipeline, and the `image` crate already link. *[Tycho's research, `apps/tycho/perf/results/2026-11-10-plot-research.md`]*
- **2026-11-10** · **A zoom or a pan moves the held image at once; the new bins replace it when they land.** `paint_image` crops and scales between the bounds painted and the bounds the whole image would cover, so the last grid follows the view every frame for the cost of holding it still, and a source's re-bin (14–54 ms on 1.57 M rows, 0.4–1 s on 25 M) is a sharpening delay, not a frozen frame. Rejected: waiting for the bins before drawing the new view. *[Tycho's research, the same note]*
- **2026-11-10** · **At most 512 bins a side by default, one per 2 CSS px.** Coloring and uploading a new grid took ~4 ms over an empty frame at 512² (~15 ms at CPU 4×) and ~13 ms at 1024² (~54 throttled): the default lands inside a frame at the reference run. Paid per landed grid, never per frame; the host can set both numbers. *[Tycho's research, the same note]*
- **2026-11-10** · **The state keeps the landed counts, and colors them on a log scale through a ramp of theme tokens mixed in Oklab,** as the tall table's cell ramps are: a theme change re-colors with no read, and a density's counts span decades. *[Tycho's research: [`docs/research/density-plot.md`](../../../docs/research/density-plot.md), "Drawing"]*

## Component API

- **2026-11-10** · **A delegate that answers bins for an extent and a grid size; the plot holds no points.** What's behind it is the source's: Tycho's is the two columns copied into DuckDB's memory (its `docs/DECISIONS.md`, "Density plot"), the bare host's a seeded point set binned in Rust. So 25 M rows cost the plot what 1.57 M do, and only the source's read differs. *[Tycho's research, [`docs/research/density-plot.md`](../../../docs/research/density-plot.md), "The component's shape"]*
- **2026-11-10** · **Bins are read when the view rests, one read in flight, the newest view next.** A wheel gesture is dozens of events and a read is up to a second of DuckDB's one thread, which can't stop a started query (`engines/duckdb/CLAUDE.md`, its gotchas); the tall table's `live` re-reads coalesce the same way. *[Tycho's research, the same section]*
- **2026-11-10** · **The link to a table is the host's, through events.** A click reports a point and a tolerance in data coordinates; a box (the `select` feature) reports two ranges. The plot depends on no table and counts nothing: finding the row, counting a box, and re-reading a table are a source's. *[Tycho's research, [`docs/research/density-plot.md`](../../../docs/research/density-plot.md), "The link to the table"]*
- **2026-11-10** · **The base is the drawing, the view's gestures, and the click; a box is a feature (`select`), off by default** (root `CLAUDE.md`, "Tiers"). A click needs no state of its own; a box brings a drag mode, its drawing, and its keys. *[planning, `PLAN.md`]*

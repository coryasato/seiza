# The bridge (`bridge/`)

The host-side crate `tall-table-bridge`: the table's events turned into a seiza host's marks, globals, and clipboard writes. Claude Code loads this file when a file under `bridge/` is read. The table's rules and the map of its folders are in `components/tall-table/CLAUDE.md`, the repo's in the root `CLAUDE.md`; both apply here. Paths are relative to `components/tall-table/`.

## Architecture

- **`bridge/`** (`tall-table-bridge`): what a seiza host does with the table's events, written once for every host (Tycho, the observatory's GPUI contender, the bare host): `Publish` (the filled mark with `mark_after_current_task`, with `live` the refreshed mark and the highest generation drawn on a global, set before the mark, with `follow` the following flag and the tail last drawn on globals the host names, set before the tail mark, with `resize` each column's set width on a global the host names (`js::widths`, at each `ColumnWidthsChanged`), with `select` the selection on a global the host names (`js::selection`, `{kind, anchor, head}` or `null` as `fixtures/selection.json` spells it, at each `Selected`; the probe's `selection` too), with `sort` the order on a global the host names (`js::sort`, `{column, direction}` or `null`, at each `Sorted`, then a mark the host names, set in the task that sorted; the probe's `sort` and the layout's `arrow` too), with `pin` the columns pinned in effect on a global the host names (at each `Pinned`; the layout's `pinned` too), with `reorder` the order on a global the host names (`js::order`, `[index]` at each place, at each `ColumnsMoved`; the layout's `index` too), the scrollbar's targets `table-scroll-track` and `table-scroll-thumb`, the probe, layout, and drawn cells on globals the host names) and `js` (the probes as JS values, for a host that puts them somewhere of its own); with `copy`, `clipboard::Clipboard`, the clipboard's writer beside `Publish` (which drops the copy's events): a host hands it each `TallTableEvent::Copy` and tells it when the table closes (`closed`). At `Started` it opens `navigator.clipboard.write([new ClipboardItem({'text/plain': promise})])`, keeps each `Text` as a JS string, resolves the promise with a Blob of them at `Copied` (the strings dropped once it's built) and rejects it at `Failed` or `closed`; without `ClipboardItem`, `writeText` at `Copied`; without `navigator.clipboard` (an insecure context), and when the browser refuses the write while the copy runs, `event` returns the copy for the host to cancel (`cancel_copy`). What became of each copy (`clipboard::Outcome`: declined, copying, writing, written, refused, failed, unavailable) goes on a global the host names and to a callback it gives, which runs outside GPUI when the browser settles a write. A host's own state and panel rows stay in its own `match`. It depends on `seiza` and the table, so it can't live in either (`docs/DECISIONS.md`, "Hosts"). `Publish::event` is `#[inline]`: its unused arms fold away in each host.

# Decisions: table

Why the table component is built the way it is. Decisions that bind every app are in the root [`docs/DECISIONS.md`](../../../docs/DECISIONS.md).

One bullet per decision, under its area, oldest first: what was chosen, the numbers that chose it, and *[where they came from]*. A decision that replaces another marks the old one *Superseded* rather than deleting it. Decisions moved here from an app keep their dates and sources.

## Table and paging

The bullets up to 2026-10-09 moved here from Tycho's `docs/DECISIONS.md` when the table left it; their sources are Tycho's milestones, and their results files are under `apps/tycho/perf/results/`. "Queries" in them are the delegate's page reads, which in Tycho are DuckDB queries.

- **2026-09-25** · **Own table, not gpui-kit's `DataTable`:** its `uniform_list` positions rows in f32 pixels (4 px steps at 47 M px, 64 px at 25 M rows). It scrolls in f64 rows and owns its scrollbars, wheel, and keys; no column resizing, selection, or sorting. *[M4]*
- **2026-09-25** · Pages of **1024 rows, prefetch 2** (twice ahead while scrolling), 3 queries in flight, **64 MiB** LRU page cache. The sweep didn't separate 256/1024/4096 × 1/2/4 beyond noise; 1024 divides the row groups. *[M4 sweep]*
- **2026-09-25** · Cancelled page queries count against the 3-in-flight limit until DuckDB answers them (it keeps reading a started page); failed pages retry once scrolled away and back; prefetch leans ahead only while the rows move (250 ms). *[M4 code review]*
- **2026-09-25** · A scrollbar drag loads pages only once the pointer rests 80 ms, or on release: a started page read can't be cancelled (DuckDB's worker uses sync XHRs), and a stale one delayed the jump's target (throttled 4.3 → 2.2 s). *[M4]*
- **2026-09-27** · **Visible pages first:** no prefetch page starts while a visible page isn't loaded. DuckDB-Wasm round-robins query slices, so prefetch in flight delayed the visible page (1 GB first rows 2.7 s → 0.8 s with the cache fix; jump to 90% 133 → 92 ms). *[M5]*
- **2026-10-07** · The table reports its first rows with an event (`TableEvent::FirstRows`) and its paging and scrolling through `RowTable::stats`; the workbench decides what the panel shows (the open-questions note). Rows/s and cache hits cover the panel's 2 s window; a cache hit is a drawn frame with every visible row loaded. *[M7 part A]* *Its `TableEvent::FirstRows` was superseded 2026-10-13: the table emits `Filled` and the host marks it (below).*
- **2026-10-07** · **No cell-string cache.** Formatting every visible cell takes 0.075 ms p50 of a 13.1 ms draw on Gaia (0.045 of 11.8 on the asteroids), timed alone in an instrumented build. Gaia's cells hold 2.4× the characters and cost +11% work per draw. *[M7 part B]*
- **2026-10-07** · Pages stay **1024 rows × prefetch 2** on Gaia too. Re-run with work per frame, the sweep still barely separates: steady work 11.9 ms at 256-row pages vs 12.5 at 1024, first rows and jumps within noise, no placeholders in any steady scroll. *[M7 part B `apps/tycho/perf/results/2026-10-08-m7-sweep-gaia.json`]*
- **2026-10-09** · Cell overflow is solved by formatting, not measuring: cells are plain blocks so GPUI's `.truncate()` cuts text at the end; doubles round to fit their column like a spreadsheet's automatic format (scientific only when the whole part doesn't fit); integers are never rounded and are cut in the middle (`1234…789`) if still too wide; one tooltip on the hovered cell shows the exact value. Measuring each column's widest value covers only the pages measured, and a column can't widen under the reader. *[M7 part F, design discussion]*
- **2026-10-16** · **The settle times are `Paging` fields:** `scroll_settle` (250 ms, prefetch leaning ahead) and `drag_settle` (80 ms, a drag's loads), with today's values as defaults. They decide which pages are requested, so the observatory holds them equal on both sides (root `docs/DECISIONS.md`, "Comparison protocol"). Tycho keeps the defaults: +1.2 KB raw after wasm-opt (+0.01%), and its table checks are unchanged (jump to 90% 83.3 ms reference, 2.2 s throttled). *[observatory M2 part A, `apps/tycho/perf/results/2026-10-16-observatory-m2-a.md`]*

## Component API

- **2026-10-13** · **Moved out of Tycho, as the repo's first component** (`seiza-table`, from Tycho's `crate/src/table/`). It depends on `gpui-kit` alone. *[Tycho M9 part C]* *Its name was superseded 2026-10-14: `seiza-tall-table`, in `components/tall-table/` (below).*
- **2026-10-13** · **A state entity, an element, and a delegate, as gpui-kit's `DataTable` does it:** `TableState<D: TableDelegate>` holds the scroll position, page cache, and hover, and draws the header and body; `Table<D>` (`RenderOnce`) adds the focus, keys, and border around it. The delegate reads pages (`load_page` returns a request id and a boxed future; `cancel`), and a page answers in the component's own `CellValue`s (`Null`, `Float`, `Float32`, `Text`): floats stay numbers so the table can round them to their column, everything else arrives as text, borrowed where the source has it. The column's `ColumnKind` (boolean, date, timestamp, integer with its widest value's characters, float, decimal, text) replaces Tycho's DuckDB type names. Named per gpui-kit's Coding Guides: a `<Control>State`, a `<Role>Delegate`, private fields with readers, `#[non_exhaustive]` on record-like structs. *[Tycho M9 part C, design]* *Its type names were superseded 2026-10-14: each carries `TallTable` (below).*
- **2026-10-13** · **Settings, not `seiza` calls.** Paging comes in as `Paging` (the host reads its URL overrides); the panel's window, clock, and visibility as `ActivityOptions` (`window_ms`, `clock`, `is_recording`); the Playwright probes as `probe_frames` and `probe_cells`. *[Tycho M9 part C]*
- **2026-10-13** · **Marks are the host's, from events emitted in render.** The first-rows and viewport-filled marks must land right after the frame that shows the rows. The table emits `TableEvent::Filled { first }` while that frame renders; GPUI flushes effects at the end of the update that draws and presents the frame (`App::update` → `finish_update` → `flush_effects`, gpui-pre 0.3.9's `on_request_frame`), so the host's subscriber runs in the same JS task, and its `mark_after_current_task` still lands in that task's microtask checkpoint, before the next task (and so before the browser can render anything else). It's queued after the present now, not during render, so it lands 0.005–0.045 ms later in that checkpoint: checked on the asteroids sample (first rows, the viewport filled, and after End; 5 runs each against the pre-extraction build, every mark before the next task in both). Rejected: an optional `seiza` feature on the component (a dependency on `seiza` the tiers forbid), and a callback hook (the event is the gpui-kit idiom and has the same timing). The probes and scrollbar targets go out the same way, only when they change. *[Tycho M9 part C, gpui-pre 0.3.9 source]*
- **2026-10-14** · **Renamed `tall-table` (`seiza-tall-table`), before the observatory's first comparison.** The types were gpui-kit's names with other meanings: `gpui_kit::component::table` exports `Table` (its simple static table), `TableState<D: TableDelegate>`, `TableDelegate`, and `TableEvent`, so a host using both had to alias. Every type that named the table now carries the prefix: `TallTable`, `TallTableState`, `TallTableDelegate`, `TallTablePage`, `TallTableEvent`, `TallTableStats`, `TallTableProbe`, `TallTableLayout`, and `TallTableColumn` (gpui-kit's table exports a `Column` too, and a host imports both unqualified); its actions are under `seiza_tall_table` and its key context is `TallTable`. `ColumnKind`, `CellValue`, `Paging`, `PageError`, `PageLoad`, `ActivityOptions`, `CellProbe`, and `ColumnProbe` keep their names: gpui-kit has none of them. "Tall" names what every feature level keeps, many rows never held at once, as MATLAB's tall arrays do (rows past memory, read lazily from a datastore). Rejected: `PagedTable` (reads as paginated), `ResidentTable` (the opposite of the design), `LocalTable` (a data path), `DataGrid` (editable), `DataView` (a built-in JS type), `CatalogTable` ("catalog" is the data in Tycho and metadata in DuckDB, Iceberg, and Unity; it names a use case, not the property), `LongTable` ("long" vs "wide" is a data shape: pandas' `melt`). The cost: "tall" also reads as an element's height, which the README's first lines answer. *[design discussion]*

# The bare host (`host/`)

The bare host of the table, crate and page. Claude Code loads this file when a file under `host/` is read. The table's rules and the map of its folders are in `components/tall-table/CLAUDE.md`, the repo's in the root `CLAUDE.md`; both apply here. Paths are relative to `components/tall-table/`.

## Architecture

- **`host/`** (`host/crate/`, package `tall-table-host`; `host/web/`, `@seiza/tall-table-host`): the bare host, where each feature's own cost is measured (`PLAN.md`, "Measuring a feature"). The table alone over rows answered from memory (`rows.rs`: each value a function of its row and column, a page materialized when its read resolves, none for a read cancelled before then, answered as the DuckDB source's Arrow pages are), on `seiza` without the panel, no engine. `?shape=narrow` (the observatory's 11 columns' kinds) or `wide` (500 float columns), 1,567,523 rows either way; `?delay=<ms>` holds each read; `?perf` turns on the probes (`__tallTable`, `__tallTableLayout`). It marks `tall-table:filled` and publishes the scrollbar's targets; `host/web/src/main.ts` defines `__seizaFrameSample`. Never deployed. One Cargo feature per table feature, each switching the feature on at run time: `custom-cells` paints every float column through its range (`rows.rs`'s `Cells`: `?cells=text|heat|bars|color`, `text` the control), publishes the drawn cells with `?perf&probe-cells` (`__tallTableCells`, for the smoke check: never in a perf run, whose frames it would slow), and takes `?jump=<row>`; `live` runs a feed at `?live=<updates/s>` (`host.rs`'s `Feed`: seeded, random visible rows, a batch about every frame, each row once, its version bumped in the source, whose floats mix it in), marking each batch from the moment its rows are picked (`tall-table:invalidated`, its last generation on `__tallTableInvalidated`) and publishing the refreshed mark (`tall-table:refreshed`, `__tallTableRefreshed`); with both, `?flash` gives every float column a flash (`rows.rs`'s `with_flash`: `chart_bearish`, `warning`, `chart_bullish`, 1 s); `select` builds the selection with every kind on (the table's default), so a press, a drag, and the keys select, and publishes it at each change (`__tallTableSelection`, through the bridge); `copy` turns on `select`: Cmd+C and Ctrl+C copy (the table's keys) and Cmd+Shift+C and Ctrl+Shift+C copy past the key's limit (`CopyConfirmed`, the host's `copy`, as a confirming click would; a key, so the clipboard takes it as a gesture), the bridge's writer puts it on the clipboard and the outcome on `__tallTableCopy`, marking `tall-table:copy-started`, `tall-table:copied`, and `tall-table:copy-written`; `?copy-max-bytes=` and `?copy-key-cells=` set the cap and the key's limit; the source counts its reads (`rows.rs`'s `Reads`, as with `follow`); and with `?perf` the scripts' hooks (`host.rs`'s `script_hooks`): `__tallTableExact(row, column)` (a value's exact text, `rows.rs`'s `MemoryRows::exact`), `__tallTableHeap()` (the wasm memory's bytes), `__tallTableSelect(kind, …)` (the table's `select`), and `__tallTableClose()` (its `close`, told to the writer), the last two entering GPUI through its foreground executor; `resize` builds every column resizable (the table's default), so the bands draw, and publishes each column's set width at each release or fit that changed one (`__tallTableWidths`, through the bridge); `follow` runs the tail feed (`host.rs`'s `Appends`: `?rows=<n>` rows at open, `?append=<rows/s>` more, a batch about every frame, one `set_rows` each, marked as sent, `tall-table:appended`, the rows then on `__tallTableAppended`), its source publishing the reads it was sent and cancelled in flight as they change (`rows.rs`'s `Reads`: `__tallTableReadsSent`, `__tallTableReadsDrained`), `?follow` following from the start, and publishes the tail mark (`tall-table:tail`, `__tallTableTail`) and the flag (`__tallTableFollowing`), and with `?perf` the scripts' hook `__tallTableLetGo()` (the table's `let_go`, entering GPUI through its foreground executor); `sort` makes every column sortable, its source sorting a column from memory (`rows.rs`'s `column_order`: the column's values read a chunk at a time into keys, a float's NULL its NaN, text by its first 8 bytes with the rest read again only for a tie there, then `order`, a stable sort under `Rules::SOURCE`, ties by row and NULLs last both ways; computed at a column and direction's first sort and kept while it's the last column sorted, a page then materialized from the rows at its positions, a read keeping the order it was sent in), bundles gpui-kit's three sort icons (`SortIconAssets`, through `Bootstrap::assets`), and with `?sort-icons` draws them (`set_sort_icons`); `?sort=<column>,<asc|desc>` opens sorted (the order computed before the first frame); each order is published (`__tallTableSorted`, through the bridge) and marked (`tall-table:sorted`); `?sort=` and the hooks send only a column in range (the table's own refusal is a debug assertion); the source counts its reads (`Reads`, never published on a global with `sort` alone, so a perf run's reads cost the page no call into JS the base's don't), the drawn cells are published with `?perf&probe-cells` (`__tallTableCells`, the smoke check's order), and with `?perf` the scripts' hooks: `__tallTableExact` (as with `copy`), `__tallTableSort(column, direction)` (the table's `set_sort`, entering GPUI through its foreground executor; `false`, nothing sent, for a column that isn't one), `__tallTableSourceRow(row)` (the source's own row at a row of the order, `rows.rs`'s `MemoryRows::source_row`, for ties), and `__tallTableDrained()` (the reads cancelled in flight so far); `pin` pins the first `?pin=<n>` columns before the first frame (by default the shape's, `Shape::pinned`: 2 in the narrow, its `spkid` and `full_name`, 1 in the wide; `?pin=0` builds the feature with nothing pinned), publishes the run in effect (`__tallTablePinned`, through the bridge), and with `?perf` the scripts' hook `__tallTablePin(n)` (the table's `set_pinned`, entering GPUI through its foreground executor; `false`, nothing sent, for anything but a whole count); `density` sets `?density=<row>,<text>[,<width>]` (px; `host.rs`'s `Density`: by default 18,11,56, the dense setting) before the first frame, the width on every float column, and `?density=30,14` builds the feature at the base's numbers with the kind widths kept (the control); with `?perf` the scripts' hook `__tallTableDensity(row, text)` (the table's `set_density` at px, entering GPUI through its foreground executor; `false`, nothing sent, unless both are positive numbers; the floats keep the width `?density=` set, so `30,14` through it isn't the base's layout). `format` formats every float column (2 decimals, `Sign::Always`, grouping) and the narrow shape's `spkid` (grouping) (`rows.rs`'s `with_format`), its page answering 3 decimals on every fourth row of the source, sorted or not (`MemoryPage::decimals`, from its `threes`), and `?format=off` builds the feature with no column formatted (the control); with `?perf&probe-cells` it publishes the drawn cells (`__tallTableCells`, the smoke check's text). `reorder` builds every column movable (the table's default); `?order=reverse` draws the columns reversed from the first frame (`?order=` alone or absent, the list's own: the control); each order is published (`__tallTableColumnOrder`, through the bridge; unset until the first change); the drawn cells with `?perf&probe-cells` (`__tallTableCells`, the smoke check's columns); with `?perf` the scripts' hooks `__tallTableExact` (as with `copy`), `__tallTableMove(start, end, to)` and `__tallTableOrder(order)` (the table's `move_columns` and `set_order`, entering GPUI through its foreground executor; `false`, nothing sent, for numbers that aren't whole, a block past the columns or a `to` past what fits, or an order that isn't one of the columns). `just tall-table build <features>` records what it was built with in `host/web/dist/build.json`, which the scripts read.

## Gotchas

- **wasm-bindgen answers a closure's `None` as `undefined`,** not `null`: a hook that means `null` returns a `JsValue` (`__tallTableExact` does), or a script's NULL tests never match.

## Files

```
  host/             # the bare host: crate/ (tall-table-host: lib.rs, host.rs, rows.rs), web/ (Vite: index.html, src/main.ts, vite.config.ts; pkg/ and dist/ gitignored)
```

## Commands

```
just tall-table dev [features]   # the bare host: debug wasm + Vite dev server with COOP/COEP (?shape=wide, ?delay=<ms>; custom-cells: ?cells=heat; live: ?live=<updates/s>; both: ?flash; follow: ?rows=<n>&append=<rows/s>&follow; pin: ?pin=<n>; density: ?density=<row>,<text>[,<width>]; format: ?format=off; reorder: ?order=reverse)
just tall-table build [features] # its release build: wasm alone (-p) + wasm-opt, Vite build, asset sizes; the base without features
just tall-table preview      # serve that build (brotli)
```

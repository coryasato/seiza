# M20 part C: `find`'s cost and the close (2026-11-19)

Measured on Apple M1, Darwin 25.6.0 arm64, machine `local`: the wasm's bytes (the bare host's builds, every feature with and without `find`, and each app that builds the table), the wide shape's frames with a term set (Chromium 153 headless=new, 1440×900 at DPR 2, cold, median of 10, the reference run alone: a term changes what a frame draws, not how it scrolls), a step's time to its frame (both shapes, reference and throttled), and the smoke check in three browsers. On part B's final table code (reviewed); part C changed no shipped code. The machine was busy throughout: Spotlight reindexing kept the load average at 25–55, so each frame run is read against the base's two runs around it, and their spread, not against a quiet machine.

Raw: `2026-11-19-m20-c-size.json` (`just tall-table size --label m20-c-size`); frames, each `-reference.json`, run in this order, each build just before its run: `2026-11-19-m20-c-frames-base`, `-find-none` (the `find` build, no term: the control), `-find` (`--find 1`: nearly every cell matching), `-base-again`, then `-find-nomatch` (`--find zzz`: every drawn cell tested, none matching) and `-find-12` (`--find 12`: about 1 in 7 drawn cells matching), added once the first four showed a cost (below); `2026-11-19-m20-c-find.json` (`just tall-table find --label m20-c-find`). In the gitignored `raw/`: each run's console, and the smoke checks' (`2026-11-19-m20-c-smoke-find.txt`, `-smoke-find-format-pin.txt`).

## What changed

Part C changed no shipped code. `perf.ts` gained `--find <term>` (the host's `?find=`, checked at open against the probe). `find.ts` (new, `just tall-table find`) times a step to the frame drawing its match. The smoke check gained a find run (C2, below), with `findThrough`, `stepThrough`, and `tintsIn` in `perf/harness.ts`; the host page's `__seizaFrameSample` gained the probe's `find`. After the code review, before every run below: the find run's density set to the base's 14 px text with `density` built (its tints are placed by the advances at it), a landing's row measured against the cells area's bottom (the scroll track's end) rather than the page's, and `find.ts`'s header saying its frame recorder stays on through the steps, as `sort.ts`'s does.

- **Built, no term: the base.** Every segment within 0.04 ms of the base's first run, inside the two base runs' spread (scroll 4.73–4.79, fling 4.54–4.66, sideways 4.46).
- **Every drawn cell tested, none tinted (`zzz`): the base.** Scroll +0.04 to +0.10 against the base's two runs, its range inside theirs but for 0.04 ms at the top; both flings within. The match tests (each drawn loaded cell's exact text lowercased and searched) cost nothing a run separates.
- **The tints cost what's drawn.** At `12`, about 1 in 7 drawn cells tinted (part B's 44 of 308), the scroll reads +0.10 to +0.16, its range touching the base's; at `1`, nearly every cell tinted, one to three ranges each, +0.25 to +0.31 (~5%), its whole range above both base runs'. The flings stay within the spread at every term: a fling's frames are 45% placeholders and the sideways fling's within a run's swing (`1`'s range 4.42–5.08 against the base's 4.10–4.59).
- **No cache of the tests:** check C1's remedy ("the tests cached per page and the run again") is revised with the owner, since the no-match reading shows the tests aren't the cost and a cache wouldn't touch the tints (`docs/DECISIONS.md`, "Features", 2026-11-19).

## A step's time (C1)

`just tall-table find` on the `find` build, the term `1` (a source answering in its first window), 3 cycles a session (a fresh term, a step back and a step on, each round the other end: far; then 8 steps on: in view, or sideways), cold, median of 10 sessions, ms. *Answer* is the source's (the call to the bridge's `Found`: the host's 1 ms least wait between windows, its window, and for a far step a second ask); *drawn* the first frame drawing the match as current; *the table's* is answer → drawn, the spread of its ten medians in brackets.

| Shape, profile | Far: answer, drawn (the table's), filled | In view | Sideways |
|---|---|---|---|
| Narrow, reference | 20.9, 40.4 (18.5 [35%]), 40.7 | 7.9, 19.7 (11.9 [28%]) | 7.6, 20.2 (13.1 [30%]) |
| Narrow, throttled | 29.1, 58.1 (28.1 [59%]), 58.5 | 12.9, 28.6 (17.2 [56%]) | 12.7, 28.6 (17.5 [64%]) |
| Wide, reference | 18.4, 37.7 (16.6 [37%]), 38.1 | 6.3, 24.0 (18.0 [34%]) | none taken |
| Wide, throttled | 26.2, 58.0 (32.2 [41%]), 59.2 | 15.3, 37.3 (21.9 [23%]) | none taken |

- **The table's part is a frame or two.** Its answer → drawn is the wait for the next frame (up to the 16.7 ms refresh) and that frame's work; its medians of 12–18 ms reference and 17–32 throttled say the match is drawn in the first or second frame after the answer, and their spreads (23–64%) are where in the refresh an answer lands. A far step's first frame is already filled (drawn ≈ filled): the host's pages answer at once, and the landing's reads go out with the jump.
- **The source's part is the bare host's,** windowed with a least wait (part B): a source over DuckDB answers in its own time (the spike's 30–130 ms for a near match on the asteroids).
- **Sideways in the wide shape:** none of the steps on left the view, `1` matching the next column each time; the smoke check's step back lands 58,702 px sideways (below).
- **On a busy machine:** a trial run before the load rose read the in-view answer at ~3 ms and the table's part 11–16 ms; the answer's medians above are 2–3× that, the table's within it.

## Reproducing it

```sh
just tall-table size --label m20-c-size
just tall-table wasm release custom-cells,live,follow,resize,select,copy,sort,pin,density,format,reorder,clicks,group-headers,hide   # and again with ,find
just tall-table build && just tall-table perf --shape wide --profile reference --label m20-c-frames-base-reference
just tall-table build find && just tall-table perf --shape wide --profile reference --label m20-c-frames-find-none-reference
just tall-table perf --shape wide --profile reference --find 1 --label m20-c-frames-find-reference
just tall-table build && just tall-table perf --shape wide --profile reference --label m20-c-frames-base-again-reference
just tall-table build find && just tall-table perf --shape wide --profile reference --find zzz --label m20-c-frames-find-nomatch-reference
just tall-table perf --shape wide --profile reference --find 12 --label m20-c-frames-find-12-reference
just tall-table find --label m20-c-find
just tall-table smoke
just tall-table build find,format,pin && just tall-table smoke
```

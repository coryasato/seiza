# M24 part A: what touch input reaches the table, a spike (2026-11-22)

Read on Apple M1, macOS 26.6.2, machine `local`, Playwright 1.63.0's Chromium (headless=new), Firefox, and WebKit, 1440×900 at DPR 1, the bare host's release build with `clicks,sort,resize,select,header-icon`, the narrow shape, gpui-kit 0.10.0 (gpui-pre and gpui-pre-web 0.3.12). One run a browser and a way of sending; a second in Chromium for one step (below). No timing: each step is what the host published before and after it (the last `Clicked`, the icon presses' count, the sort, the selection, the scroll, the first four widths) and the DOM events a capture listener on `window` saw. Not read on a phone.

The spike's script wasn't kept (part A builds no shipped code); "Reproducing it" below says what it did. The research it fed: root [`docs/research/tall-table-features.md`](../../../../docs/research/tall-table-features.md), "Touch presses".

## What changed

Nothing: no shipped code, no bytes.

## The ways of sending a touch

| Way | Chromium | Firefox | WebKit | What the page saw |
|---|---|---|---|---|
| Playwright's `touchscreen.tap`, a context with `hasTouch` | a tap | a tap | a tap | `pointerdown:touch touchstart pointerup:touch touchend`, trusted |
| CDP `Input.dispatchTouchEvent` | a tap, a hold, a pan | n/a | n/a | the same, trusted |
| `PointerEvent`s of type `touch` made by the page's script, dispatched on the canvas | a tap, a hold, a pan | a tap, a hold, a pan | a tap, a hold, a pan | `pointerdown:touch pointerup:touch`, untrusted, no touch events |

`navigator.maxTouchPoints` read 0 in every run, `hasTouch` or not.

## What the table did

The same in every browser and by every way that could send the step (18 steps × the ways above):

| Step | What changed |
|---|---|
| Tap a cell | `Clicked`: `press`, cell (3, 2); the cell selected |
| Tap a header | `Clicked`: `press`, column 3; the column selected |
| Tap `sort`'s arrow (column 0) | Sorted descending; no `Clicked` |
| Tap `resize`'s band | Nothing |
| Tap a header's icon (column 0) | The icon presses' count 0 → 1; no `Clicked` |
| Two taps on a cell, 80 ms apart | `Clicked` twice: `press`, then `double` |
| Hold a cell 800 ms, lift | `Clicked`: `context`, cell (8, 2), once (the lift's tap dropped); the cell selected |
| Hold a header 800 ms, lift | `Clicked`: `context`, column 4; the column selected |
| Hold the arrow 800 ms, lift | Nothing |
| Pan up 200 px in the body | The top row 0 → 6.7 (CDP) and 18.2 to 19.2 (script-made events, whose lift carries momentum); no `Clicked` |
| Pan left 200 px in the body | `scrollX` 0 → 200 (CDP), 203 (script-made); no `Clicked` |
| Pan left 200 px from a header | Nothing |
| Drag a band 60 px right | Nothing: no width changed |
| Hold a cell 800 ms, then move 150 px right and 90 down, lift | `Clicked`: `context` on the cell at the hold; then `scrollX` 203 → 0 (a pan); no drag-select |

## Experiments and controls

- **The last step read "no context press" in the first run,** in the three browsers: it started 700 ms after the step before, a pan's lift on the header, whose momentum was still running, and a touch that lands on a running fling catches it and can't become a tap or a long press. Run again in Chromium 3 s after, it reported the context press. A touch step waits out the last pan's momentum.
- **No control of its own:** that a step went by the touch path is the page's record of each pointer event's type (`touch` in every step). The mouse's behavior at the same places is the smoke check's (`clicks`, `resize`, `sort`), not run again here.

## Reproducing it

A script in `perf/`, on the harness's helpers: for each browser and each way, a new context (`hasTouch` for the first two ways), an init script recording `pointerdown`, `pointerup`, `pointercancel`, `touchstart`, `touchend`, `mousedown`, and `contextmenu` in the capture phase, the host opened with `?perf&shape=narrow`, then each step with the host's globals read before and 700 ms after. A hold is a down, 800 ms, an up; a pan a down, 12 moves 16 ms apart, an up.

```sh
just tall-table build clicks,sort,resize,select,header-icon
```

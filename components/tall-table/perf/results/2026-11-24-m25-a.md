# M25 part A: the fit as a call (2026-11-24)

Measured on Apple M1, macOS (Darwin 25.6.0), machine `local`: the wasm's bytes (the bare host's base at `7d845db`, HEAD, and on this part's working tree; every feature's build on the working tree, read against M24's run, the same code at HEAD), the symbols of unstripped builds, and the time of `just tall-table pairs`. gpui-kit 0.10.0. No frame reading: the call runs once a press, as the double-click's fit did, and adds nothing to a frame.

Raw: `2026-11-24-m25-a-size.json` (`size --against HEAD`: every feature's bytes, the symbols, the base at both); M24's `2026-11-22-m24-b-size.json`, the builds before.

## What changed

- **The table:** `TallTableState::fit_column(column, window, cx)`, public behind `resize`, by the column's index; the private fit by place it replaces is gone, and a band's double-click calls it. It does nothing at all to a column no band reaches (an index past the last, `resizable(false)`, or hidden with `hide`); otherwise a drag still held ends first, with its event. A single press on a band whose column a setter left with no band before the next frame (the code review's finding, older than the call) now starts nothing, by the same test (`has_band`).
- **No app builds it yet:** Tycho adopts it in its menus' part.

## `pairs`' time

2,810 s (47 minutes) for 17 features: 151 clippy builds, 111 pairs' tests, 151 rustdoc builds, all passing after the code review's fixes. The script's header said ~24 minutes, from the API review's count; it now says this run's. It ran twice: the first, started before the code review, was stopped in its tests (12 of 111) when the review's fixes came, which is why the table's `CLAUDE.md` now runs its clippy and doc parts before a review and the whole run once after.

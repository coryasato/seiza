# M17 part D: `group-headers`' cost (2026-11-16)

Measured on Apple M1, Darwin 25.6.0 arm64, machine `local`, Chromium 153 headless=new, 1440×900 at DPR 2, cold (root CLAUDE.md, "Measurement protocol"): every run a median of 10, the reference run only (the groups add rows to the header, drawn per frame like the names' row, and two drags that move a preview: the reference run separates them, as M16's did). On part C's final table code (reviewed). This part changed `perf/perf.ts` alone: `--groups 0` (the control), the header's rows checked at open, and the `reorder-group` drag. Load average 1.4–4.5 over the perf runs (the higher end at the session's start, after the size run's builds).

Raw: `2026-11-16-m17-d-size.json` (`just tall-table size`); frames, each `-reference.json`: `2026-11-16-m17-d-frames-base`, `-group-headers` (the host's default groups: two levels, so the header is three rows), `-group-headers-none` (the same build, `--groups 0`), `-reorder`, `-group-headers-reorder`, `-base-again` (the base at the session's end, for its spread across places). Run in that order, each build just before its run.

- **Building the feature costs nothing a frame shows.** With `--groups 0`, every segment falls within the base's two runs (4.22–4.38 narrow scroll, 4.49–4.61 narrow fling, 4.72–4.73 wide scroll, 4.39 wide fling, 4.56–4.66 sideways), and every range overlaps them. Between the session's first and last runs, the base itself moved by up to 0.16 ms (the narrow scroll 4.22 → 4.38).
- **Grouped, a frame costs what the same build ungrouped does, at fewer cells.** The two group rows take two body rows: 260 cells against 280 narrow, 286 against 308 wide, 312 against 336 sideways (−7%). Each segment reads −0.02 to −0.15 ms against `--groups 0`. Drawing ~20 fewer cells should save ~0.08 ms scrolling and ~0.16 ms in a fling (`density`'s ~3.8 and 7–9 µs a cell). So the group rows (3–6 cells drawn over the header, labels kept in view, the `Groups` probe each sideways frame) cost at most ~0.05–0.07 ms a frame, inside every segment's spread. Compared at the cells drawn: the same work a cell, plus a header that costs about what its cells would.
- **The drags: a group dragged costs what a column does.** The column drag held to its group reads 3.78 and 3.91 ms against `reorder`'s 3.73 and 3.97. The group drag reads 3.72 and 3.98, a 10-column preview over three header rows in the wide shape. All of them hold the display's rate with no late frame, as M15's column drag did (3.74 and 3.92). A frame of either moves the preview and the gap's line; finding the gap over the siblings shows nothing.
- Three runs read low (the base's sideways fling at 3.49, the grouped narrow drags at 3.50 and 3.39): runs whose traced frames are partly idle, so their p50 reads the idle time, as M15's note found. The medians are unaffected.

## Checks

- **D1:** `group-headers` adds +7.6 KiB after wasm-opt (+2.1 brotli) alone, and +10.9 (+4.8 brotli) with `reorder`. The scroll and flings with `?groups=` match the same build without groups at the cells drawn, and the build without groups falls within the base's spread at the session's two places. `reorder`'s drag with a group lifted runs at the column drag's cost, at the display's rate. The README's Features row.

## Reproducing it

```sh
just tall-table size --label m17-d-size
just tall-table build && just tall-table perf --profile reference --label m17-d-frames-base-reference
just tall-table build group-headers && just tall-table perf --profile reference --label m17-d-frames-group-headers-reference
just tall-table perf --profile reference --groups 0 --label m17-d-frames-group-headers-none-reference
just tall-table build reorder && just tall-table perf --profile reference --label m17-d-frames-reorder-reference
just tall-table build group-headers,reorder && just tall-table perf --profile reference --label m17-d-frames-group-headers-reorder-reference
just tall-table build && just tall-table perf --profile reference --label m17-d-frames-base-again-reference
```

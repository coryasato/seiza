# M22 part C: the header icon's cost and the close (2026-11-21)

Measured on Apple M1, macOS 26.6.2 (Darwin 25.6.0 arm64), machine `local`: the wasm's bytes (the bare host's builds, alone, over `sort`, and with every feature, and each app that builds the table), frame work with the host's icon on every header and with the feature built and none set (Chromium headless=new, 1440×900 at DPR 2, cold, median of 10, the wide shape, the reference run alone: an icon changes what the header draws, not how the table scrolls), and the smoke check in three browsers. On part B's table code with one fix made here (below); every number is on the fixed code.

Raw: frames, each `-reference.json`, run in this order, each build just before its run: `2026-11-21-m22-c-frames-base`, `-icons`, `-icons-off` (the `header-icon` build with `?icons=off`: the control), `-base-again`. In the gitignored `raw/`: the frame runs' console with the load before each (`2026-11-21-m22-c-frames.txt`), the smoke runs' (`2026-11-21-m22-c-smoke-header-icon.txt`, `2026-11-21-m22-c-smoke-combined.txt`), and `m22-c-icon-groups.ts` (the badge, the press's bounds, and the name's ink against the body's top, with and without group rows).

## What changed

- **A fix to the table:** under group rows (`group-headers`), `HeaderIconPressed`'s bounds were a pixel below the badge as painted. The names' row's layers hang from the header's bottom inside its 1 px border there, a pixel higher than under a lone header; the bounds were worked out from the body's top less a row. They and the tests' expected boxes now take the row's top from `icon_row_top`, and two window tests compare the worked-out box with where GPUI painted the element (`debug_bounds`), at rest and raised (`docs/DECISIONS.md`, "Features", 2026-11-21). Found by the smoke check below. In Chromium, from the body's top, px:

  | | Badge drawn | Press's bounds, before | After |
  |---|---|---|---|
  | Under two group rows | −24 to −8 | −23 to −7 | −24 to −8 |
  | No groups | −23 to −7 | −23 to −7 | −23 to −7 |

- **The scripts:** `perf.ts` gained `--icons off` (the host's `?icons=off`) and checks every shown column's badge on the layout at open, or none. The smoke check gained an icon run (C2, below). `perf/harness.ts` gained the icon's hooks and waits (`iconPressAfter`, `iconPressCount`, `iconThrough`) and `differingBox`, and `headerAt` and `moveGripAt` press clear of a column's icon, as `sort`'s check of a press beside its arrow now does: with the feature built, a press 8 or 12 px into a header is the icon's.

## The native runs, after the fix

`lint` passes; the icon's test builds pass: `header-icon` alone (68 tests), with `group-headers` (80), and every feature on (585, the random test's 48 cases and every control among them). `pairs` wasn't run again: the fix adds one site gated on two features (`header-icon`, `group-headers`), built and tested by the last two runs.

## Reproducing it

```sh
just tall-table wasm release                    # and with header-icon; sort; sort,header-icon;
                                                # every other feature; every feature: wc -c, brotli -q 11
# The apps: each crate at 85c0f0c and at part C's tree, one worktree, its own target,
# `cargo build -p <crate> --target wasm32-unknown-unknown --release`
# (the contender with `--features fonts`), wasm-bindgen, wasm-opt with the
# apps' flags, brotli -q 11.
just tall-table build && just tall-table perf --shape wide --profile reference --label m22-c-frames-base-reference
just tall-table build header-icon && just tall-table perf --shape wide --profile reference --label m22-c-frames-icons-reference
just tall-table perf --shape wide --profile reference --icons off --label m22-c-frames-icons-off-reference
just tall-table build && just tall-table perf --shape wide --profile reference --label m22-c-frames-base-again-reference
just tall-table build header-icon && just tall-table smoke
just tall-table build header-icon,sort,resize,reorder,select,clicks,group-headers,pin && just tall-table smoke
```

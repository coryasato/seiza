# M21 part C: the popover's cost and the close (2026-11-20)

Measured on Apple M1, macOS 26.6.2 (Darwin 25.6.0 arm64), machine `local`: the wasm's bytes (the bare host's builds, every feature with and without `popover`, and each app that builds the table), frame work with a popover open over a long text and with the feature built and unused (Chromium 153 headless=new, 1440×900 at DPR 2, cold, median of 10, the reference run alone: an open popover changes what a frame draws, not how the table scrolls), and the smoke check in three browsers. On part B's final table code (reviewed); part C changed no shipped code. The machine was quiet for the frame runs (load average 2–4, read before each).

Raw: the bytes alone from part B's size run on the final code (`2026-11-20-m21-b-size.json`, after the code review's fixes); frames, each `-reference.json`, run in this order, each build just before its run: `2026-11-20-m21-c-frames-base`, `-popover-none` (the `popover` build, none opened: the control), `-popover-wide` and `-popover-narrow` (`--popover 10000`: its two segments), `-base-again`. In the gitignored `raw/`: the frame runs' console (`2026-11-20-m21-c-frames.txt`) and the `popover,select,copy` smoke run's (`2026-11-20-m21-c-smoke-popover-select-copy.txt`).

## What changed

Part C changed no shipped code. `perf.ts` gained `--popover <chars>` (the host's `?popover-long=`) and its two segments, last in a run: the same 120 wheels at one point (40 px every 16 ms, 60 down then 60 up, as the text's 3,850 px in a 448 px box has room for), first with no popover open, so the table scrolls under them (`popover-none`), then with one open on row 1's long text, so its text scrolls and the table doesn't (`popover-open`); the run checks the popover stayed open on its cell and the table where it was. The smoke check gained a popover run (C2, below). `perf/harness.ts` gained the popover's hooks and waits (`popoverThrough`, `popoverWhere`, `popoverClosed`), and the host page's probe types its `popover` and `cue`.

## Frame work (C1)

Work p50, ms, from Chromium's trace, the ten runs' range in brackets, then presented frames a second. No late frames in any segment's median.

**Built, none opened** (the wide shape; 308 cells drawn in the scroll and fling, 336 in the sideways fling):

| Segment (wide) | Base | `popover`, none opened | Base, again |
|---|---|---|---|
| scroll | 4.67 [4.57–4.71], 56.9/s | 4.66 [4.26–4.79], 57.8/s | 4.63 [4.52–4.71], 57.1/s |
| fling | 4.79 [4.40–5.29], 59.7/s | 4.81 [4.59–5.21], 59.8/s | 4.80 [4.51–4.99], 59.7/s |
| sideways fling | 4.24 [4.10–4.42], 59.8/s | 4.23 [3.98–4.37], 59.8/s | 4.13 [3.96–4.26], 59.9/s |

- **Built and unused: the base.** Every segment within 0.03 ms of the base's two runs, inside their spread. The pointer rests over a cell throughout, so the hovered cell's cue is decided once; nothing else runs a frame until a popover opens.

**A popover open over 10,000 characters** (`--popover 10000`: the text at the cap, cut; 3,850 px of it in the 448 px box):

| Shape | The wheels, none open (the table scrolls) | The wheels over an open popover (its text scrolls) | Against none |
|---|---|---|---|
| Wide | 4.79 [4.71–4.92], 57.3/s | 5.13 [5.07–5.20], 57.2/s | +0.34 (7%), the ranges apart |
| Narrow | 4.48 [4.22–4.78], 57.0/s | 4.79 [4.67–4.93], 56.4/s | +0.31 (7%), the ranges overlapping |

- **An open popover at the cap costs about a third of a millisecond a frame, outside the spread in the wide shape.** Each frame draws the table as with none open, and lays out and draws the popover's text besides; both segments hold the display's rate with no late frames. Check C1's remedy (the cap lowered or the layout cached) was revised with the owner: the cost is accepted, the cap bounding it (`docs/DECISIONS.md`, "Features", 2026-11-20).
- **Against part B's spike:** it read 10.4 ms a frame at 10,000 characters, with `workRecorder` on a machine at load 6–23, and the table's frames under it unknown; this run's `workRecorder` reads 4.80 (wide) and 4.45 (narrow) on a quiet one, the table's frames beside it. The spike's slope set the cap; this is the cost at it.
- **The long text's column costs the table's cells, not the popover:** in the same runs, the protocol's scroll with a column of 10,000-character values on screen read 5.75 ms (wide) against the base's 4.67, and the fling's `workRecorder` p50 10.05 ms against 4.89 (52.6 frames a second against 59.7). The cells' text copies a cell's whole value (its line breaks replaced) and shapes it before cutting it to the cell, every drawn cell every frame. A base path, met here because the bare host had no long values before: a follow-up in `PLAN.md`.

## Reproducing it

```sh
# The apps: each crate at 8ffce13 and aa4f2b1, one worktree, its own target,
# `cargo build -p <crate> --target wasm32-unknown-unknown --release`
# (the contender with `--features fonts`), wasm-bindgen, wasm-opt with the
# apps' flags, brotli -q 11.
just tall-table wasm release custom-cells,live,follow,resize,select,copy,sort,pin,density,format,reorder,clicks,group-headers,hide,find   # and again with ,popover
just tall-table build && just tall-table perf --shape wide --profile reference --label m21-c-frames-base-reference
just tall-table build popover && just tall-table perf --shape wide --profile reference --label m21-c-frames-popover-none-reference
just tall-table perf --shape wide --profile reference --popover 10000 --label m21-c-frames-popover-wide-reference
just tall-table perf --shape narrow --profile reference --popover 10000 --label m21-c-frames-popover-narrow-reference
just tall-table build && just tall-table perf --shape wide --profile reference --label m21-c-frames-base-again-reference
just tall-table build popover && just tall-table smoke
just tall-table build popover,select,copy && just tall-table smoke
```

# M11 part B: the cells' text from one element, the same pixels (2026-11-04)

Checked on Apple M1, Darwin 25.6.0 arm64, machine `local`: the bare host's release build (`-Oz`), headless Chromium at DPR 2, Firefox and WebKit at DPR 1 (`shared-web/perf/`'s `open`), 1440×900. **No timing:** this part's check is pixels; the frame work and bytes are part C's, against M11's parent. No JSON per run; the screens are in `raw/smoke-screens/` (gitignored), and this note is their record.

## What changed

- The loaded cells' text is drawn by one element a region (`src/cells_text.rs`): every glyph painted inside one layer, where a `div` a cell was laid out, prepainted, and painted in a layer of its own. The header, the gutter, a loading row's bars, a failed row's message, and the tooltip are still elements.
- The smoke check's reference screens (`just tall-table smoke --screens save`, then `--screens <commit>`): each build's screens saved beside the commit they were drawn from, a later tree's compared with a named commit's pixel for pixel.

## Experiments and controls

- **The text a pixel lower** (the element's baseline offset plus 1 px, a build of the base): all 12 screens fail, 99,899 to 602,318 pixels each.
- **The snapping is only `to_taffy`'s.** Each cell's left, top, and width, the row, and the padding rounded to device pixels on their own (midpoints toward zero) is all of GPUI's snapping here: the region's origin is on a device pixel, so the post-layout absolute rounding never moves a cell's box. The fractional screens pass with nothing more.
- **The font is the inherited text style's,** as the `div`s' text read it, not `Glyphs` (the layout's reading): the same in every host that draws through `TallTable`. The native test that renders the state without `TallTable` drew at the inherited 16 px until its shell set `text_sm`, as `TallTable` does.

## Reproducing it

```sh
# at the reference commit, for each build
just tall-table build <features> && just tall-table smoke --screens save
# at the tree to check, for the same builds
just tall-table build <features> && just tall-table smoke --screens d96547f743
```

The build records the tree it was built from (`dist/build.json`'s `tree`, `perf/build-info.ts`), and `--screens` refuses a build from another tree, so a reference saved without rebuilding at its commit can't happen. Each scrolled screen is checked to land where the reference did, and the selected screen waits for the block the Shift+press makes.

The control: in `src/cells_text.rs`, `padding_top + line.ascent` plus `px(1.)` in `baseline_offset`, built with no features, then `--screens d96547f743`.

# M1: the bare host and the base's baseline (2026-10-23)

Measured on Apple M1, Darwin 25.6.0 arm64, machine `local`, Chromium headless=new, 1440×900 at DPR 2, cold, median of 10, reference and throttled (CPU 4×, Fast 4G) (root CLAUDE.md, "Measurement protocol"). The bare host's release build (`just tall-table build`), base only: no feature exists yet. Load average ~2.8 before and 1.8 after the frame runs; the runs' spread is in the JSON.

Raw: `2026-10-23-m1-frames.json` (`just tall-table perf`: every run, per shape, profile, and segment, and their medians), `2026-10-23-m1-size.json` (`just tall-table size`).

## What changed

- **The bare host** (`host/`): the table alone over rows answered from memory, on `seiza` without the panel, no engine. Two shapes, both 1,567,523 rows: narrow (the observatory's 11 columns' kinds) and wide (500 float columns, 120 px each).
- **The event bridge** (`bridge/`, `tall-table-bridge`): the filled mark, the scrollbar's targets, and the probes as JS values, moved out of Tycho (`table.rs`, `targets.rs`) and the GPUI contender (`contract.rs`); all three hosts use it. Its wasm effect on each app (release, wasm-opt with the apps' flags, brotli 11; the app's crate built alone before and after):

| Build | Before | After | Change |
|---|---|---|---|
| Tycho | 2,842.4 KiB | 2,843.0 KiB | +0.6 KiB (−0.1 KiB before brotli) |
| The GPUI contender | 2,698.0 KiB | 2,697.4 KiB | −0.6 KiB (+0.2 KiB before brotli) |

  Both are the noise of the bytes moving. Without `#[inline]` on `Publish::event` the contender grew 0.9 KiB brotli: the arms it never uses (the probe, layout, and cells globals) stayed. Recorded in each app's `perf/results/` too.
- **`shared-web/perf/trace.ts`**: `Trace`, `frameWork`, and `lateFrames`, moved from the observatory's metrics module (which re-exports them), so these scripts read per-frame work the same way.

## The base's frame work

Per-frame work is the trace's `ProxyMain::BeginMainFrame`; the recorder column is `workRecorder` (each rAF that drew), the cross-check. Late: rAF intervals over 1.5 refreshes. Cells: rows × columns on screen per frame (p50). Segments: **scroll**, 300 px every 16 ms for 2 s (≈600 rows/s, crossing a page); **fling**, top to the last row in ~3 s (`shared-web/perf/`'s `fling`); **hfling**, the first column to the last in ~3 s.

The trace and the recorder agree within ~1 ms at p50 everywhere (the recorder times the whole rAF callback, the trace the frame's main-thread update).

**Outside the frames:** in the wide fling, 831 ms (reference) of main-thread time ran outside any frame, against 191 ms narrow: the host's pages being made (500 columns × 1,024 rows per page) as reads resolve. That's the in-memory source's cost, standing in for an engine's decode; the table's own work is the frame columns above. A read the table cancels before it resolves makes no page.

## The wide shape at the base

It holds up at the reference run: no late frames in any segment, ~7 ms per frame, a sideways fling across all 500 columns as smooth as a vertical one. Wide costs ~1 ms per frame more than narrow while scrolling: it draws 308 cells to narrow's 280, and floats round (`fit_float`) where narrow's text columns are cut.

Two things the observatory's wide sheet hears before M2 (its `PLAN.md`, noted there):
- **The base draws ~310–340 cells a frame,** not the 1–2 k a frame the `custom-cells` decision assumed (`docs/DECISIONS.md`, "Features"): at 120 px columns and 30 px rows, 11–12 columns × 28 rows fill 1440×900. Denser stops need narrower columns and shorter rows, settings the base doesn't have (the row-height dial in `PLAN.md`, "Measuring a feature").
- **Throttled, a steady scroll misses frames in both shapes** (40% narrow, 61% wide): at 4× CPU a scrolled frame takes 22–28 ms. The base's own limit, not the 500 columns'; a fling, whose frames are mostly placeholders, stays on time.

## Experiments and controls

- Size: the control (the host built with Tycho) links `seiza-duckdb` and the panel; the host alone links neither, and its wasm holds neither's global.
- **Cancelled reads.** The first full pass had the host's `cancel` a no-op, so a read the table had cancelled still made its page. With it fixed (a cancelled read resolves `Cancelled`, with no page; a native test fails without it), the per-frame columns didn't move beyond run-to-run spread. Outside-frame time did only where cancels land before a read resolves: the wide throttled fling, 1,290 → 702 ms; at the reference run reads resolve on the next turn, before the table cancels them (wide fling 827 → 831 ms). The first pass's JSON wasn't kept: it measured the bug.
- `just tall-table smoke`: the release build loads, fills, scrolls down, and (wide) scrolls sideways in Chromium (WebGPU), Firefox (WebGL2), and WebKit (WebGPU), headless.

## Reproducing it

```sh
just tall-table build
just tall-table size --label m1-size
just tall-table perf --label m1-frames
just tall-table smoke
```

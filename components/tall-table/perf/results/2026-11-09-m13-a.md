# M13: `follow`'s `let_go` (part A, 2026-11-09)

Measured on Apple M1, Darwin 25.6.0 arm64, machine `local`. Sizes only: `let_go` runs only when a host calls it, so no frame work changes and no perf run was made (PLAN, M13 A5).

Raw: none written by a script. The bytes come from builds made by hand the way `just tall-table size` makes them (`cargo build -p tall-table-host --release` alone, wasm-bindgen, `wasm-opt -Oz` with the apps' flags, brotli 11), HEAD (`334d978`) in a git worktree with a target directory of its own, against the working tree. The smoke check's output is quoted below.

## What changed

- `TallTableState::let_go` (under `follow`): following off with the view where it is, `Following(false)` once per change. The bare host's `follow` build gains a script hook, `__tallTableLetGo()` (with `?perf`), so the build uses the call.
- The paging fixture gains a `let_go` step, a scenario, and a control (`let-go-to-end`); the observatory's TanStack contender ports the call (`follow.ts`'s `letGo`) and runs them.
- No app builds the table with `follow` yet (Tycho doesn't; the observatory's tail level adopts the call in its part E2), so no app's wasm changes.

## Bytes

|---|---|---|---|---|---|---|
| Base | 10,077,146 B | 10,077,146 B | 0 | 2,815,322 B | 2,815,369 B | +47 B |
| `follow` | 10,101,529 B (9,864.8 KiB) | 10,104,574 B (9,867.7 KiB) | **+3,045 B (+3.0 KiB)** | 2,822,967 B (2,756.8 KiB) | 2,825,016 B (2,758.8 KiB) | **+2,049 B (+2.0 KiB)** |

- **The base:** the same length; one byte differs, a panic location's line number in the bare host's `host.rs` (993 → 1012: the 19 lines added above it for the hook's constant and `cfg`s). Same code. Brotli moves 47 bytes with it.
- **`follow`, the call against the hook** (after the code review): the same build with the hook kept but its call to `let_go` dropped reads 10,104,254 B after wasm-opt and 2,824,347 B brotli. So **the call is +320 B after wasm-opt (+669 B brotli)** and the hook +2,725 B (+1,380 B brotli): a `Closure`, the global it's set on, and the entry into GPUI through the foreground executor, machinery the `follow` build didn't have before (it had no hook of its own). Brotli swings by up to ~2 KiB when a few bytes shift (`size.ts`), so the call's brotli reads as under 1 KiB, not a measured 669 B. A host that calls `let_go` from a button pays for the call alone. **Every later reading of the bare host's `follow` build carries the hook** (its bytes, and nothing a frame: it runs only when a script calls it).
- The working-tree `follow` build reads the same as `just tall-table build follow`'s (9,867.7 KiB after wasm-opt, 2,758.8 brotli), built from a clean target.

## The TanStack contender

Each level's build (`base`, `wide`, `market`, `tail`) with and without the port, every file but the DuckDB bundles hashed: **byte-identical** at all four (`letGo` isn't called until the observatory's part E2, so the bundler drops it).

## Checks

- **Native:** `follow`'s window tests (two new: the host lets go with the view held, a closed table lets go of the flag); `paging_scenarios` and `paging_controls_fail` with the new scenario and `let-go-to-end` failing it; the random test with `let_go` placed; `just tall-table test`; `just tall-table soak` (seeds 1–4, 500 cases each, every feature on: pass, ~47 s a seed).
- **TanStack:** `npm test` in the contender (78 tests: 75 pass, 3 skipped), the control among following's, failing.
- **Smoke** (`just tall-table build follow`, `just tall-table smoke --browsers`), the tail run:
  - chromium: followed to 1067, held at 1227.7 while 732 rows arrived, followed again to 2064, **let go at 2171.7 while 498 rows arrived**, followed again to 3009
  - firefox: followed to 1024, held at 1196.7 while 739 rows arrived, followed again to 2054, **let go at 2186.7 while 518 rows arrived**, followed again to 3029
  - webkit: followed to 1065, held at 1222.7 while 723 rows arrived, followed again to 2272, **let go at 2351.7 while 541 rows arrived**, followed again to 3215
- **Smoke again after the code review** (the let-go step resting by polling, as the wheel's does): chromium let go at 2169.7 while 708 rows arrived, followed again to 2998; firefox at 2160.7 while 726, to 3011; webkit at 2318.7 while 720, to 3178. `just tall-table lint` and `test` (60 test binaries) pass.

## Experiments and controls

- `let-go-to-end` (a `let_go` that moves the view to the end first, as `follow` does) fails the new scenario at its `let_go` step (bottom 1600, not 1500), natively and in TS.
- A first size comparison shared one cargo target directory between the HEAD worktree and the working tree, and read both `follow` builds as identical. The HEAD worktree's freshly checked-out files were newer than this tree's edits, so cargo took the HEAD build of `seiza-tall-table` as fresh for both. Redone with a target directory per tree (the numbers above).

## Reproducing it

```sh
just tall-table build follow && just tall-table smoke --browsers
just tall-table soak
# the bytes: a worktree at the parent with its own CARGO_TARGET_DIR, each build as `just tall-table size` builds it
```

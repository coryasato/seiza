# M8 part B: the sort (2026-10-29)

Measured on Apple M1 (8 cores), Darwin 25.6.0 arm64, machine `local`: native `cargo test` runs and the bare host's release builds, not the browser protocol. One run each; the sizes are `just tall-table size --against 6b6cb1b --label m8-b-size` ([`2026-10-29-m8-b-size.json`](2026-10-29-m8-b-size.json)), on the build after the code review's fixes. Part B builds the feature; its frame work and latencies are parts C and D's.

## What changed

- **The feature** (`sort`, off by default): `src/sort.rs` (`Sort`, `SortDirection`, `SortRefused`, `SortIcons`, the cycle), `TallTableDelegate::sort` (refusing every sort by default), `TallTableColumn::sortable`, `src/state/sort.rs` (the arrows, their target, `set_sort`, `set_sort_icons`, what a sort does), `PageCache::forget_all`, and `TallTableEvent::Sorted` and `SortRefused`. The spec is `PLAN.md`'s M8.
- **The fixtures:** `paging.json`'s "a sort reads the new order from the top" and its `keep-pages` control; `sort.json` (the cycle by kind, the order with NULLs and ties) and its three controls.
- **The random test:** a `Sort` step (weight 4), cases drawing sortable and refused columns, an accepted sort bumping every row's era; the controls `a_sort_keeps_the_pages` and `a_sort_keeps_the_reads`.
- **The bare host's `sort`:** every column sortable, its source sorting from memory (`rows::column_order`, `rows::order`), gpui-kit's three sort icons bundled, `?sort-icons`.
- **From the code review:** the sortable header's padding set after `px_2` (it was overwritten: a long name ran under the arrow); `set_sort` refused on a closed table, and `set_columns` clearing a stale sort whatever the source answers; the arrow pressed and hovered forgotten with their arrow; the host's `live` bump through the order; the host keeping only the last sorted column's orders (every one's would pass 4 GiB across the wide shape); two allocations dropped.

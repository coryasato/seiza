# Dependency upgrade: gpui-kit 0.9.1 → 0.10.0 (2026-11-16)

Measured on Apple M1, Darwin 25.6.0, machine `local`. The lock and the decision: `docs/DECISIONS.md`, "Toolchain and build", 2026-11-16.

## What changed

- No code changes. gpui-pre stays at 0.3.12, so the GPUI and gpui-pre-web code the table calls is the same; the bump moves gpui-component, gpui-base, and gpui-kit-assets to 0.10.0, and gpui-fast (an optional backend, off) to 0.1.16. No change to the paging, so no soak.
- The bare host's base build: **2753.2 → 2761.0 KiB brotli (+7.8 KiB, +0.3%)**, 9809.1 → 9836.3 KiB after wasm-opt (+27.2), against a 0.9.1 build of HEAD (`0a84356`) in a worktree. None of it is the table's: its code is unchanged. `size`'s "the base changed" gate fails, as it's meant to on a bump.
- Each feature's own cost against the base, in `2026-11-16-gpui-kit-0.10.0-size.json`: every one within ~2 KiB brotli of its 0.9.1 cost (`copy` 17.5 → 15.3, `live` 4.5 → 2.9, the rest within 0.8), which is brotli's spread when a few bytes move.
- Not measured: the GPUI contender (its `dist/` wasn't rebuilt; the observatory's sizes in its own session), and Tycho (changing soon).

## gpui-kit 0.10.0's DataTable, against the table's features

Read from gpui-component 0.10.0's `src/table/` against 0.9.1's. Each one is a row in the README, "How it differs from `DataTable`".

- **`TableRow::hover` (#3912):** styles the row under the pointer. The table finds the cell under the pointer only for its tooltip and draws nothing for it. Not built.
- **`TableRow::id` (#3907):** a stable identity for a row's element state when rows reorder. The table's rows are indices and hold no element state; what it keeps by index is cleared when an index changes meaning (`sort`). Nothing to carry over.
- **`DataTable::scrollbar_mode` (#3945):** always, on hover, or while scrolling. The table's scrollbars are always drawn, in their own space. Not built.
- **No per-frame redraw of a striped table that doesn't fill its area, no per-row cross-axis measure (#3978, #3868):** `DataTable`'s own layout; the table paints its rows itself. Nothing to carry over.

## Checks

- `just tall-table test`: 1,650 tests. PASS.
- `just tall-table lint`: PASS.
- `just tall-table size --against HEAD --label gpui-kit-0.10.0-size`: no engine or panel linked, no feature's symbols in the base (and the controls), no home path in any build (the control without `trim-paths`: 995). PASS, but for the base-changed gate above.
- `just tall-table smoke` (the base build): both shapes load, fill, and scroll in Chromium (WebGPU), Firefox (WebGL2), and WebKit (WebGPU). PASS.
- Not run: `perf` (no GPUI code the table calls changed), the feature builds' smoke.

## Reproducing it

```sh
just tall-table test && just tall-table lint
just tall-table size --against 0a84356 --label gpui-kit-0.10.0-size
just tall-table build && just tall-table smoke
```

# M8 part A: how a source answers a sorted page, a spike (2026-10-29)

Measured on Apple M1, Darwin 25.6.0 arm64, machine `local`, Node 26.12.1, native DuckDB 1.4.5 (`@duckdb/node-api` 1.4.5-r.1, Tycho's data tooling), one thread, the files on a local disk (warm in the OS cache after the first query). One run per query: these are orders of magnitude for the research (root [`docs/research/tall-table-features.md`](../../../../docs/research/tall-table-features.md), "`sort`"), not a source's measured cost, which the engine measures in the app that adopts `sort`. DuckDB-Wasm runs slower than native, and over HTTP every byte a query reads is a range request (the engine's `CLAUDE.md`, "DuckDB-Wasm 1.32.0 gotchas").

The spike's scripts weren't kept (part A builds no shipped code); "Reproducing it" below says what they did.

## The files

| File | Rows | Row groups | Size | Sorted by (its column's compressed bytes) |
|---|---|---|---|---|
| The observatory's `asteroids.parquet` (11 columns) | 1,567,523 | 52 | 22.8 MB | `H` (2.1 MB), `full_name` (8.5 MB) |
| Tycho's `gaia-dr3-bright.parquet` (11 columns) | 25,067,889 | 409 | 1.57 GB | `parallax` (190 MB) |

## What was measured

Each way a source could answer page *k* (1,024 rows) of a sorted order, every order ending in the row number so ties keep the file's order and pages join up:

- **OFFSET:** each page `SELECT * … ORDER BY "<col>", file_row_number LIMIT 1024 OFFSET k`. No preparation.
- **Index:** once, `CREATE TABLE ix AS SELECT file_row_number AS r FROM read_parquet(…, file_row_number = true) ORDER BY "<col>", file_row_number`; then each page the index's rows `k … k + 1024` (by `rowid`) joined to the file on `file_row_number`, ordered by position.
- **Sorted copy:** once, `CREATE TABLE s.sorted AS SELECT * … ORDER BY "<col>", file_row_number` in `ATTACH ':memory:' AS s (COMPRESS)` (as Tycho's CSV tables are); then each page by `rowid`.
- **In memory:** the file first copied into a compressed in-memory table (Tycho's CSV case: its rows already in DuckDB), then the index (by `rowid`) and OFFSET over that table.
- **The base:** today's page, `WHERE file_row_number >= k AND file_row_number < k + 1024`, for scale.

Pages at the top, the middle (50%), and 90% of the rows. Memory is `duckdb_memory()`'s total after the build.

## Results

**The asteroids** (ms; by `H` / by `full_name`):

| | Build | Top page | 50% | 90% | DuckDB memory |
|---|---|---|---|---|---|
| OFFSET | — | 119 / 48 | 660 / 558 | 1,037 / 710 | — |
| Index, joined to the file | 129 / 209 | 102 / 41 | 17 / 17 | 87 / 50 | ~20 MiB |
| Sorted copy | 1,062 / 1,112 | 2 / 1 | 1 / 1 | 1 / 1 | 33.1 / 35.8 MiB |
| In memory: index | 145 / 173 | 43 / 17 | 7 / 7 | 38 / 23 | (the table's) |
| In memory: OFFSET | — | 43 / 20 | 618 / 494 | 909 / 608 | (the table's) |
| The base (unsorted) | — | 3 | 3 | 3 | — |

**Gaia** (by `parallax`): OFFSET's top page 2,594 ms ascending, 2,416 descending; the index's build 1,904 ms (25 M row numbers), and each page joined to the file 2,325–2,423 ms. The sorted copy wasn't run: at the asteroids' ratio (a 22.8 MB file held as 33–36 MiB, ~1.5×) it would hold about 2.4 GB, past Tycho's 1.5 GiB DuckDB budget (`MEMORY_BUDGET` in `apps/tycho/crate/src/csv.rs`).

## What it says

- **OFFSET grows with the depth:** every page sorts the column again; ~1 s natively at 90% of 1.57 M rows, 2.5 s for Gaia's top page alone. Good for the first page after a click (a top-N), not for paging.
- **An index is cheap to build and cheap to page over rows in memory** (7–43 ms a page), the CSV case. Over a Parquet file its pages scatter through every row group, so the join reads every group's columns: tolerable from a warm local disk (17–102 ms), but over HTTP each page would read about the whole file (22.8 MB; 1.57 GB for Gaia) unless DuckDB's file cache holds it. Not checked in DuckDB-Wasm.
- **A sorted copy pages as fast as the base,** after reading the whole file once and holding it compressed (~35 MiB for the asteroids). Not possible for Gaia within the memory budget.
- So a source's sort costs from a tenth of a second to impossible, and a source must be able to refuse one: the table's `sort` call returns a refusal, and a source that needs a preparation starts it there and holds its first reads (root research, "The delegate's calls").

## Reproducing it

A Node script on Tycho's data tooling (`createRequire` from `apps/tycho/data/package.json`, `DuckDBInstance.create(':memory:', { threads: '1' })`), each query timed with `performance.now()` around `runAndReadAll`, run over the files above with the queries listed under "What was measured". File facts from `parquet_file_metadata` and `parquet_metadata` (`sum(total_compressed_size)` by column).

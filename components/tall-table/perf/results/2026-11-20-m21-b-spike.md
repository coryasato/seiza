# M21 part B: the popover's selectable text, and its cap (2026-11-20)

Measured on Apple M1, macOS 26.6.2, machine `local`, the bare host's release build (`just tall-table build popover,copy` for the spike, `popover` for the bytes and the frames), Playwright's Chromium, Firefox, and WebKit headless, 1440×900 (Chromium at DPR 2, the others at DPR 1: `shared-web/perf/`'s `open`). Load average 6 to 23 through the session (other work on the machine): the frame numbers are this part's evidence for a cap, not the feature's measured cost, which part C measures under the protocol.

The scripts were one-offs and weren't kept: part C's smoke check selects and copies a part of the popover's text in three browsers, and its frame segment measures an open popover. "Reproducing it" says what they did.

## The spike: `SelectableText` in the popover

**It holds in all three browsers.** The popover opened through the host's hook on a row of the long-text column (`?popover-long=3000`); a drag from 14 px into its first line to 240 px along it, then Cmd+C, then a real paste (`perf/harness.ts`'s `paste`):

| Browser | The popover open after the drag | Pasted |
|---|---|---|
| Chromium | yes | `wrejm lhtabvoer govzad wlnau xgw` (32 characters, part of the value) |
| Firefox | yes | the same |
| WebKit | yes | the same |

The same again with a `Cells` selection of 4 × 2 cells made first (through `__tallTableSelect`), which `copy`'s key would write as TSV: the same part of the popover's text pasted in all three, so the popover's copy goes before `copy`'s.

Natively, the window test `a_part_of_its_text_is_selected_and_copied` (`src/state/fixtures/popover.rs`) drives the same in GPUI's test app, with and without `copy` built.

**Found on the way:** gpui-kit's `Root` binds its copy to Cmd+C only under `cfg(target_os = "macos")`, so a wasm build has Ctrl+C alone, and in a Mac browser Cmd+C would have copied nothing once `copy`'s key stepped aside. The popover binds its own copy (Cmd+C and Ctrl+C, the table's context, bound last), which writes the window's text selection while the popover is open and goes on otherwise.

**Its bytes:** the bare host's wasm, brotli 11:

| Build | Brotli | Raw |
|---|---|---|
| base | 2,764.5 KiB | 9,848.3 KiB |
| `popover`, the text plain (`StyledText`, with its highlights) | 2,772.2 KiB | 9,880.3 KiB |
| `popover`, the text `SelectableText` | 2,776.8 KiB | 9,893.9 KiB |

`SelectableText` adds 4.6 KiB brotli over plain text (13.6 KiB raw). The feature's own size, alone and with every feature, is part C's.

## The cap: frames with a long text open

The popover open on the long-text column at each length, then a wheel inside it every 16 ms for 120 wheels (60 down, 60 up, 40 px each), so every frame lays out and draws its text; frame work from `shared-web/perf/`'s `workRecorder`, Chromium, median of 5 runs (each run's median frame):

| Characters | Frame work | Its p95 | The opening frame |
|---|---|---|---|
| 100 | 6.30 ms | 7.79 ms | 17.6 ms |
| 1,000 | 7.13 ms | 8.77 ms | 22.4 ms |
| 10,000 | 10.41 ms | 11.74 ms | 43.5 ms |
| 20,000 | 11.19 ms | 13.52 ms | 57.6 ms |
| 100,000 | 18.12 ms | 19.62 ms | 132.2 ms |

At the research's starting cap, 100,000, every frame with the popover open passed a 60 Hz frame's 16.7 ms, and opening it took 132 ms. **The cap is 10,000 characters:** about 4 ms a frame over a short text, and 43.5 ms to open; a value past it ends in "…", and the host's view of the row shows the rest. Caching the text's layout across frames (the other remedy the spec names) waits for a host that needs more.

## Reproducing it

```sh
just tall-table build popover,copy
# the spike: per browser, open ?shape=narrow&popover-long=3000&perf, wait for
# `tall-table:filled`, call __tallTablePopoverOpen(first + 2, 2), wait for the
# probe's `popover`, drag in its first line, press ControlOrMeta+C, paste.
just tall-table build popover
# the cap: per length, open ?shape=narrow&popover-long=<n>&pin=0&perf in
# Chromium with `workRecorder`, open the popover on row first + 1 of column 2,
# wheel inside it 120 times every 16 ms, read `__seizaWork`.
```

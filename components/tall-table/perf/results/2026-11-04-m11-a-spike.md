# M11 part A: where a flash frame's time goes, and the cells' text from one element (2026-11-04)

Measured on Apple M1, Darwin 25.6.0 arm64, machine `local`, Chromium headless=new, 1440×900 at DPR 2, cold (a fresh browser per run), **median of 3**: a spike, not a protocol run. The builds are the bare host's release build with its names kept (`strip` off, `wasm-opt -O2 -g` in place of `-Oz`), so a CPU profile names its functions; every variant was built that way, so they compare with each other, not with the protocol's `-Oz` numbers. The spike's code is [`2026-11-04-m11-a-spike.patch`](2026-11-04-m11-a-spike.patch) (against M11's parent; reverted after), a build-time switch, `SPIKE_TEXT`, in `render_body`'s non-`pin` path. **No JSON per run:** the runs were the scripts' without `--label`, on builds that keep names, so they're no baseline for the protocol's numbers (part C measures its own, against M11's parent); this note is their record, and the patch with "Reproducing it" regenerates them.

## Where the time goes

A CPU profile (CDP `Profiler`, 200 µs sampling, 4 s) of the bare host built `live,custom-cells`, narrow shape, `?live=1000&flash` (every float flashing for 1 s), throttled (CPU 4×): the main thread busy 1,004 ms a second. Inclusive, a second:

| | ms/s |
|---|---|
| `Window::draw` | 783 |
| the views' render (the table's `render_body` among them) | 63 |
| request layout (the element tree, text measured) | 133 |
| taffy's layout | 181 |
| prepaint (text shaped: 76) | 218 |
| paint | 378 |
| of which `TextLayout::paint_lines` (the cells' text) | 296 |
| of which `BoundsTree::insert` (the scene's draw order) | 235, 192 of it from `Scene::push_layer` |
| `Window::present` | 49 |

Every shaped line paints inside a layer of its own (gpui-pre 0.3.11, `text_system/line.rs`'s `paint_line`: `window.paint_layer(line_bounds, …)`), and each layer is inserted into the scene's `BoundsTree`, whose search for the highest order under the new bounds walks the tree when the bounds don't meet the last leaf, as a cell's next to the last one doesn't: ~300 cells a frame at ~50 frames a second, ~13 µs an insert throttled. A primitive painted inside a layer takes the layer's order and is never inserted (`Scene::insert_primitive`). A cached view's replay inserts every primitive and layer again (`Scene::replay`), so caching rows would keep the inserts.

## The cells' text, four ways

The same page and feed, throttled, `live.ts --flash --profile throttled --runs 3` (1,000 updates/s; work per frame from the trace; late frames from rAF intervals):

| The cells' text | Work p50 (p95) | Late | Busy | Refreshed frames a second |
|---|---|---|---|---|
| Today's: a `div` per cell, its text a child | 20.19 (24.41) ms | 30.57% | 994 ms/s | 11.96 |
| None (the floor: every cell's text left out) | 5.80 (7.45) | 0% | 419 | 33.59 |
| One canvas a region, each cell's `ShapedLine::paint` (a layer per line) | 12.06 (15.42) | 0% | 821 | 21.98 |
| **One canvas a region, every glyph painted in one layer** (`paint_glyph` inside one `paint_layer`) | **10.96 (14.77)** | **0%** | 745 | 27.31 |

The busy time stays high in the last two because the host's feed shares the main thread and starves less when frames are cheaper: it lands 22–27 batches a second where today's lands 12.

**Beyond the flash** (today's against one layer of glyphs, same builds):

| Run | Today's | One layer of glyphs |
|---|---|---|
| The feed with no flash, throttled (`live.ts`, 3 runs) | work p95 23.55 ms, busy 677 ms/s, 0% late, 29.2 refreshed/s | p95 12.75, busy 401, 0% late, 37.6 refreshed/s |
| The flash, reference (`live.ts --flash`, 3 runs) | work p50 6.61 (p95 7.09) ms, busy 412 ms/s | 4.54 (5.34), busy 305 |
| The base, wide shape, reference (`perf.ts --shape wide`, 3 runs): vertical scroll | work p50 8.02 (p95 9.50) ms, 58.5 presented/s | 4.82 (5.64), 59.4/s |
| … vertical fling | 4.97 (8.89), 44% placeholder frames | 5.25 (6.01), 45% |
| … sideways fling | 7.96 (9.30) | 4.38 (5.94) |

(The no-flash feed's work p50, ~1 ms, reads its idle frames: it draws only when a batch lands, so its p95 is the frame's cost.)

**The screens:** the glyph variant's first narrow screen beside today's, by eye: the same text in the same places (`raw/m11-spike/`, not committed), at `scroll_x` 0. By eye can't show a device pixel's shift, and the spike placed the text at raw coordinates where GPUI's layout snaps a `div`'s edges, so a fractional scroll would move it; its cut is only the clip: no "…" (`truncate_line`), and its padding a fixed 8 px. The build's work is more than the spike's.

## What it says

- **The flash's frame is the cells' text.** Without it the same flashing frame is 5.8 ms throttled; with today's text, 20.2. The flash's quads cost what the fills cost.
- **One element a region, glyphs in one layer, halves the frame** and keeps up on the slow device with every float flashing, and frames that draw text get cheaper (the wide scroll −40%, the sideways fling −45% at the reference run; the vertical fling unmoved, its frames ~45% placeholder rows). Leaving out the divs (their layout and prepaint) is most of it (20.2 → 12.1 ms); one layer instead of one a line is the rest (→ 11.0).
- **Fewer frames or cached rows wouldn't do it:** a feed that lands a batch most frames (the observatory's market watch, from a worker) redraws its rows anyway, and a cached row's replay still inserts its lines' layers.

## Reproducing it

```sh
git apply components/tall-table/perf/results/2026-11-04-m11-a-spike.patch
# per variant: unset (today's), none, lines, glyphs
CARGO_PROFILE_RELEASE_STRIP=none SPIKE_TEXT=glyphs cargo build -p tall-table-host --target wasm32-unknown-unknown --release --features live,custom-cells
wasm-bindgen target/wasm32-unknown-unknown/release/tall_table_host.wasm --out-dir components/tall-table/host/web/pkg --target web
wasm-opt -O2 -g --enable-bulk-memory --enable-nontrapping-float-to-int --enable-sign-ext --enable-mutable-globals --enable-reference-types --enable-multivalue --enable-threads components/tall-table/host/web/pkg/tall_table_host_bg.wasm -o components/tall-table/host/web/pkg/tall_table_host_bg.wasm
npm run build --workspace @seiza/tall-table-host && printf '{"features":"live,custom-cells"}\n' > components/tall-table/host/web/dist/build.json
node components/tall-table/perf/live.ts --flash --profile throttled --runs 3
```

The base's wide runs build with no features (`--features ""`, `build.json` `""`) and run `perf.ts --shape wide --profile reference --runs 3`. The profile was a throwaway script (CDP `Profiler.start`/`stop` over 4 s after the filled mark and a second's warm-up, self and inclusive time by function name).
